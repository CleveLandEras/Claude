## 0. 目标与本期范围

- **最终目标（需求原文）**：「活動靈活配置使用，通過配置滿足各情況下『營運需求』，如：週五要不要做一個儲值活動／節慶活動」。
- **业绩目的**：运营能随时、按人群上储值活动 → 储值人数与储值额上升（付费率 × 客单价）；同时把重复开发从研发排期里拿掉。
- **现状基线**（盘点）：近 12 个月储值、商城类活动开发需求 148 个，其中 52 个是动用研发的重复开发（按轮次/按包重开 34 个，同一变更按活动拆单 18 个；按标题归为重复的共 63 个，另 11 个只涉及美术、策划或没有子任务），约每月 4 个。
- **后台现状**（10/28 后台实看）：一个活动要出现在各处，现在要在 3 个一级菜单（活動管理、公告管理、訊息管理）、约 8 个配置页各配一次，每页都有自己的「連結位置」字段（8 页清单见实看文件第四节）；「活動管理」下有 21 个子菜单，一个玩法一个页签。
- **本期**：12/11 开始开发、1/21 开发结束（Dk 推测，未确认）。需求评审与研发评审在 12/11 前完成。
- **一句话方案**：活动 = 工具（玩法模板）＋ 参数 ＋ 素材 ＋ 投放。运营在后台选工具、填参数、选版式、选对象和入口即可上线；玩法逻辑只开发一次。三个入口按「玩家怎么参与」重新分工：要付费参与的进商城，免费参与的进限时活动，纯信息进公告。

### 1.2 归属规则（系统自动判断，运营不手选主入口）

一个活动只有一个**主入口**，由系统按活动配置判断：

1. 必须先储值或购买才能参与（工具为礼包、累充、满减、折扣、团购、一元夺宝；或抽奖券只能靠储值、购买获得）→ **银行（商城）**。礼包、折扣显示在银行现有页签的商品上，其余进「储值活动」页签。判断时注意三点：
   - 只把「本期储值过」作为参与资格的押注、登入、任务等活动，不算，按规则 2、3 判断。
   - 活动内可选的付费道具（如可选购买的加速包）不算，活动本身按核心玩法判断。
   - 「买一次、之后每天领」（如回馈卡、7 日礼）按购买处理，归银行（见 T1「分日领取」）。
2. 否则，活动配置了「指定游戏」（只在某些游戏内参与，如排行榜、外赠掉落、游戏挑战、新游戏活动、红包雨分游戏类别、BOSS 战）→ **限时活动 · 游戏活动**。
3. 其余（签到、庆典主活动、人数活动、回归、全平台抽奖等）→ **限时活动 · 平台活动**。

- **曝光位**（可多选，只做引流，点击都跳主入口；勾选后自动生成为尽量档，首批只把活动列进各模块的跳转目标，由各模块自行配置）：大厅 Banner、大厅自动弹窗、推播（发到玩家手机通知栏的消息，玩家不在游戏里也能收到，点开直接进入活动）、公告「活动」分类、游戏内悬浮按钮。勾选后：
  - 公告「活动」分类：系统自动生成一条，标题取自活动名称、正文取自活动说明，大图取自活动配置里的主视觉图（推断，待确认），随活动上架、结束自动下架。
  - 大厅 Banner、游戏内悬浮：系统自动生成一条，需上传对应尺寸的图（沿用现有大厅 Banner、游戏内悬浮的图片规格），随活动上下架。
  - 大厅自动弹窗、推播：在推送统一后台生成一条草稿，跳转目标已填为该活动；投放规则由运营在推送统一后台补齐后发布。
- 活动配好后**自动出现在所有入口与曝光位的可选列表里**，不再需要研发把新活动加进「链接位置」下拉。
- 现有各玩法自有后台（扭蛋机、每日补给、红包夺宝、抽奖大厅、BOSS 战、红包雨等）本期不改规则配置，只接入「展示设置」（主入口判断、页签标签、排序、曝光位），使它们与新工具活动出现在同一套入口里。接入名单由 RD 逐项列出接入，不做迁移功能。

## 2. 活动的组成：工具 ＋ 参数 ＋ 素材 ＋ 投放

后台新菜单：**活动管理 → 活动配置**：在后台「活動管理」下新增二级菜单「活動配置」，和现有 21 个子菜单并列；现有子菜单照常用、不迁移（10/28 后台实看）。一个活动的新建流程：选工具 → 基本信息 → 工具规则 → 对象与时间 → 预算与上限 → 展示与素材 → 预览 → 提交审核 → 排程上架。

### 2.1 通用设置（所有工具共用）

| 分组 | 字段 | 规则 |
|---|---|---|
| 基本信息 | 活动名称 | 必填；繁中、英文、越南文（与现有多语言一致） |
| | 活动说明 | 系统按工具规则自动生成规则摘要（时间、档位、奖励、限购），运营可在下方补充说明；多语言 |
| | 活动编号 | 系统生成 |
| | 点数异动科目 | 系统按「工具名-活动编号」自动生成，不再每个活动开发科目代码 |
| 时间 | 开始、结束时间 | 必填；按 UTC 存，界面按所在时区显示 |
| | 循环 | 不循环／每日固定时段／每周固定几天固定时段（如每周五 18:00–24:00）；循环活动每个时段为一期，期内进度独立。尽量档；首批不循环，同类活动靠复制再上 |
| | 领奖截止 | 活动结束后 N 天内可领未领奖励，默认 3 天；过期未领不补发 |

| | 排除对象 | 黑名单、VIP 名单、指定名单、等级区间；排除优先于可参与 |
| | 活动分组 | 同组只派发一次（沿用现有规则） |
| | 平台 | H5／iOS／GP／APK／WEB 多选 |
| | 参与游戏 | 全部游戏（默认）／指定游戏（多选，可按游戏类别选：转轮、柏青、鱼机、棋牌、视讯）；选了指定游戏，主入口按 1.2 规则 2 判断 |

| | 每人上限 | 每人在本活动可得奖励折算上限 |
| | 到上限的最后一笔 | 使累计发奖成本达到或超过上限的那一笔照常发放，发完后活动结束，超出部分计入成本；结束后领奖截止内仍可领已达成未领的奖励，同样计入成本 |
| | 退款、拒付 | 沿用现有储值退款、拒付的处理，本方案不另定 |
| | 预估成本 | 系统按档位、对象人数、历史参与率估算，提交审核时显示。尽量档 |
| | 与现有成本预警的关系 | 活动总成本上限管单个活动，到上限自动结束，用来止损；后台现有「系統設定 → 獎勵成本預警設定」是全局的单项预警、总成本预警和弹窗门槛，只预警，不会自动停。两者并存。用工具配置的活动，发奖成本要不要计入现有预警的统计，请研发确认（见第 7 节）。依据：10/28 后台实看 |
| 展示 | 主入口 | 系统按 1.2 归属规则显示，不可手选 |
| | 页签标签 | 一套统一标签：储值、押注、登入、分享、回归、其他（取代好康、限时活动、热门资讯三套），只用于后台排序、筛选与统计，不在客户端显示；另可勾「新」「热」角标，显示在客户端列表 |
| | 排序权重 | 整数，大的在前；相同按开始时间晚的在前 |
| | 曝光位 | 多选：大厅 Banner、大厅自动弹窗、推播、公告活动分类、游戏内悬浮 |
| 素材 | 版式 | 每个工具提供固定版式（抽奖按形式分转盘、刮卡、开箱三套，其余工具各 1–2 套，见第 3 节）；时间、档位、奖励、进度、按钮由系统按配置渲染，不画在图里 |
| | 主视觉图 | 上传 1 张主图（支持 spine）；可选主题色 |
| | 复制 | 任一活动可「复制为新活动」，带出全部设置，改时间与素材即可再上 |
| 状态 | 草稿 → 待审核（可退回草稿） → 已排程 → 进行中 → 已结束；已排程、进行中可「下架」 | 进行中可改：素材、说明补充、延长结束时间、提前结束、上调成本上限；不可改：工具规则、对象、奖励、开始时间（防客诉）；修改要审核，提前结束与下架不需审核、立即生效（用于止损） |
| 审核 | 上架前由另一位有审核权限的人通过 | 审核页显示规则摘要；预估成本在尽量档加入 |
| 预览 | 后台预览 | 按所选版式渲染玩家端页面，竖版、横版各一，可切换语言；提交审核前至少预览一次 |
| 测试 | 测试账号预览 | 上架前可指定测试账号在正式服看到并参与，不计入数据。尽量档 |

### 2.2 数据

- 每个活动一张数据页：曝光人数、打开人数、参与人数、储值人数、储值金额、发奖成本（折算老币）、储值额/成本；按日趋势；可导出参与名单与领奖记录。
- 活动列表显示每个进行中活动的储值金额与成本进度（成本 / 上限）。
- 储值归因：一笔储值或购买用到了哪个活动的礼包或加赠（折扣、满减），就记为该活动的储值；活动期内在活动页内发起的储值也记为该活动；累充、团购按活动统计口径计。一笔命中多个活动时各自都计，数据页注明各活动的储值金额不能相加。
- 储值额/成本是台币除以老币，两者不换算，只用于活动之间比较。

### 2.4 多个优惠同时命中一笔储值
- 首储、生涯限购、折扣按现有顺序「首储 → 生涯限购 → 折扣（接替储优）→ 基本品项」只取一个。
- 取出的结果再与满减比较，只给加赠多的一个（按折算老币比较），不叠加。
- 累充、团购按金额照常累计，不受上面的取舍影响。
- 同一工具（折扣或满减）的两个活动在时间、对象、适用商品上都有重叠时，提交审核时提示冲突，审核人确认后才能通过；同时生效时同一笔只给加赠多的一个。

### 2.3 权限与记录
- 权限：查看、编辑、审核三种，按工具分别授予；编辑与审核都含查看；编辑与审核可同时授予一人，但创建人或修改人不能审核自己提交的内容。
- 操作记录：新建、修改（改前改后）、审核、上下架、提前结束，记录人与时间。

## 3. 工具

### T1 礼包（统一现有六类礼包：独享、三选一、每日、平台限量、专属、超值）
- **用途**：卖一组道具或加赠，如每日礼包、三选一、平台限量、专属礼包、超值礼包、首储礼包。
- **规则**：
  - 形式：单包／多选一（2–3 个包选 1）／每日刷新（每日 0 点重置可买次数）／全服限量（总份数售完即止）／分日领取（买一次，之后分 N 天领取）。
  - 分日领取：领取天数 N（2–30 天）；每天的奖励可分别设置；购买当天或次日起每天登录后手动领取（可领时有红点）；当天未领的作废，不补领；活动结束后，已购买的剩余天数照常每天领完，不受活动结束与领奖截止影响；例：回馈卡（买指定礼包后每天领 4%）、7 日礼（买一次连领 7 天）。
  - 显示位置：每日刷新、多选一固定在线上购点；全服限量固定在优惠礼包 · 平台限量；单包、分日领取由运营在线上购点、专属礼包、卡别限购、超值礼包四处里选一个（见 1.3）。
  - 多选一：玩家每期只能买其中 1 个包；限购次数按活动计（买任一包算 1 次）；卡别加码按活动统一设置，对各包同样生效。
  - 商品：从现有储值品项选价格档（App 内购价格档固定，只能选已有档位）。
  - 内容：道具 × 数量，可多项；可标「价值 X 老币」。
  - 限购：每人每期 N 次；全服 N 份（限量形式必填）。
  - 卡别加码：按卡别加赠比例（沿用现有卡别加码回馈）。
- **版式**：礼包卡，显示在银行现有页签（见 1.3「礼包与折扣的显示位置」），沿用现有卡片样式（限量、限购次数、倒计时、加赠角标）；分日领取另有领取页（第几天、今日奖励、领取按钮）；超值礼包详情页模板：主图＋内容清单＋价格＋购买按钮＋倒计时——不再每个包单独做活动页。
- **现有基础**：储值活动设定（独享、三选一、每日、平台限量、专属）与产包设定（超值礼包）。上线后礼包类活动改在活动配置里新建；储值活动设定里这五类停止新建，已有活动跑到期；储值品项与产包设定不变，商品与价格档仍在那里维护。
- **首储**：首储礼包（一生一次）作为礼包的一种限购规则「每人终身 1 次」处理，首储的优先级链（首储 → 生涯限购 → 储优 → 基本品项）不变，折扣上线后接替储优的位置（见 2.4）。

### T2 累充
- **用途**：储值达到门槛送奖励，如「周五 18:00–24:00 累计储值满 1,000 送 A，满 3,000 送 B」。
- **规则**：
  - 统计方式：活动期累计／每期累计（循环活动每期重置）。
  - 储值渠道：全部／指定（App 内购、官网、FunPay 全家、MyCard、Gash、iWIN、ibon、游戏绿卡、游e卡）。
  - 档位：门槛金额（台币）→ 奖励（道具 × 数量），最多 10 档，逐档领取。
  - 领取：达成自动发放／玩家手动领取（默认手动，领取有红点）；活动结束后（含到成本上限提前结束），领奖截止内仍可领已达成未领的档位。
- **版式**：进度条（已储值 / 下一档）＋档位列表＋领取按钮。
- **现有基础**：金流活动设定的「累储单笔」「累储累计」（目前只支持第三方渠道）；本工具扩为全渠道并接入通用设置。上线后这两类停止新建，已有活动跑到期；金流活动设定里的序号活动、礼物卡活动不变。

### T7 满减（单笔满额加赠）
- **用途**：单笔储值或购买满额就加赠，如「本周末单笔储值满 1,000 加赠 10%」。
- **规则**：
  - 储值渠道：全部／指定（同累充）。
  - 适用商品：全部面额／指定面额或礼包。
  - 档位：单笔金额门槛（台币）→ 加赠（加赠比例或固定道具），最多 5 档；每笔只按达到的最高档给一次。
  - 每人限次：每期最多 N 次。
- **形态**：加赠，不做实付立减（App 内购价格档固定）。【替你定】
- **版式**：在银行对应面额与礼包上显示「满 X 送 Y」角标；储值活动页列出档位与剩余次数。
- **和累充、折扣的区别**：满减看单笔金额；累充看累计金额；折扣不设门槛，指定商品直接加赠。
- **与其他优惠同时满足**：见 2.4，与首储、生涯限购、折扣取出的结果比较，只给加赠多的一个。

### T3 折扣（限时储值加赠）
- **用途**：指定面额或礼包限时多给，如「本周储值 500 档加赠 30%」。
- **规则**：适用商品（指定面额／礼包）；加赠比例或固定加赠数量；每人限次；可按卡别设不同比例。
- **形态**：同价加赠，不做实付打折（App 内购价格档固定）；统一现有储优回馈、限时加码，折扣上线后这两类在储值活动设定里停止新建，已有活动跑到期。【替你定】
- **版式**：在银行对应面额与礼包上显示「加赠 X%」角标与倒计时（沿用现有角标样式）；不在「储值活动」页签另列。
- **优先级**：与首储、生涯限购同时满足时，按现有优先级链取一个，不叠加；折扣接替储优的位置，结果再与满减比较（见 2.4）。

### T4 抽奖
- **用途**：抽奖券抽奖池，如抽奖大厅、庆典抽奖。
- **规则**：
  - 抽奖券：券种（最多 3 种）；获取方式可多选：每储值 X 台币得 1 张／每押注 X 得 1 张／完成任务得券／用老币购买。
  - 奖池：奖品 × 数量 × 机率，机率合计 100%；每个奖可设库存；必须设 1 个不限库存的兜底奖。某奖库存抽完后，其机率并入兜底奖，其他奖机率不变，公示随之更新。
  - 保底：连续 N 抽未中指定奖，第 N 抽必中（N 由运营填，可不设）。
  - 形式：转盘／刮卡／开箱（仅换版式，规则相同）。
  - 每日抽奖上限；满券领奖（累计获得券数达门槛领奖）。
- **合规**：抽奖券可用储值或购买获得时，页面公示各奖项机率（台湾线上游戏定型化契约对机率型商品的要求，上线前请法务确认）。
- **主入口**：按 1.2 判断——券只能靠储值或购买获得 → 商城；否则选了指定游戏 → 游戏活动，未选 → 平台活动。
- **现有基础**：抽奖大厅后台（领券抽奖、满券领奖、转盘奖励、活动记录）；本工具在其上通用化。

### T5 团购（全服阶梯返利）
- **用途**：全服一起买同一商品，人数越多每人返利越多，如「100 人返 5%，300 人返 10%，1,000 人返 20%」。
- **规则**：团购商品（礼包或面额）；人数阶梯（最多 5 阶，按购买人数计，同一人多次购买算 1 人）；返利形式二选一：按购买者在团购商品上所得老币的比例补发老币（同一人多次购买按合计），或每阶补发固定道具；活动结束后按最终达到的阶梯统一补发给所有购买者，不累加低阶返利。
- **边界**：不含邀请好友成团；邀请类玩法归「裂变＋回流」。【替你定】
- **版式**：当前参团人数、阶梯进度、我的预计返利、购买按钮。

### T6 一元夺宝（凑满开奖）
- **用途**：每期一个大奖，卖券凑满即开奖。需求原文两例：「购买奖券，满 1.1 万，抽 1 万」——奖品价值 1 万、售券满 1.1 万开奖；「储值 10 万台币开奖，送 1000」——开奖条件为全服本期累计储值满 10 万台币，奖品 1,000（原文未写单位）。两例的每期截止时间原文未写，举例时按 7 天。
- **规则**：
  - 每期：奖品；开奖条件二选一（售券数满 N 张／全服本期累计储值满 X 台币）；每期截止时间（必填）；券价格与获取（老币购买，或每储值 X 台币得 1 张）；每人每期限购。
  - 开奖：达到开奖条件后立即按券号随机开出中奖者（默认 1 名，可设多名）。到截止时间仍未达到：照常开奖／退还券（老币购买的退回老币，储值赠券作废）／顺延到下一期，三选一。
  - 期数：本期开奖后自动开下一期，直到活动结束或达到期数上限。
  - 公示：每期参与人数、开奖号码、中奖人（昵称遮蔽）。
- **版式**：当期奖品图、进度（已售券数 / 目标，或已储值 / 目标）、本期截止倒计时、我的券号、购券按钮、往期开奖记录。
- **合规**：以台币直接购券换奖存在博弈合规风险，本工具只支持老币购券或储值赠券；上线前请法务确认。【替你定】

依据：重复开发的来源（日常月份动用研发的 12 个重复开发全是礼包类：超值礼包页、首储、每日与独享礼包等；另 22 个出自两次庆典）、已有后台基础、约 6 周开发期。

| 档 | 内容 |

- 必需里的「限时活动分游戏/平台」含「大厅限时活动入口」后台加「所在页签」「右侧大图」两个字段（见 1.3）。
