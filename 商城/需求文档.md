# 活动配置工具 · 需求文档

| 项目 | 内容 |
|---|---|
| 需求名称 | 活动配置工具（需求表项目名「入口调整」，优先级 P0） |
| 方案设计稿 | `商城/资料/方案设计稿.md`；文中「设计稿 N.N」指该稿的节号 |
| 现状资料 | `商城/2026-10-27_活动配置工具_现状盘点.html`；明细 `商城/资料/重复开发与储值活动明细.md`、`商城/资料/入口后台配置明细.md`；现有后台的菜单名、字段名以明细为准 |
| 时间约定 | 活动的开始、结束时间按 UTC 存储，后台与客户端按所在时区显示；文中「每日 0 点」「每周五 18:00」等时刻按 4.1.2「时间」的时区规则解释 |
| 名词 | **工具**：用参数配出一类活动的玩法模板，玩法逻辑只开发一次。**商城**：即银行，大厅左下入口，文中二者同指。**主入口**：玩家参与活动的位置，由系统按归属规则判断。**曝光位**：只做引流的位置，点击都跳主入口。**期**：循环活动的一个时段。**开奖期**：一元夺宝的一次开奖周期。**老币**：游戏内货币，奖励成本按老币折算 |

## 2 需求背景

<a id="s2-1"></a>
### 2.1 需求原因

需求原文：「活動靈活配置使用，通過配置滿足各情況下『營運需求』，如：週五要不要做一個儲值活動／節慶活動」。

| 项 | 说明 |
|---|---|
| 运营需要随时、按人群上储值活动 | 观察指标是储值人数与储值额（付费率 × 客单价） |
| 重复开发占用研发排期 | 近 12 个月储值、商城类活动开发需求 148 个，其中 52 个是动用研发（客户端、服务器、后台或 web）的重复开发，约每月 4 个（52 个 ÷ 12 个月） |
| 做法 | 活动＝工具＋参数＋素材＋投放。运营在后台选工具、填参数、选版式、选对象和入口即可上线，玩法逻辑只开发一次 |

<a id="s2-2"></a>
### 2.2 现状

**开发量**（Jira 项目 RICH，Epic 类型，2025-11-01 至 2026-10-26，共 12 个月；按标题人工归类；用别名命名的活动未计入，148 个是下限）

| 指标 | 数值 | 分母与说明 |
|---|---|---|
| 储值、商城类活动开发需求 | 148 个 | 月均约 12 个 |
| 重复开发 | 动用研发的 52 个，占 148 个的 35%；另有 11 个只涉及美术、策划或没有子任务 | 按轮次或按包重开 34 个；同一变更按活动拆单 18 个 |
| 庆典月集中 | 动用研发的 34 个按轮次或按包重开里，22 个来自 8–9 月的两次庆典 | 其余月份的 12 个全是礼包类：超值礼包页、首储、每日与独享礼包等 |
| 已有活动的优化 | 60 个，占 41% | 分母 148 个 |
| 新玩法 | 19 个，占 13% | 分母 148 个 |
| 商城、银行改版 | 6 个，占 4% | 分母 148 个 |

重复开发的三种实例：

| 形态 | 实例 |
|---|---|
| 按轮次或按包重开 | 10 月庆典与 16 周年庆相隔约 3.5 周，各开一组同样的 6 个模块：活动大页、抽奖大厅、储优、人数活动、游戏导航弹窗、换皮。超值礼包每出一个新包开一组需求，2025-09 至 2026-06 共 9 个，子单只有美术、web、策划、QA |
| 同一变更按活动拆单 | 新增「至尊卡」后，礼包、转盘、补给站、抽奖大厅、排行榜等各开一单，共 12 个 Epic；「活动周期内储值」参与条件拆成 7 单 |
| 每个玩法一套后台 | 扭蛋机、每日补给、红包夺宝、抽奖大厅各有独立后台菜单和需求文档；两次庆典的抽奖大厅规则不同，各开一组需求 |

手工逐页做的后果：10 月庆典的活动大页开了 14 张官网问题单，多为活动时间写错、内容与规格不符、错字和漏字。

**上线一个储值活动现在的步骤**

| 步骤 | 做法 |
|---|---|
| 配优惠 | 后台「金流储值 → 储值品项管理 → 储值活动设定」配储值回馈、卡别加码、对象、时间 |
| 做活动页 | 每轮新开一组需求：美术、策划、web、测试。例：「储值金好康」10 月庆典、16 周年庆各做一次 |
| 挂入口 | 好康、限时活动、公告、大厅 Banner 各在自己的后台配一次 |
| 新活动进不了入口 | 入口的「链接位置」下拉没有新活动，要研发补。例：卡别补给站、至尊回归（好康、限时活动、大厅自动弹窗三处下拉都缺） |

**三个入口现状**

| 入口 | 位置与后台 | 玩家看到 | 标签词表 |
|---|---|---|---|
| 好康活动 | 大厅左下；后台「活动管理 → 好康设置 → 活动列表」，4 类条目：宣传图链接、营运活动、外赠活动、活动排行 | 排行榜、外赠、十月庆典、抽奖大厅、黄金百万、储值等，一次看一档大图 | 5 个：精選、儲值、好康、最新、熱門 |
| 限时活动 | 大厅右下；后台「活动管理 → 大厅限时活动入口」 | 图标网格，最多 20 个，不可滑动，带剩余天数和红点 | 6 个角标：押注、儲值、登入、分享、回歸、其他；没有游戏活动与平台活动分区 |
| 公告 | 右上菜单「公告讯息」；后台「公告管理」（热门资讯、系统公告、Loading 页公告、大厅 Banner） | 「最新活动」大图列表、「公告讯息」 | 精選、儲值、好康，加游戏类型标签；没有官方、活动、其他分类 |

三个入口各配一次：祈福财神庙同时挂在限时活动、好康、推播、快显、热门资讯，另有游戏内悬浮和背包道具。

**工具现状**

| 需求里的工具 | 现在有没有 | 现状 |
|---|---|---|
| 礼包 | 有，类型最多 | 半模板：包内容能配，新类型和活动页要开发 |
| 累充 | 有，散在多处 | 累储活动、每日补给的累计任务、储值助阵榜、抽奖大厅储值送券各在各的玩法里实现；金流活动设定有「累储单笔」「累储累计」，目前只支持第三方渠道 |
| 抽奖 | 有，多种 | 抽奖大厅、月月抽、扭蛋机、红包夺宝、金币小玛莉等各一套后台 |
| 折扣 | 没有独立工具 | 由储优回馈、优惠券、限时加码分别承担 |
| 满减 | 没有 | 没有「满 X 减 Y」；最接近的是满购礼包、满购抽奖，属一次性开发 |
| 团购 | 没有 | — |
| 一元夺宝 | 没有 | — |

<a id="s2-3"></a>
### 2.3 存在的问题与目标效果

| 现状问题 | 具体表现 | 目标效果（改后） |
|---|---|---|
| 同类活动每次重新开发 | 近 12 个月 148 个活动开发需求中，52 个是动用研发的重复开发 | 必需档覆盖的活动类型上线不需要开发，只需美术出主视觉；这些类型的重复开发需求降到 0 个 |
| 储值活动上线要排期 | 配优惠之外，活动页每轮要美术、策划、web、测试 | 一个储值活动从决定到上线：配置加审核 1 个工作日内 |
| 三个入口三套后台，定位重叠 | 同一活动要在好康、限时活动、公告各配一次，同一活动挂 5–7 处；标签词表三套 | 活动配一次，系统判断主入口；三个入口按「玩家怎么参与」分工：要付费参与的进商城，免费参与的进限时活动，纯信息进公告；标签词表一套 |
| 新活动进不了入口 | 「链接位置」下拉没有新活动，要研发补 | 活动配好后自动出现在所有入口与曝光位的可选列表里 |
| 没有按活动的统一数据 | 储值额与成本没有统一的计算方式 | 每个活动可查储值额、发奖成本、储值额/成本 |

<a id="s3"></a>
## 3 需求目标

<a id="s3-1"></a>
### 3.1 目标

| 目标 | 做到什么 |
|---|---|
| 目标 1：活动配置化 | 运营在后台选工具、填参数、选版式、选对象和入口即可上线；玩法逻辑只开发一次；必需档覆盖的活动类型重复开发需求降到 0 个 |
| 目标 2：入口分工清晰 | 商城放要储值或购买才能参与的内容，限时活动放免费参与、有时限的活动，公告只放信息；主入口由系统按归属规则判断，运营不手选 |
| 目标 3：上线快 | 一个储值活动从决定到上线：配置加审核 1 个工作日内 |
| 目标 4：数据查得到 | 每个活动可查储值额、发奖成本、储值额/成本，列表可看成本进度 |
| 目标 5：成本与出错可控 | 上架前由另一位有审核权限的人审核；提交审核时显示预估成本；设活动总成本上限；进行中不可改规则、对象、奖励；上线前可用测试账号验证 |

<a id="s3-2"></a>
### 3.2 需求项与分级

分级：必需＝本期交付范围；尽量＝必需档之外争取交付；可选＝有余量时交付（一元夺宝须法务确认后）。开发期约 6 周；研发估时后必需档放不下时，按「通用设置（含复制、审核、数据页、权限与操作记录）→ 礼包 → 商城（银行迁移＋储值活动页签）→ 累充 → 满减 → 限时活动与公告改版 → 折扣」的顺序保留；累充、满减只显示在「储值活动」页签，所以商城排在它们之前。

| 编号 | 需求项 | 分级 | 目标 | 章节 |
|---|---|---|---|---|
| 1 | 通用设置：基本信息、时间（开始与结束、领奖截止）、对象、预算与上限、展示、素材；不含循环、预估成本、测试账号预览 | 必需 | 1、5 | [4.1.1](#s4-1-1)、[4.1.2](#s4-1-2) |
| 2 | 复制为新活动 | 必需 | 3 | [4.1.2](#s4-1-2) |
| 3 | 状态流转、上架前审核、后台预览 | 必需 | 5 | [4.1.3](#s4-1-3) |

<a id="s4-1-2"></a>
#### 4.1.2 通用设置（所有工具共用）

**基本信息**

| 项 | 规则 |
|---|---|
| 活动名称 | 必填；繁中、英文、越南文各填一份（与现有多语言一致） |
| 活动说明 | 系统按工具规则自动生成规则摘要，内容含时间、档位、奖励、限购；运营可在摘要下方补充说明；三种语言 |
| 活动编号 | 系统生成 |
| 点数异动科目 | 系统按「工具名-活动编号」自动生成，例：累充-A202612001；不再为每个活动开发科目代码 |

**时间**

| 项 | 规则 |
|---|---|
| 开始、结束时间 | 必填；按 UTC 存，界面按所在时区显示。循环时段与礼包「每日 0 点」重置使用同一时区：活动录入人所在时区的本地时刻（建议） |
| 循环 | 尽量档；首批不循环，同类活动靠复制再上。三选一：不循环；每日固定时段；每周固定几天固定时段（例：每周五 18:00–24:00）。循环活动的每个时段为一期，期内进度独立；不循环的活动，整个活动期为一期 |
| 领奖截止 | 活动结束后 N 天内可领未领奖励，默认 3 天；过期未领不补发 |

**对象**

| 项 | 规则 |
|---|---|
| 可参与对象 | 四选一：全部玩家；标签群组；卡别；指定会员名单（上传）。沿用现有「活动分组与可参与对象」判定 |
| 排除对象 | 可多选：黑名单、VIP 名单、指定名单、等级区间。排除优先于可参与：同时命中可参与与排除的玩家，不可参与 |
| 活动分组 | 同组只派发一次（沿用现有规则） |
| 平台 | H5、iOS、GP、APK、WEB 多选 |
| 参与游戏 | 全部游戏（默认）；或指定游戏：多选，可按游戏类别选（转轮、柏青、鱼机、棋牌、视讯）；活动只在所选游戏内参与。选了指定游戏，主入口按 [4.1.4](#s4-1-4) 顺序 2 判断 |
| 对象判定的显示效果 | 沿用现有可见对象判定：玩家未被派发到活动时，主入口列表与曝光位不显示该活动。公告不在这套判定内，沿用公告管理自身的可见对象 |

**预算与上限**

| 项 | 规则 |
|---|---|
| 活动总成本上限 | 按奖励折算老币计；累计发奖成本达到上限时，活动自动结束，并通知创建人与审核人。折算：老币按面值；道具按道具设定里的价值（老币）；没有价值的道具，在活动里填写折算值，否则不能提交审核 |
| 每人上限 | 每人在本活动可得奖励的折算上限（老币） |
| 到上限的最后一笔 | 使累计发奖成本达到或超过总成本上限的那一笔照常发放，发放后活动结束；超出部分计入发奖成本。结束后，领奖截止内仍可领取已达成未领的奖励，同样计入成本 |
| 退款、拒付 | 沿用现有储值退款、拒付的处理；已发放的活动奖励按现有规则处理，本需求不另定 |
| 预估成本 | 尽量档。系统按档位、对象人数、历史参与率估算，提交审核时显示 |

**展示**

| 项 | 规则 |
|---|---|
| 主入口 | 系统按 [4.1.4](#s4-1-4) 的归属规则显示，不可手选 |
| 显示位置 | 礼包活动：每日刷新、多选一、全服限量的位置由形式固定；单包、分日领取由运营在允许的位置里选（见 [4.1.6](#s4-1-6)）。其余工具见各工具的「主入口」 |
| 页签标签 | 一套统一标签：储值、押注、登入、分享、回归、其他，单选；取代好康、限时活动、热门资讯三套词表（见 [4.2.8](#s4-2-8)）；另可勾「新」「热」角标。页签标签是后台字段，用于后台排序、筛选与统计，不在客户端显示；客户端只显示「新」「热」角标（可无） |
| 排序权重 | 整数，大的在前；权重相同按开始时间晚的在前 |
| 曝光位 | 多选，位置与规则见 [4.1.4](#s4-1-4) |

**素材与复制**

| 项 | 规则 |
|---|---|
| 版式 | 每个工具提供固定版式：抽奖按形式分转盘、刮卡、开箱三套，其余工具各 1–2 套（见各工具）；时间、档位、奖励、进度、按钮由系统按配置渲染，不画在图里 |
| 主视觉图 | 上传 1 张主图，支持 spine；可选主题色；限时活动窗口右侧显示该图 |
| 复制 | 任一活动可「复制为新活动」，带出全部设置，改时间与素材即可再上；新活动的状态为草稿 |

<a id="s4-1-3"></a>
#### 4.1.3 状态、审核与测试

状态流转：草稿 → 待审核（可退回草稿）→ 已排程 → 进行中 → 已结束；已排程、进行中可「下架」。

| 状态 | 进入条件 | 可做的操作 |
|---|---|---|
| 草稿 | 新建；复制；待审核时被退回 | 编辑、提交审核 |
| 待审核 | 提交审核 | 审核：通过；退回草稿 |
| 已排程 | 审核通过 | 下架 |
| 进行中 | 已排程的活动到开始时间 | 改素材、改说明补充、延长结束时间、上调成本上限（以上改动要审核）；提前结束、下架（不需审核，立即生效） |
| 已结束 | 到结束时间；提前结束；累计发奖成本达到总成本上限 | 查看数据；复制 |
| 已下架（建议） | 对已排程或进行中的活动执行下架 | 查看数据；复制 |

| 规则 | 内容 |
|---|---|
| 进行中可改 | 素材、说明补充、延长结束时间、上调成本上限（要审核）；提前结束、下架（不需审核，立即生效） |
| 进行中不可改 | 工具规则、对象、奖励、开始时间，防客诉 |
| 进行中改动的审核 | 进行中的改动同样要审核，审核规则同上架前审核；改动在审核通过后生效，审核期间活动保持进行中（生效时点与审核期间的状态为建议） |
| 审核 | 上架前由另一位有审核权限的人通过：创建人或修改人不能审核自己提交的内容。审核页显示规则摘要；预估成本在尽量档加入 |
| 预览 | 后台预览：按所选版式渲染玩家端页面，竖版、横版各一，可切换语言；提交审核前至少预览一次 |
| 测试账号预览 | 尽量档。上架前可指定测试账号，在正式服看到并参与活动；测试账号的数据不计入活动数据（[4.1.14](#s4-1-14)） |

<a id="s4-1-4"></a>
#### 4.1.4 归属规则与曝光位

一个活动只有一个主入口，由系统按活动配置判断，运营不手选。按下表顺序判断，命中即止：

| 顺序 | 条件 | 主入口 |
|---|---|---|
| 1 | 必须先储值或购买才能参与：工具为礼包、累充、满减、折扣、团购、一元夺宝；或工具为抽奖，且抽奖券只能靠储值、购买获得（每种券的获取方式都只有「每储值 X 台币得 1 张」「用老币购买」） | 商城（银行）：礼包、折扣显示在银行现有页签的商品上，其余进「储值活动」页签 |
| 2 | 「参与游戏」选了指定游戏，只在某些游戏内参与：排行榜、外赠掉落、游戏挑战、新游戏活动、红包雨分游戏类别、BOSS 战 | 限时活动 · 游戏活动 |
| 3 | 其余：签到、庆典主活动、人数活动、回归、全平台抽奖等 | 限时活动 · 平台活动 |

顺序 1 判断时注意三点：

- 只把「本期储值过」作为参与资格的押注、登入、任务等活动不算，按顺序 2、3 判断。
- 活动内可选的付费道具（如可选购买的加速包）不算，活动本身按核心玩法判断。
- 「买一次、之后每天领」（如回馈卡、7 日礼）按购买处理，归商城（银行），见 [4.1.6](#s4-1-6)「分日领取」。

「参与游戏」是通用设置的字段（[4.1.2](#s4-1-2)）；现有玩法接入展示设置时同样登记（[4.2.9](#s4-2-9)）。

**曝光位**：只做引流，点击都跳主入口；可多选。首批（必需档）勾选曝光位只把活动列进各模块的跳转目标，由各模块自行配置；勾选后系统自动生成下列内容为尽量档：

| 曝光位 | 勾选后 |
|---|---|
| 公告「活动」分类 | 系统自动生成一条公告：标题取自活动名称、正文取自活动说明，不带图；随活动上架、结束自动下架 |
| 大厅 Banner | 系统自动生成一条 Banner，需上传对应尺寸的图（沿用现有大厅 Banner 的图片规格）；随活动上下架 |
| 游戏内悬浮按钮 | 系统自动生成一条悬浮入口，需上传对应尺寸的图（沿用现有游戏内悬浮的图片规格）；随活动上下架 |
| 大厅自动弹窗 | 在推送统一后台生成一条草稿，跳转目标已填为该活动；投放规则由运营在推送统一后台补齐后发布 |
| 推播（发到玩家手机通知栏的系统通知，玩家不在游戏里也能收到；点开后打开 App 并直接进入该活动的主入口） | 在推送统一后台生成一条推播草稿，跳转目标已填为该活动；发送对象、发送时间由运营在推送统一后台补齐后发出 |

活动配好后，自动出现在所有入口与曝光位的可选列表里，不再需要研发把新活动加进「链接位置」下拉（见 [4.2.8](#s4-2-8)）。进入可选列表的状态条件：已排程、进行中（建议）。

<a id="s4-1-5"></a>
#### 4.1.5 商城「储值活动」页签

商城页面结构见 [4.2.2](#s4-2-2)。「储值活动」页签只放累充、满减、团购、付费抽奖（抽奖券只能靠储值、购买获得）、一元夺宝；礼包按形式显示在银行现有页签（见 [4.1.6](#s4-1-6)），折扣以「加赠 X%」角标显示在面额与礼包上（见 [4.1.9](#s4-1-9)）。

| 项 | 规则 |
|---|---|
| 左侧活动列表 | 按排序权重排列，大的在前，权重相同按开始时间晚的在前；每项显示名称、「新」「热」角标（可无）、剩余天数或「今日截止」、红点，不显示页签标签 |
| 右侧 | 所选活动的工具版式页（版式见各工具） |
| 默认页签 | 对该玩家可见（在可参与对象内、不在排除对象内）的进行中储值活动存在时，默认打开「储值活动」页签；否则打开「线上购点」 |

<a id="s4-1-6"></a>
#### 4.1.6 礼包

用途：卖一组道具或加赠，如每日礼包、三选一、平台限量、专属礼包、超值礼包、首储礼包。统一现有六类礼包：独享、三选一、每日、平台限量、专属、超值；首储礼包按限购规则处理，不算第七类。

| 项 | 规则 |
|---|---|
| 形式 | 五选一：单包；多选一（2–3 个包选 1）；每日刷新（每日 0 点重置可买次数）；全服限量（总份数售完即止）；分日领取（买一次，之后分 N 天领取） |
| 分日领取 | 领取天数 N（2–30 天）；每天的奖励可分别设置；购买当天或次日起，每天登录后手动领取，可领时有红点；当天未领的作废，不补领。活动结束后，已购买的剩余天数照常每天领完，不受活动结束与领奖截止影响。例：回馈卡（买指定礼包后每天领 4%）、7 日礼（买一次连领 7 天） |
| 多选一 | 玩家每期只能买其中 1 个包；限购次数按活动计（买任一包算 1 次）；卡别加码按活动统一设置，对各包同样生效 |
| 商品 | 从现有储值品项选价格档；App 内购价格档固定，只能选已有档位 |
| 内容 | 道具 × 数量，可多项；可标「价值 X 老币」 |
| 限购 | 每人每期 N 次；全服 N 份（限量形式必填） |
| 卡别加码 | 按卡别加赠比例，沿用现有卡别加码回馈 |
| 首储 | 首储礼包（一生一次）作为礼包的一种限购规则「每人终身 1 次」处理；首储的优先级链「首储 → 生涯限购 → 储优 → 基本品项」不变，折扣上线后接替储优的位置（[4.1.9](#s4-1-9)） |
| 显示位置 | 部分由形式固定，部分由运营选：每日刷新、多选一固定在银行「线上购点」；全服限量固定在「优惠礼包 · 平台限量」；单包、分日领取由运营在「线上购点」「优惠礼包 · 专属礼包」「优惠礼包 · 卡别限购」「超值礼包」四处里选一个（现在的独享礼包在线上购点，专属、卡别限购礼包在优惠礼包，超值礼包在超值礼包，都是单包） |
| 版式 | 礼包卡显示在银行现有页签，沿用现有卡片样式（限量、限购次数、倒计时、加赠角标）；分日领取另有领取页：第几天、今日奖励、领取按钮；超值礼包详情页模板：主图＋内容清单＋价格＋购买按钮＋倒计时，不再每个包单独做活动页 |
| 主入口 | 商城（银行）；显示位置见上，不进「储值活动」页签 |

现有基础与现有活动的处理见 [4.2.5](#s4-2-5)。

<a id="s4-1-7"></a>
#### 4.1.7 累充

用途：储值达到门槛送奖励，如「周五 18:00–24:00 累计储值满 1,000 送 A，满 3,000 送 B」。

| 项 | 规则 |
|---|---|
| 统计方式 | 二选一：活动期累计；每期累计（循环活动每期重置，循环为尽量档） |
| 储值渠道 | 全部；或指定：App 内购、官网、FunPay 全家、MyCard、Gash、iWIN、ibon、游戏绿卡、游e卡 |
| 档位 | 门槛金额（台币）→ 奖励（道具 × 数量），最多 10 档，逐档领取 |
| 领取 | 达成自动发放；或玩家手动领取（默认手动，可领取时有红点）。活动结束后（含到成本上限提前结束），领奖截止内仍可领取已达成未领的档位 |
| 版式 | 进度条（已储值 / 下一档）＋档位列表＋领取按钮 |
| 主入口 | 商城（银行）「储值活动」页签 |

单笔满额加赠见 [4.1.8](#s4-1-8) 满减。现有基础见 [4.2.6](#s4-2-6)。

<a id="s4-1-8"></a>
#### 4.1.8 满减（单笔满额加赠）

用途：单笔储值或购买满额就加赠，如「本周末单笔储值满 1,000 加赠 10%」。

| 项 | 规则 |
|---|---|
| 储值渠道 | 全部；或指定（同累充，见 [4.1.7](#s4-1-7)） |
| 适用商品 | 全部面额；或指定面额、礼包 |
| 档位 | 单笔金额门槛（台币）→ 加赠（加赠比例，或固定道具），最多 5 档；每笔只按达到的最高档给一次 |
| 每人限次 | 每期最多 N 次 |
| 形态 | 加赠，不做实付立减（App 内购价格档固定） |
| 与累充、折扣的区别 | 满减看单笔金额；累充看累计金额；折扣不设门槛，指定商品直接加赠 |
| 与其他优惠同时满足 | 同一笔先按「首储 → 生涯限购 → 折扣 → 基本品项」取出一个（见 [4.1.9](#s4-1-9)），再与满减比较，只给加赠多的一个（按折算老币比较），不叠加；累充、团购按金额照常累计，不受影响 |
| 版式 | 在商城对应面额与礼包上显示「满 X 送 Y」角标；「储值活动」页列出档位与剩余次数 |
| 主入口 | 商城（银行）「储值活动」页签 |

<a id="s4-1-9"></a>
#### 4.1.9 折扣（限时储值加赠）

用途：指定面额或礼包限时多给，如「本周储值 500 档加赠 30%」。

| 项 | 规则 |
|---|---|
| 适用商品 | 指定面额；或礼包 |
| 加赠 | 加赠比例；或固定加赠数量 |
| 限次 | 每人限次 |
| 卡别 | 可按卡别设不同比例 |
| 形态 | 同价加赠，不做实付打折（App 内购价格档固定）；统一现有储优回馈、限时加码 |
| 优先级 | 与首储、生涯限购同时满足时，按现有优先级链取一个，不叠加；折扣取代储优在链中的位置：首储 → 生涯限购 → 折扣 → 基本品项。取出的结果再与满减比较，只给加赠多的一个（见 [4.1.8](#s4-1-8)） |
| 同工具活动重叠 | 两个折扣活动（或两个满减活动）在时间、对象、适用商品上都有重叠时，提交审核时提示冲突，审核人确认后才能通过；同时生效时，同一笔只给加赠多的一个 |
| 版式 | 在商城对应面额与礼包上显示「加赠 X%」角标，沿用现在「336%」「108%」的角标样式（固定加赠数量时显示加赠数量），带倒计时 |
| 主入口 | 商城（银行）；不进「储值活动」页签，以角标显示在面额与礼包上 |

<a id="s4-1-10"></a>
#### 4.1.10 抽奖

用途：抽奖券抽奖池，如抽奖大厅、庆典抽奖。

| 项 | 规则 |
|---|---|
| 抽奖券 | 券种最多 3 种；获取方式可多选：每储值 X 台币得 1 张；每押注 X 得 1 张；完成任务得券；用老币购买 |
| 奖池 | 奖品 × 数量 × 机率，机率合计 100%；每个奖可设库存；必须设 1 个不限库存的兜底奖。某奖库存抽完后，其机率并入兜底奖，其他奖机率不变，公示随之更新 |
| 保底 | 连续 N 抽未中指定奖，第 N 抽必中；N 由运营填，可不设 |
| 形式 | 转盘、刮卡、开箱三选一，只换版式，规则相同 |
| 每日抽奖上限 | 每人每日最多抽奖次数（建议） |
| 满券领奖 | 累计获得券数达门槛领奖 |
| 机率公示 | 抽奖券可用储值或购买获得时，页面公示各奖项机率；上线前须法务确认（台湾线上游戏定型化契约对机率型商品的要求） |
| 主入口 | 按 [4.1.4](#s4-1-4) 判断：抽奖券只能靠储值、购买获得，进商城（银行）「储值活动」页签；否则选了指定游戏，进限时活动 · 游戏活动，未选，进限时活动 · 平台活动 |

现有基础见 [4.2.7](#s4-2-7)。

<a id="s4-1-11"></a>
#### 4.1.11 团购（全服阶梯返利）

用途：全服一起买同一商品，人数越多每人返利越多，如「100 人返 5%，300 人返 10%，1,000 人返 20%」。

| 项 | 规则 |
|---|---|
| 团购商品 | 礼包或面额 |
| 人数阶梯 | 最多 5 阶；按购买人数计，同一人多次购买算 1 人 |
| 返利形式 | 二选一：按购买者在团购商品上所得老币的比例补发老币（同一人多次购买按合计）；或每阶补发固定道具 |
| 补发 | 活动结束后，按最终达到的阶梯统一补发给所有购买者，不累加低阶返利 |
| 边界 | 不含邀请好友成团；邀请类玩法归「裂变＋回流」 |
| 版式 | 当前参团人数、阶梯进度、我的预计返利、购买按钮 |
| 主入口 | 商城（银行）「储值活动」页签 |

<a id="s4-1-12"></a>
#### 4.1.12 一元夺宝（凑满开奖）

用途：每个开奖期一个大奖，卖券凑满即开奖。原文两例：「购买奖券，满 1.1 万，抽 1 万」：奖品价值 1 万，售券满 1.1 万开奖；「储值 10 万台币开奖，送 1000」：开奖条件为全服本期累计储值满 10 万台币，奖品 1,000（原文未写单位）。两例的每期截止时间原文未写，举例按 7 天。

| 项 | 规则 |
|---|---|
| 每个开奖期的配置 | 奖品；开奖条件二选一（售券数满 N 张；全服本期累计储值满 X 台币）；每期截止时间（必填）；券价格与获取（老币购买，或每储值 X 台币得 1 张）；每人每开奖期限购 |
| 开奖 | 达到开奖条件后立即按券号随机开出中奖者，默认 1 名，可设多名 |
| 到截止时间仍未达到开奖条件 | 三选一：照常开奖；退还券（老币购买的退回老币，储值赠券作废）；顺延到下一开奖期 |
| 开奖期数 | 一个开奖期开奖后自动开下一个开奖期，直到活动结束或达到开奖期数上限 |
| 公示 | 每个开奖期公示参与人数、开奖号码、中奖人（昵称遮蔽） |
| 版式 | 当期奖品图、进度（已售券数 / 目标，或已储值 / 目标）、本期截止倒计时、我的券号、购券按钮、往期开奖记录 |
| 合规 | 以台币直接购券换奖存在博弈合规风险：本工具只支持老币购券或储值赠券；上线前须法务确认 |
| 主入口 | 商城（银行）「储值活动」页签 |

<a id="s4-1-13"></a>
#### 4.1.13 庆典专题页（尽量档）

庆典专题页不是工具，是一种聚合版式。

| 项 | 规则 |
|---|---|
| 用途 | 庆典期间把多个活动放进一个页面，取代每次庆典单独开发的活动大页 |
| 页面构成 | 头图（主视觉）；页签分组，如储优、抽奖、押注活动，最多 6 个；每个页签下从已配置的活动中选若干个，按顺序排列 |
| 活动卡 | 每张活动卡显示活动名称、时间、主视觉缩略图、前往按钮（跳活动主入口） |
| 玩法 | 专题页本身不含玩法，不发奖 |
| 时间 | 专题页的开始、结束时间独立设置；所选活动未开始或已结束时，卡片显示「即将开始」或「已结束」 |
| 主入口 | 限时活动 · 平台活动；可勾选大厅 Banner、大厅自动弹窗等曝光位（[4.1.4](#s4-1-4)） |

字段见 [5.15](#s5-15)。

<a id="s4-1-14"></a>
#### 4.1.14 数据

| 项 | 规则 |
|---|---|
| 活动数据页 | 每个活动一张数据页：曝光人数、打开人数、参与人数、储值人数、储值金额、发奖成本（折算老币）、储值额/成本；按日趋势；可导出参与名单与领奖记录 |
| 活动列表 | 显示每个进行中活动的储值金额与成本进度（成本 / 上限） |
| 储值归因 | 一笔储值或购买用到了哪个活动的礼包或加赠（折扣、满减），就记为该活动的储值；活动期内在活动页内发起的储值也记为该活动；累充、团购按活动自身的统计方式计。一笔命中多个活动时各自都计，数据页注明各活动的储值金额不能相加 |
| 测试账号 | 测试账号的数据不计入 |

指标计算方式（建议）：

| 指标 | 计算方式 | 单位 |
|---|---|---|
| 曝光人数 | 看到该活动的主入口列表项或曝光位的去重玩家数 | 人 |
| 打开人数 | 进入该活动页的去重玩家数 | 人 |
| 参与人数 | 产生参与行为的去重玩家数：礼包、折扣、团购为购买；累充为产生达标储值；满减为产生达标的单笔储值或购买；抽奖为抽奖；一元夺宝为获得券 | 人 |
| 储值人数 | 按储值归因规则归入该活动的去重玩家数 | 人 |
| 储值金额 | 按储值归因规则归入该活动的储值金额合计 | 台币 |
| 发奖成本 | 已发放奖励按老币折算的合计 | 老币 |
| 储值额/成本 | 储值金额 ÷ 发奖成本，两者不换算单位 | 比值 |
