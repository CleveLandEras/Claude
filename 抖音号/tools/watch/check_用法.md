# check.py 用法：出片自查

每次渲完样片、成片都跑一遍（制作工作流第 4、5 步，“10/29 加的三条”第 1 条）。能量出来的规矩由脚本报 PASS / FAIL / WARN，不靠人记。报 FAIL 的改完，才给号主看。

## 怎么跑

在 `/Users/decheng.huang/Documents/dy` 下：

```bash
.venv/bin/python -I tools/watch/check.py 视频.mp4 时间表.json 输出目录 [--lufs -14] [--lufs-tol 1] [--peak -1] [--preview] [--sfx 事件表.json]
```

| 参数 | 默认 | 什么时候改 |
|---|---|---|
| `--lufs` | −14 | 要在抖音曲库里另加配乐的片子（002 起），音效轨传 `--lufs -19` |
| `--lufs-tol` | 1 | 和目标差 ±1 LU 以内算 PASS，再多 1 LU 以内 WARN，更多 FAIL |
| `--peak` | −1 | 真峰值上限，单位 dBTP |
| `--preview` | 不加 | 灰框、预演用：画幅按同比例缩小、没有音轨，只报 WARN，不报 FAIL。样片和成片不要加 |
| `--sfx` | 不传 | 音效事件表（格式见下面“音效事件表”）。传了就按它逐个查 key 点；不传就照旧从时间表里找音效。第二条的在 `studio/public/002/sfx_events.json` |

- 有 FAIL 时退出码是 1，没有是 0。
- 一条 60 秒的片子，跑一遍约 2 秒。只用 `.venv` 里的 numpy、Pillow、imageio-ffmpeg。
- 例子（第二条灰框第三版）：
  ```bash
  .venv/bin/python -I tools/watch/check.py videos/002_做好人/out/灰框/灰框预演_第三版_960x540.mp4 studio/src/videos/002/timeline.json videos/002_做好人/out/灰框/check_第三版
  ```

## 查什么，怎么判

| 项 | PASS | FAIL / WARN | 出处 |
|---|---|---|---|
| 画幅 | 和时间表 `layout.W × layout.H` 一样 | 不一样就 FAIL（`--preview` 下同比例缩小只 WARN） | check.sh |
| 帧率 | 和时间表 `fps` 一样 | 不一样就 FAIL | check.sh |
| 时长 | 视频帧数和时间表 `frames` 差 ≤ 2 帧 | 超过就 FAIL | 任务要求 |
| 第 0 帧不是纯色 | 三个通道的标准差有一个 ≥ 2 | 都 < 2 就 FAIL | check.sh |
| 第 0 帧不闪 | — | 第 0→1 帧平均差 > 6，且是第 1→2 帧的 3 倍以上，就 FAIL | check.sh |
| 第 0 帧和第 1 秒的颜色 | 平均色差 ≤ 6 | > 6 只 WARN：1 秒内本来就有切换时会误报，要对着 12 格图认 | check.sh |
| 整幅静止 | 没有超过 1.5 秒的；超过的都落在【停】拍里（伸出【停】不超过 0.15 秒） | 超过 1.5 秒、又伸出【停】的，FAIL | 验收单④ |
| 0.5 秒以上的静止 | 全部列出：起止、跨哪几拍、在不在【停】里 | 只列出，不判 | 任务要求 |
| 突变 | 都落在拍的边界上 | 不在边界的 WARN，附上附近的拍内事件，由人认是不是计划好的打点 | check.sh |
| 字幕平均每秒字数 | ≤ 4 | > 4 就 FAIL | 验收单② |
| 无字拍比例 | ≥ 30% | < 30% 就 FAIL；正好 30% 时写“没有余量” | 验收单③ |
| 每拍读得完 | 每句按每秒 6.5 字，在它下去之前读得完 | 读不完就 FAIL | 验收单⑤ |
| 最密的 5 秒 | 只列出 | — | timeline.py 的同一算法 |
| 时间表自带的统计 | `stats.checklist` 和脚本算的一致 | 不一致就 WARN（多半是改了时间表没重新生成） | — |
| 字幕字号 | ≥ 54 px | < 54 就 FAIL；时间表里没有字号就 WARN，说明查不了 | 剪辑认知第 18 条 |
| 第 0 秒的字号 | ≥ 50 px | < 50 就 FAIL | 剪辑认知第 18 条 |
| 其他字的字号 | 版面里其他字号都 ≥ 54 px | 有更小的就 WARN（规矩只管字幕，列出来供参考） | — |
| 音轨 | 有 | 没有就 FAIL（`--preview` 下只 WARN） | check.sh |
| 整条响度 | 在目标 ± 1 LU 内 | 差 1–2 LU WARN，更多 FAIL；基本静音也 FAIL | 制作工作流第 5 步 |
| 真峰值 | ≤ −1 dBTP | 超过就 FAIL | 任务要求 |
| 关键音效 1–4 kHz（不传 `--sfx`） | 时间表里找到的音效，前 0.05 秒到后 0.3 秒，1–4 kHz 电平 ≥ 整条响度 − 26 dB（−14 LUFS 时是 −40 dBFS） | 差 10 dB 以内 WARN（弱），再低 FAIL（几乎没有）；时间表没标音效就 WARN | 剪辑认知第 30 条 |
| 音效事件表（传 `--sfx`） | 每条的 frame 和 t 对得上（差 ≤ 1 帧），拍号和帧号所在的拍一样，帧号在片子里 | 有对不上的 WARN（按 frame 算）；文件读不了 FAIL | — |
| key 音效 1–4 kHz（传 `--sfx`） | 每个 key 点前后 ±2 帧，1–4 kHz 电平 ≥ 整条响度 − 26 dB | 有一个没有就 FAIL；没有音轨时 WARN（查不了） | 剪辑认知第 30 条 |
| key 音效和画面突变对齐（传 `--sfx`） | 每个 key 点离最近的画面突变 ≤ 2 帧 | 差超过 2 帧，或前后 15 帧里没有画面突变，WARN；声音故意先到的（剪辑认知第 7 条）可以留 | — |

**口径**
- **帧差**：和 `beats.py` 是同一个算法，`diff.txt` 逐行一样。每秒取 10 帧，缩成 96 宽的灰度图，比相邻两帧的平均差；< 0.15 算这一格不动。精度是 0.1 秒，量出的静止可能比实际短 0.1 秒。
- **静止**：查的是整幅画面不动，不管画面上动的是不是要紧的东西。
- **突变**：帧差 > 中位数的 4 倍。下限是 2，因为片子大半静止时中位数接近 0，4 倍还是 0，会漏掉硬切。连着几格过线的合成一处，中间只隔一格没过线的也合进去。起头那一格、或者帧差最大那一格离拍的边界不超过 0.15 秒，算“在边界上”。
- **字数**：汉字一个算 1，一串数字或字母算 1（“1000”“5%”“99%”各算 1），标点、空格、白点不算；0 秒大题（时间表的 `question.text`）也算。同一句连挂几拍只算一次。
- **无字拍**：这一拍没有新出现的字，就算无字拍。和上一拍是同一句、字幕段在更早的拍里就出现了，都算无字。0 秒大题所在的拍算有字，结尾那拍如果标了【停】，算无字。
- **读字时间**：从这一句出现读到它下去，同一句连挂几拍按整段算。后出现的字幕段（`[字, 颜色, 帧]`）要到那一帧才能开始读。
- **时间**：都按时间表里的帧号 `f0`、`f1` 换算，不用 `t0`、`t1` 的秒数，因为画面是按帧渲的。所以有的数会比 `timeline.py` 打印的大 0.02 秒左右。例如 26.55 秒换成帧是 796，也就是 26.53 秒。
- **电平**：用的是均方根 dBFS，满幅正弦波约 −3 dBFS。“250 Hz 以下占比”是给手机外放看的：外放听不见这一段。

## 时间表要写什么

脚本读的是 `timeline.py` 生成的 json，下面这些字段要有：

| 字段 | 用来查 |
|---|---|
| `fps`、`frames` | 帧率、时长 |
| `layout.W`、`layout.H` | 画幅；字号下限按短边换算（短边 1080 时就是 54 px） |
| `layout.sub.size`、`layout.sub.numSize`，每拍的 `sub.size`、`sub.num` | 字幕字号 |
| `layout.titleBig`，加上 `question.big` 从第 0 帧开始 | 第 0 秒的字号 |
| `question.text`、`question.big`（帧号） | 0 秒大题算进字数和读字 |
| `beats[]` 的 `id`、`f0`、`f1`、`lines`、`stop` | 静止、突变、字幕、拼图 |
| `beats[]` 的 `ev_s` | 给突变找附近的事件；名字像音效的（`whoosh`、`ding`、`嗖`、`叮`、`啪`、`咚`……）算关键音效 |
| `beats[]` 的 `sfx`（可选） | 关键音效，写法：`{"嗖": 0.4, "叮": [8.6, 9.0]}`（秒），或 `[{"name": "咚", "t": 26.9}]`，或 `{"name":, "f": 帧}` |
| `stats.checklist`（可选） | 和脚本算的对一遍 |

做音效时，建议每拍写上 `sfx`。现在 002 的时间表只认得出 2 处音效：S01 的 whoosh 和 S24 的 ding。分镜里写的“嗖”“啪”“咚”，大多还没有进时间表。有了音效事件表就用 `--sfx`，不用再往时间表里补。

## 音效事件表（`--sfx`）

格式是一个列表，每条一个音效：

```json
[{"t": 14.1, "frame": 423, "name": "啪", "beat": "S09", "key": true},
 {"t": 14.5, "frame": 435, "name": "嗖", "beat": "S09", "key": false}]
```

- `frame` 和 `t` 有一个就行，都有时以 `frame` 为准；两个差 1 帧以上会报 WARN。外面再包一层 `{"events": [...]}` 也认。
- `beat` 可以不写。写了就查它和帧号所在的拍是不是同一拍。
- 只有 `key: true` 的点要过两项检查，`key: false` 的只在明细表里列出数字，不判。
  - **1–4 kHz**：取第 N 帧前后 ±2 帧（共 5 帧，约 0.17 秒）的声音，口径和上面一样，门槛是整条响度 − 26 dB。不过就 FAIL，没有“弱”这一档。
  - **和画面突变对齐**：这一项不用声音，灰框也能查。
    - 量法：每帧缩成 96 宽的灰度图，分成 8×6 块，取和上一帧差得最多那一块的平均差。整幅帧差对小东西不灵：光点滑落、落地一闪，整幅只有 1 左右，按块取最大才看得出。
    - 突变的起点：这一帧的局部变化比前两帧都高出 4 以上，而且是它们的两倍以上，就算一次画面突变的起点。
    - 判法：在事件前后 15 帧（0.5 秒）里找离它最近的起点。差 = 突变帧 − 事件帧，正数是声音先到。差超过 2 帧，或 15 帧里一个起点都没有，就 WARN。
- 明细表“音效事件表”里，每条都列出：1–4 kHz 电平、250 Hz 以下占比、最近的画面突变、差几帧。
- 量不准的情况：
  - 声音配的是动作停下来那一下（比如翻色收尾的“叮”），画面上没有起跳，会报成离得最近的另一处突变，差好几帧；
  - 两个突变挨得很近时，可能对到相邻那一个。

  这两种都只报 WARN，要对着明细表和画面认。

## 出什么

都在输出目录里：
- `报告.md`：先列 FAIL，再列 WARN，最后列 PASS。后面附明细：静止段、突变、每拍字幕（字数、要读、有、读完没有）、每拍声音（1–4 kHz 电平和占比）、关键音效。
- `对照_12格.png`：从第 0 帧到最后一帧，均匀取 12 帧，标出秒数、帧号、拍号。
- `每拍第一帧.png`：每拍的第一帧，标出拍号、起始秒、【停】和这一拍的字幕。
- `帧差曲线.png`：上半张是整幅帧差，下半张放大到 0–2 看静止。图上标了【停】拍、0.5 秒以上的静止、突变（蓝色在边界上，红色不在）。
- `响度曲线.png`：瞬时（0.4 秒）和短时（3 秒）响度，下面一栏是每拍的 1–4 kHz 电平，红三角标出音效。没有音轨时，图上只有一行字。
- `diff.txt`：每 0.1 秒的帧差，格式和 `beats.py` 一样，可以直接拿来和参考片、旧版比。

## 查不了的，还得人看

- 字有没有出框、重叠：字号是从时间表读的，不从像素量。
- 静止的时候，要紧的东西动没动：脚本只看整幅画面。
- 突变是不是计划好的打点：脚本只列出来，要对着 `帧差曲线.png` 和 `每拍第一帧.png` 认。
- 手机上看不看得清、颜色的意思守没守住、变形是不是真变、AI 味：这些照剪辑认知和验收单，由人和评委看。
- 1–4 kHz 的门槛是我定的，还没在真手机上校过。第一次在成片上跑完，要拿手机外放听一遍，再调 `SFX_REL_OK`、`SFX_REL_WEAK`（脚本开头那几个常量）。
