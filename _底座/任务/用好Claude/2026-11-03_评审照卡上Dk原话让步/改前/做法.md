# 分角色验收：做法

通过条件见同文件夹 `通过条件.md`（下称「条件文件」），只给第二级读，不给评审。

一句话：程序先查；结构、读者、边界、依据、措辞五个角色各开一个新 agent，各只看一个方面、只报硬伤；总验收人另开一个新 agent，先不看角色报告、自己按读者的眼光判，再看五份报告给结论；第二级按条件文件判这一次算不算「没问题」，结论写进任务文件「验收结论」。评审一律新开、只读，只看脚本生成的材料文件夹，没看过制作过程。

## 适用范围和档位

- 所有交给 Dk 的稿都走这一套（包括经 Dk 转给主管、研发的稿）。同一件事不另跑别的审法。
- 档位只是这一套里的参数，不是另一套：
  - **标准档**：给主管、研发，或经 Dk 转给别人的稿。
  - **轻档**：只给 Dk 自己看、他看完拍板或跑命令的稿。
  - 两档都是五个角色加总验收人，判过的要求也一样（见条件文件）。唯一的差别：轻档在成品没改的前提下，第一次之后的各次只重开总验收人，复用同一版成品的五份角色报告。
  - 不按稿件大小减角色：考试只验证过五个角色这一种配置。
- 对齐卡「检查」一条只写档位：「分角色验收，标准档」或「分角色验收，轻档」。判过的要求不写进卡（评审会看到卡的摘录）。
- 任务自己特有的要求写进任务同名文件夹的 `验收条件.md`：一件任务一个文件，改了就整份覆盖，第一行写「最后更新：时间、谁、为什么」；交接记录只记一行「改了验收条件（时间、为什么）」，不抄内容。没有特有的，就不建，按条件文件判。

## 谁来派、用什么

| 评审 | 派法 | 模型 |
|---|---|---|
| 结构 | `subagent_type: Explore`（只读工具） | opus，思考强度 xhigh；派的时候显式传 `model: opus`、`effort: xhigh` |
| 读者、边界、依据、措辞 | `subagent_type: Explore`（只读工具） | sonnet |
| 总验收人 | `subagent_type: 总验收人`；这个 agent 装上之前（例如考试），用 `general-purpose`，提示词开头贴上候选 `总验收人.md` 的正文 | opus，思考强度 xhigh，不用 max；派的时候显式传 `model: opus`、`effort: xhigh` |

总验收人的模型照 Dk 原话：「总验收人用opus5.5 超高就行了 别max」（11/02 23:35，「总的主会话」，第一级已核实）。结构角色的模型照 Dk 原话：「结构评审角色需要确保按金字塔原理去评审。也要opus5.5模型，思考强度 xhigh」（11/03 10:1x，「用好 Claude｜主对话」，第一级建卡时照抄进 `任务/用好Claude/2026-11-03_结构角色按金字塔原理_改用opus.md`）。

评审不许进的目录：`~/claude/_底座/`（整个）、`~/.claude/projects/`（对话记录和记忆）、`~/.claude/skills/`、`~/.claude/backups/`。评审能读的只有材料文件夹，和出处清单里列的项目文件。

## 环节（第二级做）

### 1. 程序检查
- 跑 `python3 ~/claude/_底座/工具/机检.py <成品路径> --读者 主管|Dk --任务文件 <任务文件>`。结果写进「验收结论」本次标题下的第一行（`收样本.py` 靠这一行判有没有漏跑机检）。
- 卡上有字数、页数、禁用词要求的，一并用程序查。

### 2. 备材料
- 每次派评审前都重跑，不手抄、不复用上一次的材料：

  ```
  python3 ~/claude/_底座/工具/备评审材料.py <任务文件> <成品路径…> [--出处 <清单文件>] [--清单 1,2,5,10,17-21] [--本项目 <一句>] [--别的项目 <一句>] [--读者称呼 <称呼>] [--渲染]
  ```

  考试时把 <任务文件> 换成 Dk 退回那一刻的卡，加 `--试卷 <题号>`。
- 输出在 `/private/tmp/分角色验收/<任务名>/<MMDD_HHMM>/`，里面只有：
  - `成品/`：成品复制件；pptx 另出「页面文字」（不含备注）和「全文」（含备注）两个 txt；加 `--渲染` 再用 `看成品.py` 出页面图。已有的页面图可以当成品路径一起传进来。
  - `对齐卡摘录.md`：从现行卡生成，只取目标（需求原文）、内容、要做的、读者、可用时间、我们是谁与产品性质、必答、完成标准、这次不做、已替 Dk 定。不取预算、边界、检查、材料、参照、拿不准、先交、级别、交接、验收结论、交付。条目名里带日期的括号（谁几点改的）去掉。
  - `打分四档.md`：读者换成卡上的读者。
  - `验收清单原文.md`：默认全部条目；`--清单` 可以收窄（给主管的稿常用 1、2、5、10、17–21）。
  - `出处清单.md`：依据、边界两个角色可以读的文件，第二级写好用 `--出处` 传进来；不能列 `~/claude/_底座/` 下的文件（评审读不到，要读的先复制到别处）。
  - `总验收人说明.md`：复制本文件夹的同名文件。
  - `派活/`：6 份派活提示词——五个角色（模板在本文件夹 `角色/`）和总验收人第一步（模板在脚本里）。
- 屏蔽：脚本里写着两组屏蔽词，专防判过的要求漏给评审。硬屏蔽的：摘录里含它的整句剔掉，打印「已剔除 N 句」；剔不掉（在条目名里、剔完「目标」或「读者」空了）就不出材料，返回码 2。最后再查一遍除成品外的所有文件。只警告的：打印出来，第二级看一眼是不是在讲判过的要求。成品本身命中只警告。
- 剔掉的句子会列出来。剔掉的是 Dk 对成品的要求（不是判过的要求）时，交第一级把那句改写到不含屏蔽词，再重跑；不手改材料。

### 3. 五个角色（同时派，各开新 agent）
各只看一个方面，只报硬伤，最多 3 条，不提「可以加点什么」。

| 角色 | 看什么 |
|---|---|
| 结构 | 按《金字塔原理》判层次；每条判法和它防的误读只写在 `角色/结构.md`，这里不另列 |
| 读者 | 扮卡上的读者，只看卡上的可用时间（只看页面，不看备注），然后不再看成品，复述要点，打 1–10 分（按四档） |
| 边界 | 有没有混进别的项目、落地和流程的话（研发、开发量、上线、排期之类）、编出来的规则（卡上和设计里都没有、成品自己定下的） |
| 依据 | 每个数字、每个事实有没有出处（只查出处清单里的文件），撑不撑得住它所在那一块的结论，推断有没有标明 |
| 措辞 | 读者看不懂的说法（内部叫法、自造词、没解释的缩写）、重复的话、能删没删的字 |

- 提示词用材料文件夹 `派活/` 里脚本填好的那 5 份，原样发，不手改。每份都带这几条：先通读成品全文再判（读者角色是先按可用时间看、复述打分，再通读核对）；只读材料文件夹和出处清单里的文件；不打开上面那 4 个目录。
- 角色模板 `角色/*.md` 的占位符：`{成品清单}{读者一句}{可用时间}{本项目}{别的项目}{出处清单路径}{材料目录}`，由脚本填。`{本项目}{别的项目}` 不传就用默认写法，边界角色会粗一些；能写清的用 `--本项目`、`--别的项目` 传。

### 4. 总验收人（新开；先派它，再派角色）
- **第一步**：发 `派活/总验收人第一步.md`。它不看角色报告，按 `总验收人说明.md` 只用读者的眼光看成品。交回：说明里两件事各一句结果、分数（四档）、最大的问题（一句）。
- 五份角色报告收齐、而且总验收人第一步已经交回之后，第二级把五份合成一个文件，放在材料文件夹旁边（`/private/tmp/分角色验收/<任务名>/<MMDD_HHMM>_报告/五份.md`），不放进材料文件夹。
- **第二步**：用 SendMessage 续同一个总验收人，消息用本文件夹 `第二步.md`，把 `{角色报告路径}` 换成上面那个文件。交回：①结论，有问题或没问题；②和先判的比改不改判，为什么；③最大的问题，加要改的地方（最多 5 条，按严重程度排，每条写在哪、改成什么方向）；④分数。角色说的事实它要对照成品核过再采信；不同意的要写理由。
- `总验收人说明.md`（怎么判）以弹窗 11/02 试出来的那版为底本，加了思维导图、清单类成品那一段。它只在每周验收考试考过之后改。

### 5. 判、记
- 按条件文件和任务的 `验收条件.md` 判这一次算不算「没问题」、要不要从头数。
- 写进任务文件「## 验收结论」，只留最新一次，格式：
  - `### 第 N 次（MM/DD HH:MM，成品哪一版）——有问题／没问题，X 分`
  - `- 机检：通过／不通过（哪条）`
  - `- 总验收人先判：X 分；最大问题：…`
  - `- 角色：结构…｜读者 X 分…｜边界…｜依据…｜措辞…`（各写判定和最要紧的一条）
  - `- 总验收人终判：结论；改判理由；要改的（最多 5 条）`
  - `- 处理：每条改了／没改（没改要引 Dk 原话）`
  - 「Dk 验收」小节在 Dk 验完后填，格式照旧。
- 交接记录记一行：「MM/DD HH:MM 第二级验收跑完一轮：成品名、第几次、分数和结论、最大问题一句、周额度 N%」。
- 有问题时，改稿取舍按这个先后：Dk 原话 → 卡上完成标准 → 角色意见。验收意见只改写法；要改设计才能过的，不在验收里改，交第一级、由第一级交 Dk。
- 总验收人判「有问题」的新一版，返工前跑 `python3 ~/claude/_底座/工具/收样本.py --被拦 <任务文件> <成品路径> <意见出处>`（每天最多抽 3 份，脚本自己管）。

### 6. 通过以后
- 任务文件「## 交付」写三行：「成品：<完整路径>」「验收：分角色验收通过（MM/DD HH:MM）」「没做成的：…」。
- 状态改「待验收」，给第一级发「成品就绪：<任务文件路径>」。

## 校准

- **方法层面**：校准就是每周的验收考试。`总验收人说明.md`、`角色/` 下的模板改了就考，考过才生效。
- **任务层面**：这件任务有 Dk 原话针对过的退回稿（或者整批退回的理由也适用于这一份）时，开始数之前先拿它跑一轮，不告诉总验收人这是退回过的版本。总验收人要判「有问题」，而且最大问题要对上 Dk 的理由。
  - 对不上时，不为这件任务改通用说明。先看卡上是不是漏了 Dk 说过的要求：漏了，交第一级补进卡，重新生成材料，把这件任务所有退回稿一起重跑。
  - 还是对不上：照常开始数，「验收结论」里注明「校准没对上」，交付时告诉 Dk；这份退回稿交每周维护出题。
  - 不许拿单份退回稿一版一版地调说明，那等于照答案改判卷。

## 先交、分阶段给 Dk 看的稿

- 先交可以没过验收，但必须带上这一版的验收状态：回复末尾写「草稿，未交付」，并写明「这一版验过没有；验过的，最近一次是第几次、几分、最大问题是什么」。
- 交接记录记一行：「MM/DD HH:MM 先交：成品路径、哪一版、验收状态一句、草稿，未交付」。状态保持「进行中」，不改「待验收」。
- 机检必须跑（几乎不花额度）；跑不跑一轮分角色验收由第二级按需定，不强制。
- 转述先交的稿，一律说「草稿，没过验收」或「草稿，这一版没验」，不说「过了验收」。

## 用量

按弹窗 11/02 实测（四份成品各跑一轮约 1 个百分点周额度，即每份每轮约 0.25–0.35 个点，下面取 0.3；读数是整数，有 ±1 个点的舍入误差）：

| 档 | 每轮 | 一件中等稿从开跑到通过 |
|---|---|---|
| 标准档 | 约 0.3 个点（1 个总验收人＋5 个角色） | 评审约 1–2 个点，连同改稿约 2.5–3 个点 |
| 轻档 | 第一次约 0.3 个点；之后成品没改时只重开总验收人，每轮约 0.1 个点（推算，没单独量过） | 评审约 0.5–1 个点，连同改稿约 1.5 个点 |

上表是 11/03 结构角色改用 Opus 之前量的。改用后每轮会多一些：按 11/03 重考记录里结构角色和总验收人的 token 数、Opus 与结构角色原用模型的价差粗算，每轮约多 0.03–0.06 个点；周额度读数只到整数，单轮量不出来，没实测。

一件中等稿从开跑到通过大约 2–3 个百分点（评审约 1–2 个，其余是改稿）。卡上「预算」写了上限的，碰到上限就停，按条件文件交第一级。
