# 整理纠正：把纠正变成更少、更准的规则

目的：Dk 纠正过的问题不再犯，同时常驻规则不增多。判断标准只有一个：这次整理之后，验收官能不能在 Dk 之前拦下这类问题。

## 输入
- `/Users/decheng.huang/claude/_底座/纠正记录.md` 里「处理」列为空的行
- 现有规则：`~/.claude/CLAUDE.md`（常驻）、`/Users/decheng.huang/claude/_底座/验收清单.md`（验收官逐条查）、各技能、各项目规则（项目 `CLAUDE.md`、`先看这里.md`、弹窗 `规则与交接/`）
- 考题：`/Users/decheng.huang/claude/_底座/考试/题目.md`

## 步骤

1. **归类。** 把新纠正按「问题一句话」归成几类（同一个标准算一类，不按稿件分）。每类数一数出现几次、涉及几份稿件。
2. **逐类定去向**，按下表选一个，写进每行的「处理」列：

| 情况 | 去向 |
|---|---|
| 能用程序判定、每次都必须做（例：交付前没经独立审查、文件里出现内部代号） | 钩子或脚本（改 `~/.claude/hooks/`，先测再上） |
| 看成品就能判是否做到 | 验收清单加一条或改一条（写成能判是/否的问句，带「怎么查」） |
| 不常驻就会在多数任务里犯错，且看成品查不出（例：先读需求原文再动手） | 常驻规则（`~/.claude/CLAUDE.md`） |
| 某类稿件特有的做法 | 对应技能或项目类型卡 |
| 只对一个项目成立的业务口径、稿件写法、工具路径 | 项目规则（项目 `CLAUDE.md`、`先看这里.md` 或它的规则库） |
| 是事实（Dk 是谁、东西在哪、一次性决定），不是做法 | 记忆（只放事实，见 `_底座/规则体系说明.md`） |
| 只对这一次、这一份稿件成立 | 不立规则，只在「处理」写「个案」 |
| 已有规则写到了，但还是犯了 | 不加新文字。查为什么没生效：没加载（规则放错位置）？写得不可判定？验收官没查？改那一处 |

3. **守预算。** 常驻规则不超过 80 行，验收清单不超过 25 条。要加一条就先找一条能合并或删掉的；三个月没拦下过任何问题、也没被 Dk 提起的条目列为删除候选。同一件事只写在一处，别处写指向。
4. **防矫枉过正。** 新写或改写的规则，对照原话检查：有没有把一次的话变成「一律」？有没有从一个极端跳到另一个极端？有没有把检查项写成固定句式让人照抄？有就改回 Dk 原话针对的范围。不用「必须」「一律」「绝对」这类强调词。
5. **加考题。** 每类至少挑一份被退回的原稿加进 `考试/题目.md`：原稿路径（复制到 `考试/原稿/` 下，别指向会被覆盖的文件）、当时的需求原文和读者、可用时间、我们是谁与产品性质、Dk 原话、应拦下的问题（同一处、同一个问题）、只看原稿能否发现。
6. **考一次。** 用「验收官考试」技能跑新加的题和上次没拦下的题。改动后拦下率没升、或误拦了 Dk 判通过的稿，就撤回这次对清单的改动，换个写法再考。
7. **给 Dk 的只放五个数和一句结论，经第一级转交。** 要 Dk 补标准或范例的，只有属业务方向取舍时才走思考页「待拍板」，其余第二级自己定。
   - 五个数：第二级每周四派子代理按 `~/claude/用好Claude/先看这里.md`「每周四算的五个数」算出的结果，和目标比（方案第五节）。
   - 这周纠正合成了几类、每类去了哪里、删了哪些规则、考试结果、哪几类还拦不下：写进这次维护任务文件的「交付」，给第二级核对，不交 Dk。
   - 校准：汇总本周各任务文件「验收结论」里的「Dk 验收」（新加考题几道、合格样本几份、误拦几份），不另做判稿页。
   - 成品路径写进这次维护任务文件的「交付」，状态改「待验收」，由第一级转交 Dk；第二级和子代理不直接给 Dk 发消息。

## 不做
- 不为单次纠正新建记忆文件或规则文件。
- 不在多个文件里重复写同一条规则。
- 不改 Dk 的原话；改的是我们的执行规则。
