## 每周清单（括号里是思考页附表的项号）

0. **开工。** 建本周维护任务文件 `/Users/decheng.huang/claude/_底座/任务/用好Claude/<日期>_每周维护.md`（模板 `_底座/模板/对齐卡.md`，状态「进行中」），交接记录第一行记开工时的周额度读数。本圈的过程文件（改前副本、复核意见、试卷、给 Dk 的命令）放旁边同名文件夹。
   - 怎么验证通过：任务文件存在；交接记录第一行带额度读数。
1. **对账（2）。** 先跑 `python3 ~/claude/_底座/工具/收样本.py --只看`，再去掉 `--只看` 真跑：状态以「已完成」「退回」开头、还没登记的任务，原稿快照到 `考试/原稿/<日期>_<任务名>/`，`考试/样本登记.md` 加一行（验收官通过、Dk 也通过＝合格样本；验收官通过、Dk 退回＝漏拦，Dk 指出的每一处在第 3 项出一道题）。脚本最后输出两项：
   - 对账差＝判过的件数 − 登记件数。大于 0 就列出漏记的件补上；快照拿不到的写「原稿丢失」，那件不出题。
   - 漏跑机检＝10/31 起改成待验收、但「验收结论」第一行没有「机检」的件。逐件写进维护任务文件，第 7 项那页照报；攒几圈看次数，再定要不要提登记钩子。

2. **归类（5、6）。** 派一个思考子代理，读本周新纠正行、本周漏拦样本、上周的失败类型表。先给每行写一句笔记，再合并成类（同一个标准算一类，不按稿件分），从次数最多的类先处理：
   - 纠正记录每个新行填「类型」（失败类型表的类名）和「快照」（原稿快照路径；没有就写「原稿丢失」或「不涉及稿件」）。
   - 失败类型表：新类加一行，旧类改次数、对应纠正、最近日期；每类一句能判做到没有的标准句。
   - 已落地的类又重犯，状态改「没生效」，第 5 项查原因：放错地方、写得没法判、还是验收官没查；只改那一处，不加新文字。
   - 复核：再派一个不带上下文的只读子代理（便宜模型），随机抽 5 行重归一遍，随机种子写进维护任务文件；5 行里 2 行以上不同意就重归。
   - 怎么验证通过：本周新行的「类型」列没有空的；复核不同意的不超过 1 行；每类有次数和标准句。
3. **出题（7）。** 有原稿的类，每类至少挑一份被退回的原稿加进 `考试/题目.md`：原稿路径（复制到 `考试/原稿/` 下，别指向会被覆盖的文件）、当时的需求原文和读者、可用时间、我们是谁与产品性质、Dk 原话、应拦下的问题（同一处、同一个问题）、只看原稿能否发现。每题标组别（回归组、能力组、合格样本组、封存组，见技能「验收官考试」）；Dk 不同意过的验收官意见写进对应题的误报对照。
   - 怎么验证通过：新题都有原稿路径，并且文件存在；每题标了组别。
4. **考前测（8）。** 用技能「验收官考试」考本圈试卷：不超过 6 份稿，写在本圈文件夹的 `试卷.md`，考后用同一份。上周考后测之后没改过规则、模型版本也没变，就沿用上周的考后测，不重考。
   - 怎么验证通过：`考试/成绩单.md` 最上面有新一节，带日期、分母、题源、模型版本；沿用的写明沿用哪一节。
5. **定去向、改规则（9）。** 逐类按下表选一个去向，写进纠正记录每行的「处理」列，并填失败类型表的「去向」「落在哪」「最小测试题号」「状态」：

| 情况 | 去向 |
|---|---|
| 能用程序判定、每次都必须做（例：交付前没经独立审查、文件里出现内部代号） | 脚本（放 `_底座/工具/`，如 `机检.py` 的禁用词表，先测再用）；要登记成钩子的，写成命令交 Dk（见下「可改与不可改」） |
| 看成品就能判是否做到 | 验收清单加一条或改一条（写成能判是/否的问句，带「怎么查」） |
| 不常驻就会在多数任务里犯错，且看成品查不出（例：先读需求原文再动手） | 常驻规则（`~/.claude/CLAUDE.md`） |
| 某类稿件特有的做法 | 对应技能或项目类型卡 |
| 只对一个项目成立的业务口径、稿件写法、工具路径 | 项目规则（项目 `CLAUDE.md`、`先看这里.md` 或它的规则库） |
| 是事实（Dk 是谁、东西在哪、一次性决定），不是做法 | 记忆（只放事实，见 `_底座/规则体系说明.md`）；改法写成命令交 Dk |
| 只对这一次、这一份稿件成立 | 不立规则，只在「处理」写「个案」 |
| 已有规则写到了，但还是犯了 | 不加新文字。查为什么没生效：没加载（规则放错位置）？写得不可判定？验收官没查？改那一处 |

   - **四条门槛：**
     1. 只出现一次的类，只记、不立规则（状态「只记」）；同类第二次才立。
     2. 去向按 程序 > 验收清单 > 技能或类型卡 > 常驻规则 的顺序，挑能真正拦住它的最高一档。
     3. 新进验收清单的条目，每条配一道最小测试：一份故意违反它的小样本，验收官应该判不通过；题号写进清单那条和失败类型表。配不出测试的条目不进清单。
     4. 一进一出：全局规则不超过 80 行、8,000 字，验收清单不超过 25 条；满了先合并或删一条。用 `python3 ~/claude/_底座/工具/查规则预算.py` 判，最后一行不是「预算：过」就不算改完。改了全局规则，同步 `_底座/全局规则_快照.md`（脚本会比对两份）。
   - **删除：** 三个月没在答卷里拦下过任何问题、也没被 Dk 提起的条目列为删除候选，每圈至少审一次；拿「有这条、没这条」各考一次，分数一样就删；记了来源的直接删，没来源的观察一期。同一件事只写在一处，别处写指向。
   - **防矫枉过正：** 新写或改写的规则，对照原话检查：有没有把一次的话变成「一律」？有没有从一个极端跳到另一个极端？有没有把检查项写成固定句式让人照抄？有就改回 Dk 原话针对的范围。不用「必须」「一律」「绝对」这类强调词。
   - **只做条目级改动：** 增、改、并、删，不整篇重写。
   - **改前副本与撤回：** 动手前把要改的每个文件原样复制到本圈文件夹的 `改前/` 下，保留原路径结构（`~/.claude/` 下的放 `改前/home/.claude/…`，`_底座/` 下的放 `改前/_底座/…`）。撤回＝把改前副本拷回去，并在交接记录写一行。（`_底座/` 没进版本管理、`~/.claude/` 不在仓库里，所以不用 git 撤回。）
   - **可改与不可改：** 全局规则、技能「整理纠正」「验收官考试」、验收清单、模板、`_底座/` 下的文件，Claude 自己改；钩子、记忆、设置要改的，写成命令（改什么、为什么、怎么撤回）放本圈文件夹的 `给Dk的命令.md`，经主对话交 Dk。去向落在别处的（验收官说明、别的技能、项目类型卡和项目规则），失败类型表照填去向，状态写「待落地：<哪里>」，算已处理，在第 7 项那页列一张短表。
   - 怎么验证通过：纠正记录「处理」列以「待整理」开头的计数为 0，每行的处理是检查、规则、考题之一，或写明不立的理由；`查规则预算.py` 最后一行「预算：过」；改过的每个文件在 `改前/` 有副本。
6. **考后测（10）。** 同一份试卷再考一次。考后拦下率不低于考前、误拦不增加，就保留，考过就生效，不等 Dk 批准（Dk 10/30：「考过就生效没问题」）；否则撤回（改前副本拷回、交接记录写一行），换个写法再考。

## 用量和停机
- 每圈上限：本周额度的 5 个百分点（Dk 10/30：「上限 5 个百分点吧」）。开工读数写在交接记录第一行；对账、归类出题、两次考试、五个数各做完记一次读数。快超了先少考能力组的新题，回归组和合格样本组照考。
- 子代理同时不超过 4 个，每个约 40 步；复核和判分用便宜模型。
- 停机：清单全过，停在「待验收」；用量到上限，停在当前项、写交接；遇到业务方向取舍，状态改「待拍板」，待查清单空了即停。不新增清单项，不出 Dk 没要的产出。

## 不做
- 不为单次纠正新建记忆文件或规则文件。
- 不在多个文件里重复写同一条规则。
- 不改 Dk 的原话；改的是我们的执行规则。
