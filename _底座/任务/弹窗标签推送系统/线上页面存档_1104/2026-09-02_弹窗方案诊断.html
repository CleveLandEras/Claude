B

三个判断

01人群不互斥，权重在替你做人群决策

工作表2 第 2–14 行把付费状态、卡别、回流时长、破产状态四个层级并排放在一列，一个用户会同时命中好几行，表里没写弹哪个——于是权重决定了结果，而三套机制并存（工作表1 的 P0–P4 按内容性质、工作表2 的 P1–P5 按弹出顺序、外加权重字段），没人说得清哪套生效。

具体后果：工作表1 新增权重 B26=2、未首储 B57=1，所有新增用户按定义都是未首储，权重高的赢，所以未首储那块对新用户从不生效；而新增块 B27=1，新用户一次登入只看得到「登入签到礼」。改成互斥判定树后，权重可以整个删掉。

02卡别是终身累计，不适合单独当分层轴

升级看的是累计储值 / 累计押注（银卡 1,000、金卡 5,000、黑卡 100,000），记录的是历史投入总量。两年前充 10 万、之后一年没付费的用户今天仍是黑卡。用它单独切储值类弹窗，等于用历史行为决定今天推什么包。

标签体系里已有更合适的信号：当月储值额小于上月 70% / 50% / 25% 这组衰减型标签。

031800 秒间隔可能让「单次 ≤ 3 次」实际变成 1 次

工作表1 C18 单次 ≤ 3 次、C19 间隔 1800 秒。要凑满 3 次，用户得在线 60 分钟。所以还缺一个数：人均单次在线时长中位数。若低于 30 分钟，表的写法要变——不是每人群排 5–10 条，而是定「第 1 弹是什么」。

另外时机只有 5 个且全是位置 / 事件，「连败后弹安慰包」「金币低于 X 弹补充包」这类都做不了，只能改成离线圈人 + 下次进大厅命中。这让标签的最快更新频率成为必答题。

C

建议的结构

自上而下第一个命中就落桶，一个用户任一时刻只属于一个桶，跨桶不需仲裁。

  1. 破产中 独立通道，不占普通额度
  2. 新注册未完成引导 生涯一次
  3. 未首储 不分卡别——首储只能靠买首储礼包解除
  4. 回流 7 天 / 7–30 天 / >30 天
  5. 常规在线 再按下面两根轴切

第 3 步的位置要验一个数：未首储用户里高卡占比多少？如果不是长尾，它会挤掉高价值用户的高价包，顺序就得反过来。

轴一 · 卡别

决定给他看多贵的包。终身累计刻度，变化慢，适合当价格带。

轴二 · 当月储值 / 衰减

决定现在该不该给他看包。现成的价值下滑信号。
