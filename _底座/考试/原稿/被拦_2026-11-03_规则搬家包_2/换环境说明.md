# 换环境：旧电脑对比一致后再推送；新电脑克隆后跑 4 条命令装上，再重建会话编号和定时任务；云端会话第一次要用时再补全局规则

规则已经收成一套能整体搬走的包，放在仓库里。这台电脑照旧用 `~/.claude/` 那份，没有被改动。

| 情况 | 做哪几节 |
|---|---|
| 换电脑或换账号 | 旧电脑上做第 1 节；新电脑上做第 2、3 节 |
| 第一次用云端会话 | 第 4 节，现在不用动手 |
| 有空时 | 第 5 节，两样都可选，不做也能搬 |

## 搬家包不会让规则多一份生效，也没有改动这台电脑

**一、除 report-format 外，每样规则只有 `~/.claude/` 一份在生效；规则包不会被自动加载（按文档推断，会话里对照过）**
- 这台电脑（搬家时就是旧电脑）生效的只有 `~/.claude/` 那份。规则包放在 `~/claude/_底座/搬家/规则包/`，只用来存档和装到新电脑上。
- 规则包不会被自动加载，是按官方文档推断的：文档列出的自动加载位置，只有叫 `.claude` 的文件夹、叫 `CLAUDE.md`（或 `CLAUDE.local.md`、`AGENTS.md`）的文件和插件；文档没有明说别处不加载。规则包下这类名字有 0 个（第二级已核）。出处：[skills](https://code.claude.com/docs/en/skills)、[sub-agents](https://code.claude.com/docs/en/sub-agents)、[memory](https://code.claude.com/docs/en/memory)。
- 会话里对照过：读规则包里的技能文件，没有触发任何加载；对照组读弹窗项目 `.claude/skills/` 下的文件，马上自动载入了 `弹窗标签推送系统/CLAUDE.md`。所以读文件会不会触发加载，这种测法看得出来。
- 这种对照看不出一件事：技能会不会不出任何提示、直接加进技能列表。子代理按文档只在启动时载入，不受读文件影响。
- 命令行实测没跑成，因为桌面应用里的 `claude -p` 报「未登录」。这项实测可选，不跑也能搬（第 5 节）。
- report-format 是例外：弹窗项目里还有一份副本，归弹窗项目管；claude.ai 上还有一份旧版，见第 5 节。
- 新电脑上，装上脚本把规则包拷进 `~/.claude/`，自检逐项核对内容和规则包一致。旧电脑搬完就不用了，两边不用同步。

**二、规则包里的路径已不绑用户名，这台电脑照常运转**
- 规则包里的路径已经改成 `~`、`$HOME`，旧电脑家目录的路径有 0 处（第二级已核）。
- `_底座/` 在这台电脑上不改。到新电脑装上时，装上脚本照 `_底座/搬家/路径替换.json` 改 8 个文件（4 个工具、README、对话定位、项目登记、考试题目）。纠正记录、考试答卷这些历史记录不改。
- 这台电脑照常运转的依据：
  - 导出的预演、执行、对比三步，每步前后各核对一次本机 270 个规则和底座文件，一个都没变（执行子代理自称）；
  - 对比报「规则包和本机一致（12 项）」，本机 `~/.claude/` 的规则文件没有被改过（第二级已核）。

## 1. 旧电脑（搬之前）：对比一致、推上 GitHub、拷走不进库的文件夹

| 步 | 做什么 | 怎么算成功 |
|---|---|---|
| 1 | `bash ~/claude/_底座/搬家/导出.sh --对比` | 末行是「规则包和本机一致（N 项）」 |
| 2 | 不一致就跑 `bash ~/claude/_底座/搬家/导出.sh --执行`，再跑一次第 1 步 | 末行「已写：…」，再对比时一致 |
| 3 | 请 Claude 提交并给推送总结。你看完说「通过」，它才推 | GitHub 网页上 main 的最新一条是这次的提交 |
| 4 | 想带走记忆的，照第 3 节「记忆」打包 | 桌面上有 `记忆.tgz` |
| 5 | 拷走不进库的文件夹（清单在表下） | 清单里的都拷出来了 |

- 第 5 步要拷的，都不在仓库里：
  - `~/claude/_底座/任务/`；
  - 仓库根目录下的 `商城/`、`用好Claude/`、`团队工作模式/`、`竞品跟踪分析/`、`抖音总结/`、`企业微信自动回复/` 等；
  - 仓库外的 `~/Documents/dy`、`~/Documents/消息助手` 等。
- 第 1 步报「快照：和 ~/.claude/CLAUDE.md 不一致」或「路径替换.json 对不上」时，先不要推，把输出交给 Claude。前一种要照技能「整理纠正」把 `_底座/全局规则_快照.md` 同步成和 `~/.claude/CLAUDE.md` 一样；后一种要在旧电脑上重新生成 `_底座/搬家/路径替换.json`。
- 平时也要跑：每次推送前，Claude 会先跑一次对比；每周四整理纠正之后，可以手动跑一次对比。

## 2. 新电脑或新账号：登录 GitHub 后克隆到 `~/claude`，跑 4 条命令装上，自检九项全过

| 步 | 做什么 | 怎么算成功 |
|---|---|---|
| 1 | 装 Claude Code 并登录。新 Mac 第一次跑 `git` 时会提示安装命令行开发者工具，照提示装上（脚本用的 `/usr/bin/python3` 也来自它） | `git --version` 能打出版本号 |
| 2 | 先登录 GitHub，再 `git clone https://github.com/Clarelive/Claude.git ~/claude`（要点在表下） | `~/claude/_底座/搬家/装上.sh` 存在 |
| 3 | 命令 1：`bash ~/claude/_底座/搬家/装上.sh`（预演，不改文件） | 有一行以「检查：全过。」开头（现在是要拷 12 项、改 8 个文件） |
| 4 | 命令 2：`bash ~/claude/_底座/搬家/装上.sh --执行` | 末段是「已装上：…逐项核过」。把它打印的撤回命令留着 |
| 5 | 命令 3：跑第 4 步打印的 settings 命令。它先备份 `~/.claude/settings.json`，只合并钩子那一段 | 打印出改前改后的差异 |
| 6 | 命令 4：`bash ~/claude/_底座/搬家/装上.sh --自检` | 末行「自检：九项全过」 |
| 7 | 在 `~/claude` 开一个对话，请 Claude 提交 `_底座/` 里 8 个文件的路径改动。要推送的话，照旧先看总结、说「通过」 | `git status` 里 `_底座/` 下没有改动 |
| 8 | 把从旧电脑拷来的文件夹放回原位 | 路径和旧电脑一样，各项目的入口文件（如 `~/claude/商城/先看这里.md`）都在 |

- 第 2 步：仓库要登录才能克隆，而且必须克隆到 `~/claude`：
  - 仓库匿名读不了，克隆时会问用户名和密码。用户名填 `Clarelive`；密码处填 GitHub 的个人访问令牌，不填账户密码。令牌在 GitHub 网页上生成，做法见 [GitHub 文档](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)。
  - 必须克隆到 `~/claude`。规则和钩子都按这个位置找文件，放在别处，装上脚本会拒绝装上。
- 碰到下面几种情况就停下，不要往下跑：
  - 预演报「检查：有 N 处不过」：把输出交给 Claude。
  - 报「本机保护…拒绝 --执行」：说明你是在旧电脑上跑的。
  - 报「克隆到 ~/claude」：仓库放错了位置。
- 自检有不过的：先跑第 4 步打印的撤回命令，再把自检输出交给 Claude。

## 3. 新电脑装好后：会话编号、定时任务、记忆搬不走，照下面重建

**会话编号：照项目登记逐个重开主对话和分发，让它们登记新编号**
1. 照 `~/claude/_底座/项目登记.md` 里的名字，逐个开各项目的主对话（如「弹窗标签推送｜主对话」）。怎么算成功：对话名和项目登记里的一致。
2. 第一轮钩子会提示「本对话还没登记定位」。让它把 `~/claude/_底座/对话定位.md` 里自己那一条的桌面编号和会话 ID 改成新的。怎么算成功：下一轮不再提示，附上的是这个对话的定位。
3. 对主对话说「开分发」，重开分发对话，分发也同样登记。
4. 让分发跑一次 `~/claude/_底座/工具/做项目总览.py`。怎么算成功：`~/claude/_底座/项目总览.md` 里列的是新对话。

**定时任务：每周整理纠正由新的「用好 Claude｜分发」重建，夜间定时由各分发自己重建**
- 每周四 09:07 的整理纠正：新的「用好 Claude｜分发」照技能「整理纠正」第 8 步重建。怎么算成功：定时列表里有一条，下次触发在周四 09:07–09:37 之间。这个区间照技能「整理纠正」第 8 步的验证标准写：定时工具会固定错开最多 30 分钟。
- 各分发的夜间定时：由各分发自己照 `~/claude/_底座/夜间推进.md` 重建。
- 桌面应用里那 9 个 `popup-tag-push-*` 定时任务是弹窗的旧流程，不搬。

**记忆（可选）：有内容的记忆文件夹都打包带走，到新电脑按新家目录改名放回**
- 旧电脑上打包。命令最后打出的数字是打包了几个文件夹（11/03 盘点时，有内容的记忆文件夹是 5 个）：
  ```
  cd ~/.claude/projects && find . -mindepth 2 -maxdepth 2 -name memory -type d ! -empty | tar czf ~/Desktop/记忆.tgz -T - && tar tzf ~/Desktop/记忆.tgz | grep -c '/memory/$'
  ```
- 新电脑上，先把 `记忆.tgz` 放到桌面，再跑下面这条。文件夹名开头的旧家目录会换成新家目录（规则是路径里字母、数字以外的字符都换成 `-`）；不以旧家目录开头的，照原名放：
  ```
  D=$(mktemp -d) && tar xzf ~/Desktop/记忆.tgz -C "$D" && OLD=-Users-decheng-huang && NEW=$(printf '%s' "$HOME" | sed 's/[^A-Za-z0-9]/-/g') && cd "$D" && for d in ./*/; do n=${d#./}; n=${n%/}; case "$n" in "$OLD"*) t="$NEW${n#"$OLD"}" ;; *) t="$n" ;; esac; mkdir -p "$HOME/.claude/projects/$t" && cp -R "./$n/memory" "$HOME/.claude/projects/$t/"; done
  ```
- 怎么算成功：`ls -d ~/.claude/projects/*/memory` 列出的文件夹里，有打包时的那几个，名字开头换成了新家目录。

## 4. 云端会话：拿不到用户级规则，现在不用动手；第一次要用时贴一段 setup script 补全局规则（只按文档写，没有实测）

- **现在不用动手，第一次要用云端会话时再做**：告诉「用好 Claude｜主对话」。它按下面的做法把 setup script 写好交给你，你贴进 claude.ai 的环境设置；再开一个会话实测一次，把结果补进这一节。前提是仓库已经推上 GitHub（第 1 节第 3 步），云端会话从 GitHub 克隆。
- **能拿到：仓库里提交过的文件，和 claude.ai 上开启的技能**。仓库根目录的 `CLAUDE.md`（工作区索引）会读到，`_底座/` 和规则包能当普通文件读。出处：[What carries over from your setup](https://code.claude.com/docs/en/cloud-environments#what-carries-over-from-your-setup)。
- **拿不到：`~/.claude/` 下的全局规则、技能、子代理，和 `~/.claude/settings.json` 里登记的钩子**。所以钩子做的事，比如每轮附上全局规则和本对话的定位、交付闸门，在云端都不会跑。出处同上；另见 [Setup scripts vs. SessionStart hooks](https://code.claude.com/docs/en/cloud-environments#setup-scripts-vs-sessionstart-hooks)，原文是「User-level settings stay on your machine」。
- **全局规则可以用 setup script 补，改了规则要重贴**：
  1. 在 claude.ai/code 新建会话的页面，打开环境选择器，编辑环境，加一段 setup script，把 `_底座/全局规则_快照.md` 的全文写进 `~/.claude/CLAUDE.md`（文档里的例子就是这么写的）。贴全文、不从仓库里拷，是因为文档没写脚本跑的时候仓库克隆在哪。
  2. 怎么算成功：在云端会话里跑 `/context`，Memory files 下出现 `/root/.claude/CLAUDE.md`。出处：[Add personal preferences without committing to the repo](https://code.claude.com/docs/en/cloud-environments#add-personal-preferences-without-committing-to-the-repo)。
  3. 以后改了全局规则，要把脚本里的全文换成新的，再存一次。脚本里是贴进去的全文，不会跟着仓库变；改了脚本，云端才会马上重跑。
- **这样补，这台电脑不会多一份**：
  - setup script 存在 claude.ai 的环境设置里，不在仓库里，这台电脑看不到。
  - 文档建议把技能提交到仓库的 `.claude/` 下，这里不这么做。放在那里，在 `~/claude` 开的对话会把它当项目级规则再加载一份；子代理同名时项目级优先，仓库那份会盖过本机那份。出处：[sub-agents](https://code.claude.com/docs/en/sub-agents)。
- **setup script 的三点限制（文档已写明）**：
  - 在 Claude Code 启动前跑，用 root 身份、Ubuntu 24.04；退出码不是 0，会话就起不来。
  - 跑完以后环境会缓存起来，之后的会话直接用缓存。只有改了脚本，或者约 7 天后缓存到期，才会重跑。
  - 能用这个环境的人都能读到 setup script。
  - 出处：[Script requirements](https://code.claude.com/docs/en/cloud-environments#script-requirements)、[Environment caching](https://code.claude.com/docs/en/cloud-environments#environment-caching)。
- **技能、子代理、钩子能不能在云端补上，还没确认**：
  - setup script 写进 `/root/.claude/` 下 skills、agents、settings.json 的东西会不会被读，文档没写，要等实测。
  - setup script 跑的时候仓库克隆好了没有、克隆在哪个目录，文档没写。按 `~/claude/…` 找文件的工具在云端能不能用，也跟着未确认。
  - 就算钩子补上了，交付闸门（每轮结束时检查交付物的钩子）用来认路径的正则只认 macOS 的 `/Users/…`。云端是 Linux（`/root`、`/home/…`），它认不出回复里的文件路径，也就不会拦。

## 5. 可选，不做也能搬：删掉 claude.ai 上的旧版 report-format；在旧电脑上补一次「不多加载」的命令行实测

**claude.ai 上的旧版 report-format：只有你能删**
- 它以 `anthropic-skills:report-format` 的名字出现，只有你能在 claude.ai 的技能设置里删掉。
- 不删也不影响装上：旧版只能用全名调，`/report-format` 调的是本机那份。

**「不多加载」的命令行实测：只能在旧电脑上跑**
- 在你自己登录过的终端里跑，不要在桌面应用的对话里跑：`bash ~/claude/_底座/任务/用好Claude/2026-11-03_规则搬家包/不多加载实测.sh`
- 脚本只读，不改任何规则文件，结果写进一个临时文件夹。末行「结论：过」就算过；末行是「不过或要人看」的，把末行和结果文件夹交给 Claude。
- 只能在旧电脑上跑：这个脚本放在 `_底座/任务/` 下，这个文件夹不进库，新电脑上没有。
