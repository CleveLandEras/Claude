# 换环境：旧电脑先提交改动、再推送，把没进库的打包带走；新电脑克隆后跑 4 条命令装上，再重建会话编号和定时任务；云端会话第一次要用时再补全局规则

规则已经收成规则包，放在仓库的 `_底座/搬家/规则包/`；导出、装上两个搬家脚本（`导出.sh`、`装上.sh`）放在它外面的 `_底座/搬家/`。旧电脑照旧用 `~/.claude/` 那份，没有被改动。

| 情况 | 做哪几节 |
|---|---|
| 换电脑或换账号 | 旧电脑上做第 1 节；新电脑上做第 2、3 节 |
| 第一次用云端会话 | 第 4 节，现在不用动手 |
| 有空时 | 第 5 节，可选，不做也能搬 |

**一共约 1 小时 10 分钟，另加拷文件的时间：旧电脑约 10 分钟，新电脑装上约 15 分钟，7 个项目和 2 个跨项目对话各重建约 5 分钟**

没实测，是按下面每节的命令条数和手动步数估计的。7 个项目是项目登记里登记的：`~/claude` 下 5 个，仓库外 2 个（`~/Documents/dy`、`~/Documents/消息助手`）。2 个跨项目对话是项目登记里的「总的主会话」「产出汇报」，工作文件夹都是 `~/claude`。
- 旧电脑（第 1 节）：必跑 3 条命令（第 1、3、6 步），对比不一致时再加 2 条（第 4 步），可选 2 条（第 7、9 步）；手动 3 步（第 2 步在各项目的主对话说「提交」，第 5 步看推送总结说「通过」，第 8 步拷进移动硬盘或网盘）。估计约 10 分钟，另加拷文件的时间。
- 新电脑装上（第 2 节）：6 条命令（克隆 1 条、装上 4 条、解开压缩包 1 条）；手动 4 步（装 Claude Code、生成 GitHub 令牌、请 Claude 提交、把 `搬家` 文件夹拷到桌面）。估计约 15 分钟，另加拷回的时间。
- 装好后重建（第 3 节）：7 个项目，每个重开主对话，原来有分发的再开分发，各让它登记一次；2 个跨项目对话各重开一次、登记一次；记忆 1 条命令（可选）。跨项目对话照项目的估法算，每个约 5 分钟；9 个约 45 分钟。

## 规则包不会让规则多一份生效，旧电脑也没有被改动

**一、生效的只有 `~/.claude/` 那一份；例外是 report-format 和 `_底座/任务/` 下两处历史备份**
- 旧电脑上生效的只有 `~/.claude/` 那份。规则包放在 `~/claude/_底座/搬家/规则包/`，只用来存档和装到新电脑上。
- 规则包不会被自动加载，是按官方文档推断的：文档列出的自动加载位置，只有叫 `.claude` 的文件夹、叫 `CLAUDE.md`（或 `CLAUDE.local.md`、`AGENTS.md`）的文件和插件；文档没有明说别处不加载。`_底座/搬家/` 下（规则包和搬家脚本都在内）这类名字有 0 个，自检第⑨项查的就是这个。出处：[skills](https://code.claude.com/docs/en/skills)、[sub-agents](https://code.claude.com/docs/en/sub-agents)、[memory](https://code.claude.com/docs/en/memory)。
- 读规则包里的文件时，没有触发加载。还没确认的只有一点：技能会不会不出任何提示、直接加进技能列表。可以在旧电脑上补一次实测（第 1 节第 9 步，可选，不做也能搬）。
- 例外一：report-format 另有两份。弹窗项目里一份副本，归弹窗项目管；claude.ai 上一份旧版，见第 5 节。
- 例外二：`_底座/任务/用好Claude/` 下两处历史备份里有旧版的 `CLAUDE.md`（全局规则）和技能，在 10/29「自循环闭环」任务的 `第一圈/改前/home/.claude/`，和 11/02「分角色验收上场」任务的 `候选/home/dot-claude/CLAUDE.md`。它们只在读到这两个文件夹里的文件时才会加载；`_底座/任务/` 拷到新电脑后也一样。
  - 可选，不在这次范围，要做就另开一件：把第一处的 `.claude/` 改名成 `dot-claude/`，两处的 `CLAUDE.md` 都改名成 `CLAUDE_备份.md`。改名是因为 Claude 按 `.claude`、`CLAUDE.md` 这类名字自动加载，换了名就不会再被当成规则。不改的话，以后每次读到这两个文件夹里的文件，都会多载入一份旧版规则。
- 新电脑上，装上脚本把规则包拷进 `~/.claude/`，自检第④项逐项核对 `~/.claude/` 和规则包内容一致。旧电脑搬完就不用了，两边不用同步。

**二、规则包里的路径已不绑用户名，旧电脑照常运转**
- 规则包里的路径已经改成 `~`、`$HOME`，旧电脑家目录的路径有 0 处。
- `_底座/` 在旧电脑上不改。到新电脑装上时，装上脚本照 `_底座/搬家/路径替换.json` 改 8 个文件（4 个工具、README、对话定位、项目登记、考试题目）。纠正记录、考试答卷这些历史记录不改。
- 旧电脑照常运转：导出前后，旧电脑上 270 个规则和底座文件一个都没变；对比报「规则包和本机一致（12 项）」。

## 1. 旧电脑（搬之前）：先列出并提交没提交的改动，对比一致后推上 GitHub，再把没进库的打包带走；打包记忆、补实测两步可选

| 步 | 做什么 | 怎么算成功 |
|---|---|---|
| 1 | `git -C ~/claude status --porcelain --ignored`：列出没进库和改了没提交的内容（怎么看在表下） | 打出列表，没有报错 |
| 2 | 改了没提交的，你到那个项目的主对话说一句「提交」，由那个项目的 Claude 提交（找哪个对话在表下） | 再跑一次第 1 步，`!!`、`??` 以外的行只剩来不及提交的 |
| 3 | `bash ~/claude/_底座/搬家/导出.sh --对比` | 末行是「规则包和本机一致（N 项）」 |
| 4 | 不一致就跑 `bash ~/claude/_底座/搬家/导出.sh --执行`，再跑一次第 3 步 | 末行「已写：…」，再对比时一致 |
| 5 | 在「用好 Claude｜主对话」里请 Claude 提交第 4 步导出的改动（没跑第 4 步就没有），给你推送总结。你看完说「通过」，它才推 | GitHub 网页上 main 的最新一条是这次的提交 |
| 6 | 跑表下的打包命令：没进库的、还没提交的，和两个仓库外的项目文件夹，打成压缩包放进桌面的 `搬家` 文件夹 | 命令末尾列出 `claude_没进库.tgz`、`Documents_两个项目.tgz`，大小都不是 0 |
| 7 | 可选：想带走记忆的，跑表下的记忆打包命令 | `搬家` 文件夹里多了 `记忆.tgz` |
| 8 | 把桌面的 `搬家` 文件夹整个拷进移动硬盘或网盘 | 移动硬盘或网盘里的 `搬家` 文件夹有第 6、7 步的压缩包 |
| 9 | 可选：补一次「不多加载」实测（命令在表下） | 输出里有「结论：过」 |

- 第 1 步，怎么看列出的内容。每行一处文件或文件夹，路径从 `~/claude` 算起：
  - `!!` 开头：不进库的，第 6 步打包带走。
  - `??` 开头：还没加进库的，第 6 步打包带走。
  - 其余开头（如 ` M`、`M `、` D`）：进了库、改了还没提交的，第 2 步提交。
  - 行数参考（11/03 实查）：`!!` 647 行，`??` 47 行，其余 28 行。
  - 参考（11/03 用 `ls -d ~/claude/*/` 和这条命令查的）：整个不在库里的文件夹是 `商城/`、`用好Claude/`、`团队工作模式/`、`竞品跟踪分析/`、`抖音总结/`、`企业微信自动回复/`，根目录下还有 `.claude/` 和 12 个散放的文件；`_底座/`、`弹窗标签推送系统/` 在库里，里面有一部分挡在库外。以搬的那天命令列出的为准。
  - 仓库外的项目文件夹只有 `~/Documents/dy`、`~/Documents/消息助手` 两个，命令列不出来，第 6 步一起打包。这两个是 11/03 从 `_底座/对话定位.md`、`_底座/项目登记.md` 里查出来的。
- 第 2 步，找哪个对话：看路径第一段是哪个项目的文件夹，就到那个项目的主对话，例如 `弹窗标签推送系统/…` 到「弹窗标签推送系统｜主对话」；`_底座/…` 和根目录的文件到「用好 Claude｜主对话」。来不及提交的不用等，第 6 步会把它们一起打包带走。
- 第 3 步报「快照：和 ~/.claude/CLAUDE.md 不一致」或「路径替换.json 对不上」时，先不要推，把输出交给 Claude。前一种要照技能「整理纠正」把 `_底座/全局规则_快照.md` 同步成和 `~/.claude/CLAUDE.md` 一样；后一种要在旧电脑上重新生成 `_底座/搬家/路径替换.json`。
- 平时也要跑：每次推送前，Claude 会先跑一次对比；每周四整理纠正之后，可以手动跑一次对比。
- 第 6 步，打包。命令把 `!!`、`??` 开头的，和还没提交的（` M`、`M `、`MM`、`A `、`AM`），按 `~/claude` 下原来的相对路径打成 `claude_没进库.tgz`；两个仓库外的项目文件夹按 `~/Documents` 下的相对路径打成 `Documents_两个项目.tgz`。删掉的（` D`）不用带。中途报错停下的，把输出交给 Claude：
  ```
  mkdir -p ~/Desktop/搬家 && git -C ~/claude status --porcelain -z --ignored | perl -0ne 'print substr($_,3) if /^(!!|\?\?|[ MA][ M]) /' | tar -C ~/claude --null -T - -czf ~/Desktop/搬家/claude_没进库.tgz && tar -C ~/Documents -czf ~/Desktop/搬家/Documents_两个项目.tgz dy 消息助手 && ls -lh ~/Desktop/搬家
  ```
- 第 7 步，打包记忆。命令最后打出的数字是打包了几个文件夹（11/03 盘点时，有内容的记忆文件夹是 5 个）：
  ```
  cd ~/.claude/projects && find . -mindepth 2 -maxdepth 2 -name memory -type d ! -empty | tar czf ~/Desktop/搬家/记忆.tgz -T - && tar tzf ~/Desktop/搬家/记忆.tgz | grep -c '/memory/$'
  ```
- 第 9 步，「不多加载」实测。在你自己登录过的终端里跑，不在桌面应用的对话里跑（桌面应用里的 `claude -p` 报「未登录」）：
  ```
  bash ~/claude/_底座/任务/用好Claude/2026-11-03_规则搬家包/不多加载实测.sh
  ```
  脚本只读，不改任何规则文件，结果写进一个临时文件夹。输出里是「结论：不过或要人看」的，把这一行和结果文件夹交给 Claude。

## 2. 新电脑或新账号：登录 GitHub 后克隆到 `~/claude`，跑 4 条命令装上，自检九项全过，再解开带来的压缩包

| 步 | 做什么 | 怎么算成功 |
|---|---|---|
| 1 | 装 Claude Code 并登录。新 Mac 第一次跑 `git` 时会提示安装命令行开发者工具，照提示装上（脚本用的 `/usr/bin/python3` 也来自它） | `git --version` 能打出版本号 |
| 2 | `git clone https://github.com/Clarelive/Claude.git ~/claude`（登录做法在表下） | `~/claude/_底座/搬家/装上.sh` 存在 |
| 3 | `bash ~/claude/_底座/搬家/装上.sh`（预演，不改文件） | 有一行以「检查：全过。」开头（现在是要拷规则包里的 12 项、改 `_底座/` 里 8 个文件） |
| 4 | `bash ~/claude/_底座/搬家/装上.sh --执行` | 末段是「已装上：…逐项核过」。它前面打印的撤回命令和 settings 命令都留着 |
| 5 | 跑第 4 步打印的 settings 命令（没打印就跳过）。它先备份 `~/.claude/settings.json`，只合并钩子那一段 | 打印出改前改后的差异 |
| 6 | `bash ~/claude/_底座/搬家/装上.sh --自检` | 末行「自检：九项全过」（九项是哪些在表下） |
| 7 | 在 `~/claude` 开一个对话，请 Claude 提交 `_底座/` 里 8 个文件的路径改动。要推送的话，照旧先看总结、说「通过」 | `git status` 里 `_底座/` 下没有改动 |
| 8 | 把移动硬盘或网盘里的 `搬家` 文件夹拷到新电脑桌面，再跑表下的解包命令 | 旧电脑上第 1 节第 1 步列出的路径，新电脑 `~/claude` 下都在；`~/Documents/dy`、`~/Documents/消息助手` 都在 |

- 第 2 步：仓库要登录才能克隆，而且必须克隆到 `~/claude`：
  - 仓库匿名读不了，克隆时会问用户名和密码。用能读这个仓库的 GitHub 账号登录；密码处填 GitHub 的个人访问令牌，不填账户密码。令牌在 GitHub 网页上生成，参考 [GitHub 文档](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)。
  - 必须克隆到 `~/claude`。规则和钩子都按这个位置找文件，放在别处，装上脚本会拒绝装上。
- 第 3 步的「12 项」是规则包里的 12 个文件或文件夹：技能 6 个、子代理 2 个、钩子 3 个、钩子登记 1 个。
- 碰到下面几种情况就停下，不要往下跑：
  - 报「检查：有 N 处不过」：把输出交给 Claude。
  - 报「本机保护…拒绝 --执行」：说明你是在旧电脑上跑的。
  - 报「克隆到 ~/claude」：仓库放错了位置。
  - 第 4 步报「核对不过：…按上面的撤回命令撤回」：照它打印的撤回命令撤回，再把输出交给 Claude。
- 第 6 步自检的九项：①每轮附上全局规则和本对话定位，②交付闸门能拦，③技能、子代理都在，④内容和规则包一致，⑤settings.json 登记了钩子，⑥`机检.py --自测`，⑦`查规则预算.py`，⑧不绑用户名，⑨不多加载。有不过的：把自检输出交给 Claude。
- 第 8 步，解包命令：
  ```
  tar -xzf ~/Desktop/搬家/claude_没进库.tgz -C ~/claude && tar -xzf ~/Desktop/搬家/Documents_两个项目.tgz -C ~/Documents
  ```
  只解开这两个压缩包，不要拿旧电脑的整个 `_底座/`、`弹窗标签推送系统/` 盖过去。整个盖过去，会盖掉第 4 步改好的路径和 GitHub 上更新的文件。

## 3. 新电脑装好后：会话编号、定时任务照下面重建；记忆解开旧电脑打的压缩包（可选）

**会话编号：照项目登记逐个重开各项目的主对话、分发和 2 个跨项目对话，让它们登记新编号**
1. 照 `~/claude/_底座/项目登记.md` 里的名字，逐个开各项目的主对话（如「用好 Claude｜主对话」），再在 `~/claude` 开「总的主会话」「产出汇报」两个跨项目对话。怎么算成功：对话名和项目登记里的一致。
2. 第一轮钩子会提示「本对话还没登记定位」。让它把 `~/claude/_底座/对话定位.md` 里自己那一条的桌面编号和会话 ID 改成新的。怎么算成功：下一轮不再提示，附上的是这个对话的定位。
3. 原来有分发的项目（项目登记里写了分发的），对主对话说「开分发」，重开分发对话，分发也同样登记。
4. 让分发跑一次 `~/claude/_底座/工具/做项目总览.py`。怎么算成功：`~/claude/_底座/项目总览.md` 里列的是新对话。
5. 对话定位里另有几个对话不在项目登记里：「项目推进监督与规划」是你自己开、自己看的，要接着用就自己重开，同样让它登记，不算在上面的时长里；「新版功能框架」「屏幕那头 执行会话（旧，10/29）」「《金字塔原理》第一章内容」「粘贴即脑图（工具）」是任务、旁支或工具对话，不重建。

**定时任务：每周整理纠正由新的「用好 Claude｜分发」重建，夜间定时由各分发自己重建**
- 每周四 09:07 的整理纠正：新的「用好 Claude｜分发」照技能「整理纠正」第 8 步重建。怎么算成功：定时列表里有一条，下次触发在周四 09:07–09:37 之间。这个区间照技能「整理纠正」第 8 步的验证标准写：定时工具会固定错开最多 30 分钟。
- 各分发的夜间定时：由各分发自己照 `~/claude/_底座/夜间推进.md` 重建。
- 桌面应用里那 9 个 `popup-tag-push-*` 定时任务是弹窗的旧流程，不搬。

**记忆（可选）：解开第 1 节第 7 步打的压缩包，文件夹名换成新家目录**
- `记忆.tgz` 在第 2 节第 8 步拷到桌面的 `搬家` 文件夹里。跑下面这条，文件夹名开头的旧家目录会换成新家目录（规则是路径里字母、数字以外的字符都换成 `-`）；不以旧家目录开头的，照原名放：
  ```
  D=$(mktemp -d) && tar xzf ~/Desktop/搬家/记忆.tgz -C "$D" && OLD=-Users-decheng-huang && NEW=$(printf '%s' "$HOME" | sed 's/[^A-Za-z0-9]/-/g') && cd "$D" && for d in ./*/; do n=${d#./}; n=${n%/}; case "$n" in "$OLD"*) t="$NEW${n#"$OLD"}" ;; *) t="$n" ;; esac; mkdir -p "$HOME/.claude/projects/$t" && cp -R "./$n/memory" "$HOME/.claude/projects/$t/"; done
  ```
- 怎么算成功：`ls -d ~/.claude/projects/*/memory` 列出的文件夹里，有打包时的那几个，名字开头换成了新家目录。

## 4. 云端会话：拿不到用户级规则，现在不用动手；第一次要用时贴一段 setup script 补全局规则（只按文档写，没有实测）

- **现在不用动手，第一次要用云端会话时再做**：告诉「用好 Claude｜主对话」。它按下面的做法把 setup script 写好交给你，你贴进 claude.ai 的环境设置；再开一个会话实测一次，把结果补进这一节。前提是仓库已经推上 GitHub（第 1 节第 5 步），云端会话从 GitHub 克隆。
- **能拿到：仓库里提交过的文件，和 claude.ai 上开启的技能**。仓库根目录的 `CLAUDE.md`（工作区索引）会读到，`_底座/` 和规则包能当普通文件读。出处：[What carries over from your setup](https://code.claude.com/docs/en/cloud-environments#what-carries-over-from-your-setup)。
- **拿不到：`~/.claude/` 下的全局规则、技能、子代理，和 `~/.claude/settings.json` 里登记的钩子**。所以钩子做的事，比如每轮附上全局规则和本对话的定位、交付闸门，在云端都不会跑。出处同上；另见 [Setup scripts vs. SessionStart hooks](https://code.claude.com/docs/en/cloud-environments#setup-scripts-vs-sessionstart-hooks)，原文是「User-level settings stay on your machine」。
- **全局规则可以用 setup script 补，改了规则要重贴**：
  1. 在 claude.ai/code 新建会话的页面，打开环境选择器，编辑环境，加一段 setup script，把 `_底座/全局规则_快照.md` 的全文写进 `~/.claude/CLAUDE.md`（文档里的例子就是这么写的）。贴全文、不从仓库里拷，是因为文档没写脚本跑的时候仓库克隆在哪。
  2. 怎么算成功：在云端会话里跑 `/context`，Memory files 下出现 `/root/.claude/CLAUDE.md`。出处：[Add personal preferences without committing to the repo](https://code.claude.com/docs/en/cloud-environments#add-personal-preferences-without-committing-to-the-repo)。
  3. 以后改了全局规则，要把脚本里的全文换成新的，再存一次。脚本里是贴进去的全文，不会跟着仓库变；改了脚本，云端才会马上重跑。
- **这样补，电脑上不会多一份**：
  - setup script 存在 claude.ai 的环境设置里，不在仓库里，电脑上看不到。
  - 文档建议把技能提交到仓库的 `.claude/` 下，这里不这么做。放在那里，在 `~/claude` 开的对话会把它当项目级规则再加载一份；子代理同名时项目级优先，仓库那份会盖过 `~/.claude/` 那份。出处：[sub-agents](https://code.claude.com/docs/en/sub-agents)。
- **贴进 setup script 的全局规则，能用这个环境的人都读得到；脚本出错，会话起不来；不改脚本，约 7 天才重跑一次（文档已写明）**：
  - 能用这个环境的人都能读到 setup script，所以贴进去的全局规则全文他们也读得到。
  - 脚本在 Claude Code 启动前跑，用 root 身份、Ubuntu 24.04；退出码不是 0，会话就起不来。
  - 跑完以后环境会缓存起来，之后的会话直接用缓存。只有改了脚本，或者约 7 天后缓存到期，才会重跑。
  - 出处：[Script requirements](https://code.claude.com/docs/en/cloud-environments#script-requirements)、[Environment caching](https://code.claude.com/docs/en/cloud-environments#environment-caching)。
- **技能、子代理、钩子能不能在云端补上，还没确认**：
  - setup script 写进 `/root/.claude/` 下 skills、agents、settings.json 的东西会不会被读，文档没写，要等实测。
  - setup script 跑的时候仓库克隆好了没有、克隆在哪个目录，文档没写。按 `~/claude/…` 找文件的工具在云端能不能用，也跟着未确认。
  - 就算钩子补上了，交付闸门（每轮结束时检查交付物的钩子）用来认路径的正则只认 macOS 的 `/Users/…`。云端是 Linux（`/root`、`/home/…`），它认不出回复里的文件路径，也就不会拦。

## 5. 可选，不做也能搬：删掉 claude.ai 上的旧版 report-format

- 它以 `anthropic-skills:report-format` 的名字出现，只有你能在 claude.ai 的技能设置里删掉。
- 不删也不影响装上：旧版只能用全名调，`/report-format` 调的是 `~/.claude/` 里那份。
