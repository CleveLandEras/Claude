# 换环境：旧电脑先跑一次导出对比，新电脑克隆后一条命令装上，自检九项全过才算装好（约 10 分钟）

规则已经收成一套能整体搬走的包，放在仓库里。这台电脑照旧用 `~/.claude/` 那份，没有被改动。

## 先回答两件事

**一、任何时候都只有一份规则在生效**
- **这台电脑**：生效的只有 `~/.claude/` 那份。仓库里的规则包放在 `~/claude/_底座/搬家/规则包/`，只用来存档和装到新电脑上。
  - 为什么不会多加载一份：按官方文档，会被自动加载的只有叫 `.claude` 的文件夹、叫 `CLAUDE.md`（或 `CLAUDE.local.md`、`AGENTS.md`）的文件和插件。规则包下这类名字有 0 个（第二级已核，写说明时又复核了一次）。出处：[skills](https://code.claude.com/docs/en/skills)、[sub-agents](https://code.claude.com/docs/en/sub-agents)、[memory](https://code.claude.com/docs/en/memory)。
  - 实测情况：在会话里对照过，命令行实测没有跑成。
    - 对照的做法：在会话里读规则包里的技能文件，没有触发任何加载；对照组是读弹窗项目 `.claude/skills/` 下的文件，马上就加载了那个文件夹的规则。这说明这种测法看得出按需加载。
    - 局限：技能会不会不出提示、直接加进列表，这次看不出来。
    - 命令行实测没跑成，因为桌面应用里的 `claude -p` 报「未登录」。想补的话见文末「可选」。
- **新电脑**：装上脚本把规则包拷进 `~/.claude/`，自检逐项核对，内容要和规则包一致。
- **旧电脑**：搬完就不用了，两边不用同步。

**二、路径不再绑定用户名，这台电脑照常运转**
- 规则包里的路径已经改成 `~`、`$HOME`，旧电脑家目录的路径有 0 处（第二级已核）。
- `_底座/` 在这台电脑上不改。到新电脑装上时，脚本按替换表改 8 个文件（4 个工具、README、对话定位、项目登记、考试题目）。历史记录不改。
- 这台电脑照常运转的依据：
  - 导出的预演、执行、对比三步，每步前后各核对一次本机 270 个规则和底座文件，一个都没变（执行子代理自称）；
  - 对比报「规则包和本机一致（12 项）」，本机 `~/.claude/` 的规则文件没有被改过（第二级已核）。

**已知限制**
- 云端会话只按官方文档写，没有实测。
- 交付闸门（每轮结束时检查交付物的钩子）用来认路径的正则只认 macOS 的 `/Users/…`。在 Linux 上（云端的 `/root`、`/home/…`），它认不出回复里的文件路径，也就不会拦。
- 不进库的文件夹，换电脑时要另外拷：
  - `_底座/任务/`；
  - 仓库根目录下的 `商城/`、`用好Claude/`、`团队工作模式/`、`竞品跟踪分析/`、`抖音总结/`、`企业微信自动回复/` 等；
  - 仓库外的 `~/Documents/dy`、`~/Documents/消息助手` 等。
- 新电脑上，仓库必须克隆到 `~/claude`。规则和钩子都按这个位置找文件，放在别处脚本会拒绝装上。

## 1. 搬之前（旧电脑）：对比一致、推上 GitHub、拷走不进库的文件夹

| 步 | 做什么 | 怎么算成功 |
|---|---|---|
| 1 | `bash ~/claude/_底座/搬家/导出.sh --对比` | 末行是「规则包和本机一致（N 项）」 |
| 2 | 不一致就跑 `bash ~/claude/_底座/搬家/导出.sh --执行`，再跑一次第 1 步 | 末行「已写：…」，再对比时一致 |
| 3 | 请 Claude 提交并给推送总结。你看完说「通过」，它才推 | GitHub 网页上 main 的最新一条是这次的提交 |
| 4 | 想带走记忆的，照第 4 节打包 | 桌面上有 `记忆.tgz` |
| 5 | 拷走「已知限制」里列的不进库文件夹 | 新电脑上的路径和旧电脑一样 |

- 第 1 步报「快照和 ~/.claude/CLAUDE.md 不一致」，或报替换表某条「出现 N 次」时，先不要推，把输出交给 Claude。前一种要先同步快照，后一种要在旧电脑上重新生成替换表。
- 平时也要跑：每次推送前，Claude 会先跑一次对比；每周四整理纠正之后，可以手动跑一次对比。

## 2. 新电脑或新账号：克隆、装上、自检

| 步 | 做什么 | 怎么算成功 |
|---|---|---|
| 1 | 装 Claude Code 并登录。新 Mac 第一次跑 `git` 时会提示安装命令行开发者工具，照提示装上（脚本用的 `/usr/bin/python3` 也来自它） | `git --version` 能打出版本号 |
| 2 | `git clone https://github.com/Clarelive/Claude.git ~/claude` | `~/claude/_底座/搬家/装上.sh` 存在 |
| 3 | `bash ~/claude/_底座/搬家/装上.sh`（预演，不改文件） | 有一行以「检查：全过。」开头（现在是要拷 12 项、改 8 个文件） |
| 4 | `bash ~/claude/_底座/搬家/装上.sh --执行` | 末段是「已装上：…逐项核过」。把它打印的撤回命令留着 |
| 5 | 跑第 4 步打印的 settings 命令。这条命令先备份，只合并钩子那一段 | 打印出改前改后的差异 |
| 6 | `bash ~/claude/_底座/搬家/装上.sh --自检` | 末行「自检：九项全过」 |
| 7 | 在 `~/claude` 开一个对话，请 Claude 提交 `_底座/` 里 8 个文件的路径改动。要推送的话，照旧先看总结、说「通过」 | `git status` 里 `_底座/` 下没有改动 |
| 8 | 把从旧电脑拷来的文件夹放回原位 | 各项目的入口文件（如 `~/claude/商城/先看这里.md`）都在 |

- 碰到下面几种情况就停下，不要往下跑：
  - 预演报「检查：有 N 处不过」：把输出交给 Claude。
  - 报「本机保护…拒绝 --执行」：说明你是在旧电脑上跑的。
  - 报「克隆到 ~/claude」：仓库放错了位置。
- 自检有不过的：先跑第 4 步打印的撤回命令，再把自检输出交给 Claude。

## 3. 云端会话：拿不到用户级规则，可以用环境的 setup script 补（只按文档写，没有实测）

- **能拿到**：仓库根目录的 `CLAUDE.md`（工作区索引）、仓库里提交过的文件（`_底座/` 和规则包都能当普通文件读），以及 claude.ai 上开启的技能。出处：[What carries over from your setup](https://code.claude.com/docs/en/cloud-environments#what-carries-over-from-your-setup)。
- **拿不到**：全局规则 `~/.claude/CLAUDE.md`、`~/.claude/` 下的技能和子代理，以及 `~/.claude/settings.json` 里登记的钩子。所以每轮附上定位、交付闸门这些在云端都不会跑。出处同上；另见 [Setup scripts vs. SessionStart hooks](https://code.claude.com/docs/en/cloud-environments#setup-scripts-vs-sessionstart-hooks)，原文是「User-level settings stay on your machine」。
- **怎么补全局规则**：
  1. 在 claude.ai/code 新建会话的页面，打开环境选择器，编辑环境，加一段 setup script，把 `_底座/全局规则_快照.md` 的全文写进 `~/.claude/CLAUDE.md`（文档里的例子就是这么写的）。
  2. 怎么算成功：在云端会话里跑 `/context`，Memory files 下出现 `/root/.claude/CLAUDE.md`。出处：[Add personal preferences without committing to the repo](https://code.claude.com/docs/en/cloud-environments#add-personal-preferences-without-committing-to-the-repo)。
- **为什么这台电脑不会因此多一份**：
  - setup script 存在 claude.ai 的环境设置里，不在仓库里，这台电脑看不到。
  - 文档建议把技能提交到仓库的 `.claude/` 下，这里不这么做。原因是放在那里，在 `~/claude` 开的对话会把它当项目级规则再加载一份；子代理同名时项目级优先，仓库那份会盖过本机那份。出处：[sub-agents](https://code.claude.com/docs/en/sub-agents)。
- **要知道的（文档已写明）**：
  - setup script 在 Claude Code 启动前跑，用 root 身份、Ubuntu 24.04；退出码不是 0，会话就起不来。
  - 跑完以后文件系统会做快照，之后的会话直接用快照。只有改了脚本，或者约 7 天后快照到期，才会重跑。这期间改了规则，云端用的还是旧的。
  - 能用这个环境的人都能读到 setup script。
  - 出处：[Script requirements](https://code.claude.com/docs/en/cloud-environments#script-requirements)、[Environment caching](https://code.claude.com/docs/en/cloud-environments#environment-caching)。
- **未确认**：
  - setup script 跑的时候仓库克隆好了没有、克隆在哪个目录，文档没写。所以要把全文贴进脚本，不从仓库里拷。按 `~/claude/…` 找文件的工具在云端能不能用，也跟着未确认。
  - setup script 写进 `/root/.claude/` 下 skills、agents、settings.json 的东西会不会被读，文档没写。也就是技能、子代理、钩子在云端能不能补上，要等实测。

## 4. 搬不走的三样：到新电脑上重建

**会话编号（各项目的主对话和分发）**
1. 照 `~/claude/_底座/项目登记.md` 里的名字，逐个开各项目的主对话（如「弹窗标签推送｜主对话」）。怎么算成功：对话名和项目登记里的一致。
2. 第一轮钩子会提示「本对话还没登记定位」。让它把 `_底座/对话定位.md` 里自己那一条的桌面编号和会话 ID 改成新的。怎么算成功：下一轮不再提示，附上的是这个对话的定位。
3. 对主对话说「开分发」，重开分发对话，分发也同样登记。
4. 让分发跑一次 `做项目总览.py`。怎么算成功：`_底座/项目总览.md` 里列的是新对话。

**定时任务**
- 每周四的整理纠正：新的「用好 Claude｜分发」照技能「整理纠正」第 8 步重建。怎么算成功：定时列表里有一条，下次触发在周四 09:07–09:37 之间。
- 各分发的夜间定时：由各分发自己照 `_底座/夜间推进.md` 重建。
- 桌面应用里那 9 个 `popup-tag-push-*` 定时任务是弹窗的旧流程，不搬。

**记忆（可选）**：要拷的是三个文件夹：`~/claude`、弹窗项目、dy。另外 2 个有内容的记忆文件夹属于桌面应用的临时工作区，新电脑上没有同样的路径，拷过去也用不上。
- 旧电脑上打包：
  ```
  cd ~/.claude/projects && tar czf ~/Desktop/记忆.tgz ./-Users-decheng-huang-claude/memory ./-Users-decheng-huang-claude---------/memory ./-Users-decheng-huang-Documents-dy/memory
  ```
- 新电脑上，先把 `记忆.tgz` 放到桌面，再跑（文件夹名按新家目录改，规则是路径里字母、数字以外的字符都换成 `-`）：
  ```
  D=$(mktemp -d) && tar xzf ~/Desktop/记忆.tgz -C "$D" && NEW=$(printf '%s' "$HOME" | sed 's/[^A-Za-z0-9]/-/g') && cd "$D" && for d in ./-Users-decheng-huang*; do t="$HOME/.claude/projects/$NEW${d#./-Users-decheng-huang}"; mkdir -p "$t" && cp -R "$d/memory" "$t/"; done
  ```
- 怎么算成功：`ls ~/.claude/projects/` 里出现 3 个以新家目录开头的文件夹，每个下面都有 `memory/`。
