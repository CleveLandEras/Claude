# 换环境：约 1 小时 10 分钟、三大步装好，新电脑上只有 `~/.claude/` 一份规则生效；云端会话以后再说，只补得上全局规则，其余未确认

- **多久、几步**：换一次环境约 1 小时 10 分钟（估计，另加拷文件的时间），分三大步：旧电脑上提交、推送、打包（约 10 分钟）→ 新电脑上克隆、装上（约 15 分钟）→ 重建 9 个对话（7 个项目、2 个跨项目对话，各约 5 分钟）。
- **只有一份生效**：新电脑上生效的规则只有 `~/.claude/` 一份；规则包（`~/claude/_底座/搬家/规则包/`，存着要装进 `~/.claude/` 的技能、子代理、钩子）只存档，不会被自动加载。例外两处，都不用管：弹窗项目里有一份 report-format 副本，在弹窗项目里开的对话会多载入它，归弹窗项目自己管；`_底座/任务/` 下两处历史备份里有旧版全局规则和技能，只在读到那两个文件夹里的文件时多载入一份。
- **云端会话**：现在不用动手。第一次要用时，只补得上全局规则；技能、子代理、钩子能不能补上未确认，交付闸门在云端不拦。

叫法：旧电脑＝现在用的这台；新电脑＝要换过去的那台（换账号也照新电脑做）；搬家脚本＝`~/claude/_底座/搬家/` 下的 `导出.sh`（把本机规则收进规则包）和 `装上.sh`（把规则包装进新电脑的 `~/.claude/`）；带走文件夹＝桌面上的 `换环境带走/`，放要拷到新电脑的压缩包。

## 1. 旧电脑：先让各项目提交，再推送，最后打包带走（约 10 分钟）

1. 看哪些改了没提交，每行是「个数 顶层文件夹」：
   ```
   git -C ~/claude -c core.quotepath=off status --porcelain --untracked-files=no | cut -c4- | cut -d/ -f1 | sort | uniq -c
   ```
   成功：打出几行；没有输出就是都提交过了，跳到第 3 步。
2. 让各项目提交：`弹窗标签推送系统` 那行，到「弹窗标签推送｜主对话」说「提交」；`_底座` 和根目录散放文件那几行，到「用好 Claude｜主对话」说「提交」。别的文件夹整个不在库里，不会出现。成功：再跑第 1 步没有输出；来不及提交的不用等，第 6 步会一起打包。
3. 对比规则包和本机：`bash ~/claude/_底座/搬家/导出.sh --对比`。成功：末行「规则包和本机一致（12 项）」。平时推送前、周四整理纠正之后也跑这条。
4. 第 3 步不一致时，跑 `bash ~/claude/_底座/搬家/导出.sh --执行`（成功：末行以「已写：」开头），再跑第 3 步。报「快照：和 ~/.claude/CLAUDE.md 不一致」（全局规则的存档 `_底座/全局规则_快照.md` 和本机全局规则不一样）或「路径替换.json 对不上」（新电脑改路径用的对照表 `_底座/搬家/路径替换.json` 过期了）就先停，把输出交给「用好 Claude｜主对话」。
5. 推送：在「用好 Claude｜主对话」说「推送」，它把第 4 步导出的改动一起提交、给你推送总结，你说「通过」它才推。成功：下面这条打出 `0`，表示本机的提交都已在 GitHub 上：
   ```
   git -C ~/claude fetch -q && git -C ~/claude rev-list --count origin/main..main
   ```
6. 打包带走：没进库的、来不及提交的，和仓库外的两个项目 `~/Documents/dy`、`~/Documents/消息助手`，打成压缩包放进带走文件夹。先看没进库的有哪些，每行是「个数 顶层文件夹或散放文件」：
   ```
   git -C ~/claude -c core.quotepath=off status --porcelain --ignored | grep -E '^(!!|\?\?)' | cut -c4- | cut -d/ -f1 | sort | uniq -c
   ```
   再打包：
   ```
   mkdir -p ~/Desktop/换环境带走 && git -C ~/claude status --porcelain -z --ignored | perl -0ne 'print substr($_,3) if /^(!!|\?\?|[ MA][ M]) /' | tar -C ~/claude --null -T - -czf ~/Desktop/换环境带走/claude_没进库.tgz && tar -C ~/Documents -czf ~/Desktop/换环境带走/Documents_两个项目.tgz dy 消息助手 && ls -lh ~/Desktop/换环境带走
   ```
   成功：末尾列出 `claude_没进库.tgz`、`Documents_两个项目.tgz`，大小都不是 0。中途报错就停下，把输出交给「用好 Claude｜主对话」。
7. 可选，带走记忆：
   ```
   cd ~/.claude/projects && find . -mindepth 2 -maxdepth 2 -name memory -type d ! -empty | tar czf ~/Desktop/换环境带走/记忆.tgz -T - && tar tzf ~/Desktop/换环境带走/记忆.tgz | grep -c '/memory/$'
   ```
   成功：打出打包的记忆文件夹数（11/03 盘点是 5 个）。记下这个数，新电脑上要对。
8. 可选，命令行实测规则包不会被自动加载：在你自己登录过的终端里跑（桌面应用的对话里跑会报未登录）`bash ~/claude/_底座/任务/用好Claude/2026-11-03_规则搬家包/不多加载实测.sh`。成功：输出里有「结论：过」；没有就把结论那一行交给「用好 Claude｜主对话」。
9. 把带走文件夹整个拷进移动硬盘或网盘。成功：那边的文件夹里有第 6、7 步的压缩包，大小和桌面上的一样。

## 2. 新电脑：克隆、解开压缩包、装上、自检九项全过（约 15 分钟）

1. 装 Claude Code 并登录；第一次跑 `git --version` 时照提示装上命令行开发者工具。成功：`git --version` 打出版本号。
2. 克隆到 `~/claude`（必须是这个位置，放别处装上脚本会拒绝）：`git clone https://github.com/Clarelive/Claude.git ~/claude`。仓库是私有的：用户名填能读它的 GitHub 账号，密码填 GitHub 个人访问令牌（[怎么生成](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)）。成功：`ls ~/claude/_底座/搬家/装上.sh` 打出这个路径。
3. 把带走文件夹拷到新电脑桌面，解开两个压缩包，再核对：
   ```
   tar -xzf ~/Desktop/换环境带走/claude_没进库.tgz -C ~/claude && tar -xzf ~/Desktop/换环境带走/Documents_两个项目.tgz -C ~/Documents
   LC_ALL=en_US.UTF-8 tar tzf ~/Desktop/换环境带走/claude_没进库.tgz | cut -d/ -f1 | sort -u | while read -r p; do [ -e ~/claude/"$p" ] || echo "缺：$p"; done; ls -d ~/Documents/dy ~/Documents/消息助手; echo 核对完
   ```
   成功：没有「缺：」开头的行，打出 `dy`、`消息助手` 两个路径和「核对完」。只解开这两个压缩包，不拿旧电脑的整个文件夹盖过来，那样会盖掉 GitHub 上更新的文件。
4. 预演，不改文件：`bash ~/claude/_底座/搬家/装上.sh`。成功：有一行以「检查：全过。」开头，写着 `~/.claude/` 要拷 12 项、`_底座/` 要改 8 个文件。12 项＝全局规则（`_底座/全局规则_快照.md` 拷成 `~/.claude/CLAUDE.md`）、技能 6 个、子代理 2 个、钩子 3 个；8 个文件＝`_底座/` 里写着旧电脑家目录的 4 个工具、README、对话定位、项目登记、考试题目。
5. 执行：`bash ~/claude/_底座/搬家/装上.sh --执行`。成功：最后一段以「已装上：」开头、写着「逐项核过」。它打印的撤回命令留着备用。
6. 登记钩子：第 5 步若打印了「请自己跑这条命令」，把那条命令整段复制到终端跑一次（它先备份 `~/.claude/settings.json`，只合并钩子一段）。成功：打印出「改前」「改后」的差异。没打印就跳过。
7. 自检：`bash ~/claude/_底座/搬家/装上.sh --自检`。成功：末行「自检：九项全过」。九项：①每轮附上全局规则和本对话定位 ②交付闸门能拦 ③技能、子代理都在 ④内容一致 ⑤settings.json 登记了钩子 ⑥机检.py --自测 ⑦查规则预算.py ⑧不绑用户名 ⑨不多加载。

碰到这几种就停下，在 `~/claude` 新开一个对话，把输出贴给 Claude：「检查：有 N 处不过」（其中「仓库不在 ~/claude」是克隆位置错了，「本机保护…拒绝 --执行」是你在旧电脑上跑了）；「核对不过：…」（先照第 5 步打印的撤回命令撤回）；自检「N 项不过」。

## 3. 新电脑装好后：放回记忆，重建 9 个对话和定时任务，提交路径改动（约 45 分钟）

1. 可选，放回记忆。文件夹名开头的旧家目录会换成新家目录：
   ```
   D=$(mktemp -d) && tar xzf ~/Desktop/换环境带走/记忆.tgz -C "$D" && OLD=-Users-decheng-huang && NEW=$(printf '%s' "$HOME" | sed 's/[^A-Za-z0-9]/-/g') && cd "$D" && for d in ./*/; do n=${d#./}; n=${n%/}; case "$n" in "$OLD"*) t="$NEW${n#"$OLD"}" ;; *) t="$n" ;; esac; mkdir -p "$HOME/.claude/projects/$t" && cp -R "./$n/memory" "$HOME/.claude/projects/$t/"; done; ls -d ~/.claude/projects/*/memory | wc -l
   ```
   成功：打出的数不少于旧电脑第 1 节第 7 步打出的数。
2. 重开 9 个对话，工作文件夹照 `~/claude/_底座/项目登记.md`。7 个项目的主对话：用好 Claude｜主对话、弹窗标签推送｜主对话、商城活动配置｜主对话、抖音号（dy）｜主对话、团队工作模式｜主对话、消息助手｜主对话、企业微信自动回复｜主对话；再在 `~/claude` 开「总的主会话」「产出汇报」。成功：对话名和 `~/claude/_底座/对话定位.md` 里的一致。
3. 登记新编号：每个新对话第一轮，钩子会提示「本对话还没登记定位」，让它把对话定位里自己那一条的桌面编号和会话 ID 改成新的。成功：下一轮不再提示。
4. 重开分发：用好 Claude、弹窗标签推送、企业微信自动回复三个项目原来有分发，对它们的主对话说「开分发」，分发同样登记。成功：分发跑完 `~/claude/_底座/工具/做项目总览.py` 后，`~/claude/_底座/项目总览.md` 列的是新对话。
5. 别的对话（如「项目推进监督与规划」）你要用就自己重开，同样登记。
6. 提交路径改动：在「用好 Claude｜主对话」说「提交」，提交装上时改的 `_底座/` 8 个文件；要推送，照旧看完推送总结说「通过」。成功：下面这条打出 `0`：
   ```
   git -C ~/claude status --porcelain --untracked-files=no _底座 | wc -l
   ```
7. 定时任务：每周四 09:07 的整理纠正，由新的「用好 Claude｜分发」照技能「整理纠正」第 8 步重建。成功：定时列表里有这一条，下次触发在周四 09:07–09:37 之间（定时工具会错开最多 30 分钟）。各分发的夜间定时由它们照 `~/claude/_底座/夜间推进.md` 自己重建；桌面应用里 9 个 `popup-tag-push-*` 定时任务是弹窗的旧流程，不搬。

## 4. 云端会话：现在不用动手；第一次要用时只补得上全局规则，技能、子代理、钩子未确认，交付闸门不拦

- 第一次要用时：告诉「用好 Claude｜主对话」，它写好 setup script（云端会话启动前跑的脚本），你贴进 claude.ai/code 的环境设置，再开一个会话实测。前提是第 1 节第 5 步已推送，云端会话从 GitHub 克隆仓库。
- 能拿到：仓库里提交过的文件（含根目录 `CLAUDE.md`）和 claude.ai 上开启的技能。拿不到：`~/.claude/` 下的全局规则、技能、子代理，和 `settings.json` 里登记的钩子（[文档](https://code.claude.com/docs/en/cloud-environments#what-carries-over-from-your-setup)）。
- 全局规则补得上：setup script 把 `_底座/全局规则_快照.md` 全文写进 `~/.claude/CLAUDE.md`。成功：云端会话里跑 `/context`，Memory files 下出现 `/root/.claude/CLAUDE.md`（[文档](https://code.claude.com/docs/en/cloud-environments#add-personal-preferences-without-committing-to-the-repo)）。改了全局规则，要把脚本里的全文换新再存。
- 技能、子代理、钩子补不补得上未确认：写进 `/root/.claude/` 会不会被读，文档没写。交付闸门只认 macOS 的 `/Users/…` 路径，云端是 Linux，不拦。
- 技能不提交进仓库的 `.claude/`：放在那里，在 `~/claude` 开的对话会把它当项目技能再加载一份。贴进 setup script 的全局规则，能用这个环境的人都读得到；脚本退出码不是 0，云端会话起不来。

## 已知限制
- 云端这一节只按官方文档写，没有实测。
- 「规则包不会被自动加载」是按官方文档列出的自动加载位置判断的，自检⑨查的就是这些名字；命令行实测是第 1 节第 8 步，可选。
- claude.ai 上还有一份旧版 report-format（`anthropic-skills:report-format`），只有写全名才调得到，不影响装上；要删只能你在 claude.ai 的技能设置里删。
- 没进库的内容只靠带走文件夹带过去，拷丢了 GitHub 上也没有。
