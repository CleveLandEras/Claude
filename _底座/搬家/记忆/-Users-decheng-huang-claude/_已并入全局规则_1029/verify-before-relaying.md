2026-09-30 反省时发现：我在项目总览里照抄日志写「02 修正了 5 处已知错误」，没有核对；后来自己读 02 才发现提案里一句写反（「确定 25 人买过首储」应为「没买过」）。

**Why:** Dk 基于我给的信息做判断、做验收。把 agent 自评当事实转述，等于让 Dk 在不知情的情况下替 agent 的错误背书。这和「把过程当结果」「过闸 = 做完」是同一类毛病。

**How to apply:**
- 给 Dk 的任何进度或状态，都标明来源等级：执行者自称 / 审查通过 / 我已核实。
- 进总览、汇报里的关键结论和数字，先抽查原文再写。
- 同类反省总表见 `弹窗标签推送系统/简报/2026-09-30_同类问题反省.html`：用错尺子、约束用错地方、过程当结果、对象混为一谈、前提变了下游没跟着改。参见 [[dk-acceptance-gate]]、[[prevent-iteration-drift]]。
