用户在 2026-09-28 明确说过：「长内容用高可读性的文件展示」。起因是我在聊天里用长篇表格和列表回答了「现状进行到哪、我要回答什么」。

**Why:** 聊天窗口不适合读长内容；文件可以排版、折叠、跳转、复制，用户也能留存和转交。

**How to apply:**
- 超过一屏、带多张表、需要反复查看的内容（进度汇报、待回答清单、分析结果、方案），一律写成 HTML 文件，并在侧边栏打开。
- 聊天里只写 2–4 句：核心结论 + 文件链接 + 最需要用户做的一件事。
- 文件遵循 [[report-readability-standard]]：结论先行、逻辑链、表格与图、数字带分母、长清单折叠、要发出的消息附复制按钮。
- 弹窗项目里这类给 Dk 的简报放在 `弹窗标签推送系统/简报/`，文件名带日期。
