# 顶尖做法参考库

收录业界顶尖产品「怎么做」的公开资料，带官方文档出处。10/19 起建库，来源是 10/12–10/19 各轮对标。

## 用途

1. 设计每一个点之前先查这里，已有的做法直接引用，不重新找。
2. 这里查不到，再上网查官方文档；查到后按下面的格式补进来。
3. 本库是参考材料，不是规则（`../标准体系.md` 第〇.1、〇.2 节）。与写作标准、已定事项、Dk 原话冲突的做法，「我们的取舍」写不采纳，并注明冲突的规则出处（文件与行号，或 Dk 原话的答复登记日期）；写采纳、部分采纳的，同时写「对照过：」列出对照过的规则。评审拿本库比对时，与规则冲突处以规则为准，不要求我们为不同于本库的做法另写理由。

## 收录规则

1. 出处必须是官方文档或公开资料链接；没有出处链接、或出处只是「同行审」「Jira」的条目不收。
2. 每条写核对日期（取来源文件里的日期）。官方页面常改，落地前对关键口径再核一次。
3. 同一做法多家共有时合并为一条，「哪些产品这样做」列出全部；同一做法在不同来源出现的，合并出处与日期。
4. 来源标了「摘要」「未逐字核对」的出处，链接标题后保留该标记，表示只看到搜索摘录。
5. 「做法」只写业界怎么做；我们怎么取舍写在「我们的取舍」，两者不混。

## 表格的列

| 列 | 内容 |
|---|---|
| 编号 | 文件内序号，评审时可直接引用，例如「控-05」 |
| 做法 | 一句话写清怎么做 |
| 哪些产品这样做 | 做法对应的产品；只列有出处链接的 |
| 出处链接 | 官方文档或公开资料，同一做法的多个出处都列 |
| 核对日期 | 来源对标的核对日期 |
| 我们的取舍 | 采纳／部分采纳／不采纳／未定，加一句理由；采纳、部分采纳写「对照过：」，不采纳注明冲突的规则出处（用途第 3 条）。来源里的结论先照录，没有写「未定」；照录的结论按用途第 3 条对照规则后改正 |
| 落在哪 | 落在哪个原型页或需求文档节；来源没写的写「—」 |

「我们的取舍」照录对标当时的结论，不是已确认的决定。10/19 起按用途第 3 条普查：「需求评审与设计展示」「写死迁移与功能开关」两个文件已普查改正（与写作标准冲突的改为不采纳并注明行号，采纳的写了「对照过」）；其余七个文件 10/19 晚也已普查：81 条写采纳、部分采纳的（含 2 条写「方向相同」「排除相同」按采纳处理）中，8 条全部或部分改为不采纳（配-07 撤下本活动、配-08 渠道连接页、配-12 内容块与模板、群-08 人数曲线、控-03、群-10、编-03、数-41，依据写作标准第 172 行或推送系统后台集成需求第七节），无未定，5 条按规则收窄、限定范围或删去不合规的理由（控-01、控-09、控-12、配-01、编-01），其余补写了「对照过」；原写不采纳的编-05、数-42 改了理由；各文件文首有说明，逐条记录见 `过程记录/规则整理_1019.md`。对标之后需求文档又改过的，在取舍里写了「后续」；其余以需求文档最新版为准。
