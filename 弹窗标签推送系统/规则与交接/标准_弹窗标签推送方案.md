# 标准：弹窗、推送、标签方案（进度汇报）

2026-10-14 建，规则见 `标准体系.md`。每次开工先读 `过程记录/进度_弹窗标签推送方案.md`（进度流水账，10/19 起不再放在本文件），取优先级最高的未通过项。条目只由主对话改，并写明依据。

## 一、目的
- 产品计划短期三项：
  - 弹窗：「滿足不同用戶下的彈窗內容，并整體控制彈窗 數量/內容/順序等」，针对新增、回流、破产、潜在付费、潜在流失五类用户逐步设计客制化弹窗内容；优先用已有功能满足，不满足的再排期补充。
  - 推送：「統一推送入口，提高易用性，并增加數據情況（發送量，到達率等）」。
  - 标签：「針對現有標籤能力進行補充」；现有「And」「排除」，新增「or」，后续增加「交集」。
- 这份稿子的用途：「我们只是汇报一下工作进度，好让主管知道和他期望有没有出入而已」（10/12）。

## 三、约束（已定，违反就不通过）
- 不写排期；不出现「主管」等指称读者的词和内部用语（已定事项 19、20）。
- 正文：封面 → 结论 → 目录 → 一 目标 → 二 弹窗 → 三 推送 → 四 标签，每个现状页后紧跟做法页；不设「原因」；附录单独成节、可折叠（已定事项 21）。

- 活跃、付费、业绩、购买不作目标或指标（已定事项 2、3）。

- 现状页后面紧跟它的做法页（已定事项 21）。
