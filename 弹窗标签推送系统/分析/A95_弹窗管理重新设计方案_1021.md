## 三、新设计

### 总体思路
1. 列表层回答运营最常问的「每个位置现在弹什么、谁先谁后、弹给多少人、效果如何」：按 位置 › 类型 分区，组内按权重排成实际先后，一行一条规则。
2. 编辑层按运营要回答的问题分段（放在哪、叫什么、给谁、排第几、弹什么、何时生效），右侧固定摘要随填随算，保存前看得到后果。
3. 叫法统一到触达系统其他页：规则名称、编号、对象、标签群组、弹窗内容、状态。

### 叫法对照

| 现有叫法 | 新叫法 | 理由 |
|---|---|---|
| 大厅弹窗顺序设定（页名、页签） | 弹窗（菜单与页名）；页签「规则」 | 页里也有游戏破产弹窗 |
| 弹窗名称 | 规则名称 | 写的是规则，不是某个弹窗 |
| 弹窗活动 ID | 编号（显示为「#12」） | 是规则编号；数值不变 |
| 弹窗排序（列表列）、弹窗顺序（编辑段） | 弹窗内容 | 放的是内容清单，先后由表内顺序体现 |
| 派发对象、群组标签 | 对象、标签群组 | 与推播、短信、快显一致 |
| 标签状态 ＋ 上架中／下架 | 状态（生效中、未开始、已结束、已暂停、草稿） | 一个状态回答弹不弹 |
| 弹出数量 | 每次最多弹出 N 个 | 句子本身说明含义 |
| 权重、首次登入、弹窗时机、弹窗形式、冷却时间 | 不变 | Dk 已定或叫法准确 |

## 四、同一思路用到其他界面

| 界面 | 方向 |
|---|---|
| 推播 | 列表首屏回答「接下来发什么、发给多少人、名额够不够」：保留状态计数筛选，上限与勿扰条改为只读＋修改并显示今天被上限拦下的人数；编辑层用同一骨架（对象 → 内容 → 发送时间），右侧固定摘要放预计人数与重要／普通名额占用。 |
