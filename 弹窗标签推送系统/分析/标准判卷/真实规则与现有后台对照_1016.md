# 真实规则与现有后台对照（1016）

> 视角：弹窗运营，没有项目背景，要把同事草稿里的真实规则和现有后台的规则搬进新后台。
> 对照对象：需求文档 v0.9.22（4.2.1、4.2.3、5.10、5.11、5.12、5.16）与原型页 #8、#9、#15。

## 结论

1. **草稿中的人群分层规则大多能配出来，但三处配不出来：**
   - 储值类礼包只能「按位置弹」，不能指定「返回大厅」。草稿的储值类规则都写「返回大厅」，因此配不出来。
   - 没有「按类型（活动、普通礼包）每人每天上限」，草稿全局规则「活动 24 小时 ≤ 1 次、普通礼包 24 小时 ≤ 1 次」配不出来。
   - 「大厅金币 < n」算破产，配不出来。
2. **草稿的另外两条全局规则，语义和新后台不一致：**
   - 「弹出间隔 1800 秒」：新后台的「弹窗间隔」是同一次弹出里各弹窗之间隔几秒，不是两次弹出之间隔多久。
   - 「单次最多 3 个」：新后台只能在每条规则上分别设弹出数量，没有活动类、储值类合计的上限。
   - 两条都只能靠变通近似。
3. **现有后台的字段、选项、查询结果项在新后台都有对应，没有发现无意中去掉的功能。** 有两处是有意改动，文档写了理由：同类规则由「叠加都弹」改为只弹优先级最高的一条；对象由选一个标签改为选标签群组。
4. **迁移有三个风险要先处理：**
   - 迁入优先级的初值写的是 ID 12、13、14、15。10/10 截图里上架中只有 ID 5、6、7 三条；盘点里出现过的 ID 10、11 也没写进迁入清单。
   - 「首次登入」要拆成当日首次和生涯首次。现有规则迁入时按哪个对应，还在等研发确认（第 9 章研发 34）。
   - 玩家查询里两张「弹窗顺序表」写的是「照旧」。改成只弹优先级最高的一条之后，表里列的是命中的全部规则，还是实际会弹的那一条，文档没有定义。
5. **建议先补 3 项：** 储值类项的时机、按类型每日上限、迁入清单按实况重做。其余缺口是文档补写或小改动。
