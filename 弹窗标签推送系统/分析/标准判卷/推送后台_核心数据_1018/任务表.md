# 核心① 数据：运营要靠数据完成的真实任务

10/18 设计主线定。用途：每个任务在原型上从头走到尾，逐层查「页面 → 字段与口径 → 回传来源与异常（拿不到的数据怎么显示）」。

这件核心要做到（Dk 10/18）：每种推送的发送、到达、点击，弹窗、快显的曝光、点击，能按推送方式、人群、单条、时间看，口径与回传来源清楚。
衡量口径（已定事项第 3 条）：游戏外推送（推播、短信、Facebook、LINE）看发送、到达、点击；游戏内（弹窗、快显）看曝光、点击；短信例外，按发送对象一定时间内登录人数判定。领取、购买、发送后登录、发送后付费只作后台数据，不进目标与验收。

出处简称：计划＝`来源资料/产品计划原文_1010.md` 第 2 项「增加數據情況（發送量，到達率等）」；参照 Axx＝`分析/应有内容参照.md` A.2 任务表；定 N＝`规则与交接/已定事项.md`；Jira＝`分析/参照来源_Jira历史工单.md`。

每个任务走查三层：
1. **页面**：从侧栏哪个入口进、到哪一页哪一块、几步能读到答案；中途有没有走不下去（没有入口、要手工相加、要跨页记数）。
2. **字段与口径**：答案里的每个数，定义是什么（人数还是次数、是否去重、按发出时刻还是按回传时刻归日、人群按发送当时还是现在）、页面与需求文档是否写清且一致。
3. **回传来源与异常**：这个数从哪来（服务商受理回执、运营商回执、平台回传、客户端上报、点击跳转记录、登录记录）、多久到、统计窗口多长；拿不到（渠道不回传、回传中断、统计窗口未满、记录不全）时页面显示什么，会不会显示成 0 让人误判。
