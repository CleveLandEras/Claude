推送系统的后台集成需求　·　第 7 页
编号
需求
规则与取值
为什么这样定
结论
2.6
一次性推送的状态
草稿 → 已排程（定时）／发送中（立即）→ 已完成、发送失败或已停止；到时名单或可触达为 0 人 → 无可发送对象
每个状态对应确定的下一步
2.7
已完成与发送失败的界线
至少 1 条被受理即已完成（部分失败也算）；全部未受理为发送失败；全部在发送前拦下为已完成、发送 0
失败条数与原因在单条推送数据页
2.8
系统延迟发送
定时推送因故障延后 2 小时内的恢复后发出；超过 2 小时不发，记发送失败「系统延迟超时」，不可重试，可复制
过时的内容不再迟发
2.9
按行为推送的状态
草稿 → 运行中 ⇄ 已暂停 → 已结束；暂停可手动恢复或到时间自动恢复；生效期间结束自动结束；已结束不能恢复
按行为推送持续运行，要能暂停与结束
2.10
停止、暂停与复制
已排程、发送中可停止：已发出的不撤回，自动重试取消
暂停期间的触发不发，恢复后不补发
全部状态可复制成新草稿，记来源 ID
补发会集中打扰玩家

4.1
立即、定时可按标签群组发
全部玩家，或一个及以上标签群组（下拉列出当前人数，可搜索）；再选排除群组

结论
5.1
三种发送方式
立即、定时、按行为；快显只有立即、按行为；弹窗按自己的规则弹出
快显只发给在线玩家，定时到点时玩家多半不在线
5.2
定时的时间范围
须在 3 分钟后、30 天内，以点确认的时刻为准

5.3
按行为发给触发的玩家
可加「只限这些群组」（默认不限，触发即发）与排除群组；每次触发时判断这位玩家在不在群组内

5.4
首批触发行为
限时加码礼包快到期（剩 N 小时；默认只发给尚未购买的）、玩家升级、完成任务、通行证升级；快显另有中奖（金额不低于 N）
覆盖现有礼包提醒与客户端写死的快显
5.5
生效期间、提醒次数与间隔
生效期间必填，结束日 24:00 自动结束，开始前的触发不发；每次触发最多发 N 条（默认 1），同一玩家两次提醒至少间隔 N 小时（默认 24）
按行为推送不会无期限运行，也不会短时间重复提醒
5.6
预计人数按近 7 天日均
触发 → 排除后 → 可触达 → 勿扰放弃 → 频率上限拦下 → 预计发出
按行为推送没有固定名单

结论
5.7
每次触发的判断顺序
生效期间与运行中 → 只限与排除群组 → 提醒次数与触发条件 → 可触达 → 勿扰（只查游戏外推送）→ 每人每天上限；全部通过才发

重复触发提示

事件去重与补处理
同一事件重复上报只触发一次；事件服务中断后补处理时重新判断条件，不成立的不发
避免重复发与过期发
5.11
礼包提醒在切换前不能运行
「推荐礼包设定」为原处生效时，触发行为为「限时加码礼包快到期」的推播不能确认或恢复；确认按钮换成「保存，去切换」
同一条提醒只在一处发

编号
需求
规则与取值
为什么这样定
结论
6.1
表单显示当前上限
只读「推播每人每天 2 条（在「频率上限」页设置）」，可点去修改；「本条遵守频率上限」默认勾选

6.2
不遵守上限须写明
取消勾选时须选「仍计入当天条数」或「不计入」并填原因；确认页摘要写明，原因记入操作纪录

6.3
确认前校验
内容完整、对象不为 0 人、定时时间有效、触发条件完整、生效期间有效、不遵守上限已写明；全部通过才可确认，未通过项逐项列出并标红

6.4

群组 → 排除后 → 可触达 → 勿扰顺延（或放弃）→ 频率上限拦下 → 预计发出；拦下人数按近 7 天估算并注明
成熟后台（Braze）发布前同样给确认摘要
6.5
确认后直接生效，不设审批
立即「确认发送」→ 发送中；定时「确认排程」→ 已排程；按行为「确认启用」→ 运行中；附摘要表
防错靠确认页、测试发送与可停止
