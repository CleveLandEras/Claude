# 原型新增页 · 运营走查判卷（夜间）

判卷人视角：棋牌手游资深运营，用过 Braze／OneSignal／CleverTap。材料：产品计划原文 1010、`3_原型.html`（页 10a、12、12 游戏外推送数据、12a–12d、13、14、15、16，及 3、9 表单）、`4_需求文档.md` v0.9.7。口径按已定：推送看发送、到达、点击，弹窗看曝光、点击，短信另看发送后登录。

## 一、总体结论

**日常看数和单人排查已经够用，配召回链路还不够用。**

- 够用的部分：看数（概览→游戏外／游戏内推送数据→单条→玩家）可以一路下钻；玩家查询能逐项写出弹窗没弹的原因。这两块比 OneSignal 细，接近 Braze 的 User Profile 加 Message Activity Log。
- 卡住的部分：
  1. 一次召回由「推送＋承接弹窗」组成，系统里没法把两者绑在一起。弹窗规则没有「所属活动」，也不能按「收到或点了某条推送」来定向。
  2. 周报里的「最差」排序口径自相矛盾，排序也不分渠道基线。
  3. 客服处置没有独立角色，也不能补发。
- 页面之间有 14 处数字或口径对不上（见第四节），其中 2 处是算术上不可能成立的硬伤（第 1、4 条）。

## 三、新增页够不够用、缺什么

够用：概览、游戏外推送数据、游戏内推送数据、单条数据页、玩家查询、操作纪录的「相关改动」、告警与发版登记。日常看数和排障可以上线使用。
