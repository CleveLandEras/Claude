# 核心③ 按人群发：运营要靠按人群发完成的真实任务

10/18 夜 设计主线定。用途：每个任务在原型上从头走到尾，逐层查「页面 → 规则与口径（运算顺序、刷新、人数含义）→ 异常」。

这件核心要做到（Dk 10/18）：标签且、或、排除、交集，五类人群都圈得出，人数可预览。产品计划原文：「標籤能力：針對現有標籤能力進行補充……現有『And』、『排除』，新增『or』，後續增加『交集』」；第 1 项「針對 新增 / 回流 / 破產 / 潛在付費 / 潛在流失用戶 逐步設計 客製化彈窗內容」。
守已定事项：五类人群都能圈出，潜在付费、潜在流失按定 17 口径新建标签（定 17）；「或」已上线、弹窗对象能用排除（定 15）；推送分游戏内、游戏外两层，不混说（定 24）；使用者是运营，不设审批；本期范围未定：不删块、不加候选块；标签与群组的计算由标签系统实现，推送后台只读取与显示（需求文档 4.3）。

出处简称：计划＝`来源资料/产品计划原文_1010.md` 第 1、3 项；盘点＝`来源资料/claude_弹窗标签推送_盘点.html`（标签约 100 个、十大类，每个是独立 BigQuery 脚本，最快 25 分钟刷新；组合支持 And、排除、or；弹窗对象填「标签名称＋群组 ID」；排除名单含黑名单、VIP 名单 108 人；机器人与测试账号 740 人）；截图＝Dk 10/10 附的后台截图（弹窗顺序设定、玩家弹窗顺序查询；会员标签设定的现状见盘点第一节与 `分析/A37_能力线现有能力.md` 标签节）；参照 Axx、B3-xx＝`分析/应有内容参照.md`；Jira＝`分析/参照来源_Jira历史工单.md`；定 N＝`规则与交接/已定事项.md`；示例＝主对话 10/18 夜交办时给的任务示例；需求＝`推送系统后台集成需求/4_需求文档.md`。

每个任务走查三层：
1. **页面**：从侧栏哪个入口进（标签群组设定页 #19 不在侧栏内，从哪里跳过去）、到哪一页哪一块、几步能做完或读到答案；中途有没有走不下去（没有入口、要手工推算、要跨页记数、要开单问研发）。
2. **规则与口径**：答案依赖的每条规则写清没有——且、或、排除的运算顺序与括号；交集的定义与嵌套；刷新频率、批次、发送时取名单的时点（排程时、开始发送时、每次重复时）；人数含义（原始符合、排除后、可触达、预计发出、当前生效）与各处是否同一口径；进出群组的时点；原型与需求文档是否一致。
3. **异常**：被引用群组刷新失败或过期、标签计算失败、人数骤降、改口径时有在用的推送与弹窗、群组停用或删除、同一人多账号、未登录态、名单上传有无效 ID、名单与群组重叠、旧群组算法变化；页面上会不会给出与实际不符的说法。
