## 评2 重算（p13 例 ID 61）

通过率＝本层人数 ÷ 上一层人数（上限为扣上限后 ÷ 可触达），按人数精确算、显示到 0.01%：
排除 16,500/16,564＝99.61% → 11,190/11,240＝99.56%；可触达 12,010/16,500＝72.79% → 7,920/11,190＝70.78%；勿扰 100%；上限 12,000/12,010＝99.92% → 7,890/7,920＝99.62%。

| 来源 | 算式 | 结果 |
|---|---|---|
| 群组影响 | −5,324 × 确认时下游通过率之积 72.45%（＝12,000/16,564） | −3,857.0 |
| 排除影响 | 11,240 ×（99.56% − 99.61%）× 72.73%（＝12,000/16,500） | −4.8 |
| 触达影响 | 11,190 ×（70.78% − 72.79%）× 99.92% | −224.8 |
| 上限影响 | 7,920 ×（99.62% − 99.92%） | −23.4 |
| 发送失败 | 照旧 | −90 |
| 合计 | | −4,200.0（四舍五入 −3,857 −5 −225 −23 −90 ＝ −4,200） |

## 做法上的取舍（我定的，请设计主线过目）

1. 三级状态的归类：本批失败沿用、连续失败或超过刷新周期 2 倍、源表迟到、按日换批失败都归「名单较旧」；群组层的「已暂停」只用于可疑批次（原因「人数异常待确认」，按钮「确认采用新批次」）；过期超过 24 小时的暂停落在推送、快显自身（显示「已暂停」与「恢复」），弹窗 72 小时同理。「待计算」视为新建未可用，放在三级之外（置灰），未并入三级。
2. 「人数异常待确认」的推送行：群组未判可疑、只是受众偏差的，「按上一成功批次发送」置灰，「确认采用新批次并发送」即原「照常发送」，以守「操作四个不变」。分组上放在「发送」组；待处理总数 22 → 20 类（合并 −1，今日名单未出 −1）。
3. 名单未更新：重复的定时本期跳过不进待处理，只站内通知；不重复的定时记发送失败，落在待处理「发送失败」。p1 原「今日名单未出」状态卡改成通知卡，未删块。
4. 名单算出后又登录过的起点只取纳入条件的标签，排除组的标签（如批次型「回流」）不计；按行为推送按只限群组区分两种写法。
5. 评4 的「超出 ±20%」按判可疑处理（与确认的试算不符）。
6. 评9 示例里没有现成的「破产后未回到游戏」推送 ID，提示文案写「运行中的按行为推送（触发：破产后未回到游戏）」，未编造 ID。
7. 评10 存量标签未登记源表时的兜底（按排程推定并标「源表未登记」）是我补的，需求文档执笔人如另有写法以需求文档为准。
8. p3「名单时点提示」卡的例子用的是按日换批标签，评12 之后 05:30 到点会等当天名单，原提示「将用 10/12 的名单」与新规则冲突，已改为两种情况分写（按日换批会等，最迟 07:30；滚动型照用前一日批次）。
