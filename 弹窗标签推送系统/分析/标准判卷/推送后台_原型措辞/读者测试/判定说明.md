# 读者复述测试：判定与改写说明（10/15）

依据：`规则与交接/措辞审查流程.md` 第 3、4、6 节。六位无背景读者各读一组页面的全部文字（`R1.txt`…`R6.txt`），复述写在 `R1_复述.md`…`R6_复述.md`。原型：`推送系统后台集成需求/3_原型.html`；本意以原型与需求文档 `推送系统后台集成需求/4_需求文档.md` 为准。

## 判定
- 逐条看读者标为把握低、可能读偏、矛盾、冗长套话的句子，以及读者对标题和规则句的复述。
- 对照本意，只认三类：**读偏**（主语、对象、关系、程度、状态、指标含义有一项与本意不同）、**读不出**（要靠猜）、**看起来矛盾**。读者的其他追问，若同页或附录有答案，不改。
- 读者指出的矛盾先查事实：原型与需求文档真不一致的，按需求文档改原型；需求文档本身说不通的，不改，记进备注。
- 冗长、重复、套话：删；不为补主语加字，主体是运营的不写「运营」。

## 改写
- 标准照 `分析/标准判卷/推送后台_原型措辞/任务说明.md`，术语照同目录 `术语表.md`。改名会波及你负责范围以外的页时，不改，记进备注「跨页名称」，写清各处叫法与建议。
- 交 `改动_读者_<组>.json`（格式同任务说明），放在 `分析/标准判卷/推送后台_原型措辞/`；先运行 `python3 _scripts/pl_原型替换.py 检查 <json>` 到「问题 0 条」，不要运行「应用」，不要直接改 HTML（别的子任务同时在改别的页）。界面框里放不下的用短写法。
- 另写 `备注_读者_<组>.md`：判定表（读者原话摘要｜判定｜改法或不改的理由）、「跨页名称」、「需求文档问题」。
- 回复不超过 150 字：判为读偏、读不出、矛盾各几条，改了几条，跨页名称与需求文档问题各几条。
