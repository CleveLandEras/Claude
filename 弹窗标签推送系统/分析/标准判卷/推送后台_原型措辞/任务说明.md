# 原型措辞调整：任务说明（10/15）

依据：Dk 10/15「先把原型文件的措辞调整好，再说其他的」。
对象：`推送系统后台集成需求/3_原型.html`（静态 HTML 原型，后台界面用 HTML/CSS 画）。你只负责分到的段（按 `<section id="…">` 划分）。项目根目录：`/Users/decheng.huang/claude/弹窗标签推送系统`。

## 只改什么
- 只改措辞。不改事实、数字、规则、页面结构、版面；HTML 标签、class、id、CSS 不动。
- 范围：段内所有可见文字：章首、页标题与副标题、标注栏、必读层与折叠的查阅层说明、界面上的字段名、按钮、状态、提示文字、表头、图注。
- 不改：界面里给玩家看的示例文案（推送内文、弹窗文字、短信内容），保留原样。
- 发现事实不清、页与页矛盾、规则说不通的，不在这里改，记进「事实问题」。

## 标准
1. `规则与交接/写作标准_合并版.md` 第二部分第 4 组「措辞」（约第 107–133 行）全部条目，第 2 组「标题与观点」（约第 77–90 行）。
2. `规则与交接/措辞审查流程.md` 第 1、2 节的自查项，逐句过。
3. 名称以需求文档为准：功能名、页面名、状态名、字段名、推送方式名用 `推送系统后台集成需求/4_需求文档.md` 的叫法。原型与需求文档叫法不同的，改成需求文档的；需求文档本身前后不一或叫法不清的，不自己造新名，记进「建议改名」，写清各处叫法和建议用哪个。
4. Dk 定过的：专业、简洁、直接，不用口语、比喻、拟人；不出现内部编号与内部用语（如 D1、E3、B8、A 组、判例、判卷、「我方」）；一组集合名（如「六种推送」）第一次出现就写出成员；标题不重复同页卡片标题；并列的句子各占一行；行首不出现标点。
5. 简洁但不缺信息：删铺垫和重复，不为压字数省主语、对象。

## 怎么交
1. 改动写成 JSON：`分析/标准判卷/推送后台_原型措辞/改动_<段名>.json`，数组，每条 `{"old": 源码里的精确字符串, "new": 改后字符串, "why": 一句话原因}`。why 写对应的标准，如「成分不全：缺主语」「名称统一：按需求文档 4.1.3」。
   - old 原样取自 HTML 源码（含其中的标签与实体），在整个文件里只出现一次；不唯一就带上前后文。
   - 提交前运行 `python3 _scripts/pl_原型替换.py 检查 <你的json>`，直到「问题 0 条」。不要运行「应用」，不要直接改 HTML（主对话统一写入，别的段也在同时改）。
   - 同一个名字在段内多处要改，每处一条。
2. 另写 `分析/标准判卷/推送后台_原型措辞/备注_<段名>.md`，两节：「建议改名」（要动需求文档的）、「事实问题」；没有就写「无」。
3. 给主对话的回复不超过 200 字：改了几条；主要改了哪几类，各举一例「改前 → 改后」；建议改名几条；事实问题几条。
