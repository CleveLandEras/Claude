# 核心④ 一个入口：评审后改法（10/19 设计主线定）

依据：`评审_资深同行.md`（甲 2、乙 12、过度设计 4、还缺 6、外围 7）。原则：甲级全改；乙级、过度设计、还缺的，属「一个入口」且能让任务走通的改，属其他核心或外围的记细节表。需求文档 v0.9.47 → v0.9.48；新用例从 T730 起编。

## 改

| 评2 | 甲 2 | **切换期营销侧已排程以只读「外部排程」登记进本后台**：切换前营销侧未发完的一次性发送逐行登记（发送时刻、对象说明、条数、可选所属活动），在该推送方式列表与活动总览显示「营销侧发送 · 本后台不可改」；挂了活动的进改期与撤下清单，处理方式写「须到营销侧操作」并通知负责人；活动总览该行在有外部排程或「尚未切换」时不写「未配」，写「营销侧排程 N 条」，「＋新建」旁提示先核对；8.1 B08 最小版明写含「已排程清单逐行登记与标记，未标完不开开关」（按推荐，可推翻） | 迁移通行做法是切换窗口内冻结旧端新建、旧端已排程逐条登记到新端并标来源（评审）；Braze 接入 LINE 时关注者自动同步，同理把旧端排程同步进来才能在一处核对 |

| 评4 | 还缺 2 | **活动总览页头「上线前核对」**一行：项目仍为草稿、跳转目标未上架、未测试 N 条、测试后改过内容 N 条、渠道尚未切换或连接异常、合并组成员时间不一致、营销侧仍有同活动排程、建议挂入 N 条；每项可点到对应行；只提示不拦 | Airship 发送前 Review 步骤、Braze 建活动最后的汇总步骤都把核对集中一处；我们不设审批，所以做成提示 |
