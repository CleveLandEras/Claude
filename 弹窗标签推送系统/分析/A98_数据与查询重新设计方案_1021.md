## 二、体验问题

- P1 数字与明细分两页：看到概览数字变了，要换页才知道是哪一条推送引起的。
- P2 概览只有每个数字的小图，看不出涨跌是否与上限、勿扰、规则改动有关（位置数据页有改动标记，概览没有）。
- P3 叫法不一：数据页写「推送 46 · 已完成」「上架中」「ID 15」，列表写「#46 · 已结束」「生效中」「#15」。
- P4 单条数据页看不到这条现在的设置，要回编辑页对照。
- P5 玩家查询首屏是两张顺序表，客服要自己推断「为什么没收到」；顺序表看不出哪个此刻会弹、哪个因次数、冷却或每次最多弹出数而不弹。
- P6 弹窗顺序表的「弹窗活动 ID」「弹窗名称」与列表的「规则名称 #编号」叫法不同。

## 三、设计点（含参考出处）

| 设计点 | 解决 | 参考 |
|---|---|---|
| D1 概览与明细并一页：关键数字 → 每日走势 → 每条推送；页顶切层，时间范围整页生效 | P1 | Braze、OneSignal 活动分析页（数-38）；极光、个推数据概况分块（数-43） |
| D2 走势画所选期间连同对比前一段，竖线标上限与勿扰改动，前后各一段平均，图下列改动 | P2 | Amplitude 批注与 Releases（数-37）；Braze 变更日志（数-34） |
| D3 名称下一行「#编号 · 状态」，状态与列表一致，已结束写原因 | P3 | Shopify Polaris 同一对象各处同名 |
| D4 单条页顶「当前设置」一行 | P4 | Braze、OneSignal 单条报告页顶摘要（数-38） |
| D5 玩家查询首屏四张「能否收到」卡片 | P5 | 它-02（Braze 用户档案、OneSignal 订阅状态）；它-01（MoEngage Push Debug） |
| D6 弹窗按位置分组、按规则小标题，每个弹窗内容标所属规则与此刻状态，组顶一句「下次会弹哪几个」 | P5、P6 | 控-08（Pendo 补位、Braze 优先级）；控-09（每天上限、最小间隔） |

按 R1：列表、概览不加需逐条算的新指标；玩家查询的此刻状态只对一位玩家算，成本小。按 R2：说明常显（卡片结论、组顶一句、说明列）。按 R4：不贴「新」标签。按 R7：只改界面；概览走势用已有数据与已有的改动记录，没有新功能。
