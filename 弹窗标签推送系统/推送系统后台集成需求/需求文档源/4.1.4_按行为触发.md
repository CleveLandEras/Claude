#### 4.1.4 按行为触发

> 玩家发生指定行为时发给触发的玩家；适用于游戏外推送（推播、短信、Facebook、LINE）与游戏内推送的快显（决定 1）。
>
> 关键规则：没有固定的发送对象，预计人数按近 7 天平均；每次触发依次判断生效期间、群组、提醒次数与触发条件、可触达、勿扰、每人每天上限（v0.9.41：第 6 步按 4.1.1 五的发送前拦下顺序判全，含最小间隔、短信费用封顶、每周与合计上限、活动提醒类别上限、重要推送预留）；被上限拦下、勿扰放弃的不算一次提醒，也不起算间隔；（v0.9.42）同一触发的不同推送方式可放进同一合并组，按渠道顺序每次触发只发一则（本节「合并组」）；（v0.9.42）游戏外推送可选「玩家在线时：不发（由游戏内承接）／照发」，玩家行为类默认不发（本节「玩家在线时」）；活动事件中时间偏移的项目锚点与每日定点＋状态消息类别固定为营销，活动提醒只给玩家自身事件（4.1.7「活动提醒」）；礼包推播的切换开关（v0.9.50 起在迁入管理页，原在「推荐礼包设定」页）为「由礼包后台发送」时，触发行为为「限时加码礼包快到期」的推播不能进入运行中。

原型页 #4、#5、#10、#18；验收用例 T02、T14、T15、T30、T31、T38、T50、T55、T64、T81、T418（v0.9.28）；字段：[5.5](#s5-5)。

**核心逻辑**

| 项 | 规则 |
|---|---|
| 发送对象 | 固定为「触发的玩家」；「只限群组」建议默认值为「不限，触发即发」，可选标签群组；排除群组同立即、定时；（v0.9.44）游戏外推送四种可勾「发送前 N 小时内登录过的不发」（4.1.1 三），只限群组纳入部分「在」行含未登录型标签时默认勾（复评后改，原为组成含；（v0.9.45）按标签属性「未登录型」判断，原按名称识别；按行为的发送对象是触发的玩家，仍为 N 小时一种，不用「名单算出后」） |
| 预计人数 | 近 7 天平均每天：触发 → 排除后 → 可触达 → 勿扰时段放弃（或顺延）→ 频率上限拦下 → 预计发出；各步单位为人次（同一玩家一天触发多次计多次），预计发出人次即预计发出条数；没有固定的发送对象，不显示群组总人数；（v0.9.44）勾了「发送前 N 小时内登录过的不发」时可触达一层另扣近期已登录，按近 7 天各次触发时该玩家前 N 小时是否登录过估 |
| 生效期间 | 开始日期必填；结束日期选填，不填则长期运行（与弹窗规则一致）；填了则结束日 24:00 自动变为已结束。（10/16 夜补充）选了活动事件模板的项目时，建议默认值「跟随项目上架时间」：按项目时刻生效，项目时间变更时自动跟随（4.1.20）；（v0.9.47）未选活动事件模板、选了所属活动时，开始、结束可写成相对活动时间（例「开始时 – 结束后 1 天」），按时刻生效，活动改期时自动跟随（4.1.20「相对活动时间」，5.5 序号 39）；从活动总览新建时默认「开始时 – 结束时」 |
| 提醒次数 | 每次触发最多提醒 N 次，建议默认值 1；N 大于 1 时，后续提醒在间隔到达且触发条件仍成立时再发 |
| 间隔 | 同一玩家两次提醒（不论是否同一次触发）至少间隔 N 小时，建议默认值 24<br>• （v0.9.41）「提醒过一次」只算受理（受理后退回、结果不明也算，避免重复）；被频率上限拦下、勿扰放弃、短信费用封顶等发送前拦下的，不算一次提醒，也不起算间隔，下次触发仍可提醒<br>• （v0.9.41）间隔从上一次受理时刻起算，不从触发或判断时刻起算<br>• 对标：Braze re-eligibility 按「收到」算资格，触发了没收到的下次仍有资格（[Re-eligibility](https://www.braze.com/docs/user_guide/engagement_tools/campaigns/building_campaigns/delivery_types/reeligibility/)）；MoEngage 事件触发活动按滑动窗口内最多 N 条（[Limit messages](https://moengage.com/docs/user-guide/settings/channels/delivery-controls/limit-messages-for-periodic-and-triggered-campaigns)）；我们相同 |
| 勿扰处理 | 建议默认值「放弃发送」，单条可改为「顺延到勿扰结束」（选项文字写当前结束时刻，同 4.1.3.2）；可单独勾选「本条不受勿扰」并填原因（同 4.1.3.2，v0.9.28 改）；按每次触发时刻判断（4.1.7「判断时点」）；放弃的记「勿扰时段放弃」，计入拦下与未送达原因（决定 6） |
| 玩家在线时（v0.9.42） | • 选项：不发（由游戏内承接）／照发；只游戏外推送四种，快显不显示（快显本来只发在线玩家）<br>• 建议默认值按触发行为：触发行为发生在游戏内的玩家行为类（玩家升级、完成任务、通行证升级；（v0.9.44）破产后未回到游戏）默认不发；时间到期类（限时加码礼包快到期、时间偏移、排名变化、每日定点＋状态）默认照发；之后新登记的事件默认照发，运营按需改选<br>• 判断：选不发时，对此人提交服务商前按服务端在线状态（长连接在线即算在线）判断，即判断顺序第 4a 步；勿扰顺延、间隔顺延的到点再判<br>• 不发的记「在线不发」：算受众，计入拦下与未送达原因（单条推送数据多一行「在线不发 N」），不算一次提醒、不起算间隔、不占每人每天上限；下次触发时不在线照常发<br>• 合并组里按渠道顺序取中的那条在线不发时，不改走下一顺位（同「只在不可触达时补位」）<br>• 游戏内承接检查：保存时检查游戏内承接：同一触发行为有运行中或已排程的快显，或有落地同一项目的运行中弹窗规则，才算有承接；没有承接时保存处提示「同一触发没有游戏内承接，玩家在线时这次什么都收不到」，可改为照发或仍保存，仍保存的在列表与编辑页标「无游戏内承接」；承接的快显、弹窗停止或到期时，其停止确认框列出靠它承接的按行为推送，这些推送同样标「无游戏内承接」。为什么：没有承接时在线玩家什么都收不到，选不发就成了漏发<br>• 预计人数：选不发时「确认与测试」块在可触达后加一层「在线不发」，按近 7 天各次触发时刻该玩家的在线状态估<br>• 已运行的按行为推送升级后取「照发」，原有发送不变<br>• 例：玩家 12:00 在线时通行证升级，快显「通行证升级提示」照常显示，推播「通行证升级奖励提醒」记「在线不发」<br>• 为什么：玩家正在游戏里时，推播与同一事件的快显、弹窗同时到；以后登记破产事件时，破产推播与破产弹窗也会同时到；在线玩家不发营销推播是游戏运营常见做法，服务端已有在线状态<br>• 立即、定时的在线不发仍为后续（3.5）<br>• 成本：小改动（提交前读在线状态；字段 5.5 序号 36）；原型页 #4（注 7）、#15；T574、T575 |
| 确认 | 按钮为「确认启用」，确认后为运行中，生成版本 1 |

（v0.9.44）破产后未回到游戏：<br>
• 三种做法分工：玩家在游戏里破产 → 破产位弹窗（4.2.1）；破产后离开 → 本触发；每天定时给近 7 天破产过的人 → 群组「近 7 天发生过破产」（4.3.3）<br>
• 为什么按「离开 N 小时」而不是「破产即推」：在游戏里破产的人由破产位弹窗承接，离开后才需要游戏外推送；原写法下破产后几分钟内推两条路都走不通（按行为没有破产触发，群组按前一自然日算）<br>
• 「玩家在线时」建议默认值为不发；判断顺序第 3 步「触发条件仍成立」即到点此人仍未回到游戏<br>
• 对标：数数 TE 触发型任务可在事件后延迟推送，Braze Canvas 延迟步骤配合退出条件（回来即退出）（4.3.9）<br>
• 成本：小改动（破产事件已有，排检查同限时加码礼包；字段 5.5 序号 3、36、37）

**异常与边界**

| 场景 | 处理 |
|---|---|
| 同一事件重复上报 | 按事件唯一标识去重（如同一礼包实例、同一次升级），只触发一次 |
| 事件处理时条件已不成立 | 例：礼包已到期，或玩家已不满足「尚未购买该礼包」；按第 3 步不算受众，不发 |
| 暂停期间的触发 | 不判断、不计受众；恢复后不补发 |
| 生效期间开始前已确认启用 | 状态为运行中；开始前的触发按第 1 步不算受众 |
| 编辑保存新版本时正在处理的触发 | 以触发时刻的有效版本为准 |
| 触发条件不完整、生效开始日期未填 | 校验不通过，「确认启用」不可点，列出未通过项 |
| 事件服务中断 | • 中断期间的事件在恢复后补处理时，仍按第 3 步重新判断条件；条件不成立的不发<br>• （10/16 夜补充）触发时效：从触发到开始处理超过 30 分钟（暂定；推播不超过有效期）的放弃，记「触发已过期」<br>• （10/16 夜补充）补处理时刻在勿扰时段内的一律顺延到勿扰结束，不论该推送勿扰处理选顺延还是放弃（第 9 章运营 29）；结束时重新判断第 3 步与第 6 步<br>• （10/16 夜补充）补处理按触发时间先后，受服务商限速（4.1.1「八」4）<br>• （10/16 夜补充）单条推送数据拦下原因多一行「触发已过期 N」；告警 4 文案注明「事件积压补处理中」<br>• 运行中满 24 小时没有触发的推送列入总览待处理「按行为异常」（4.1.2） |
| 按行为推送的失败 | • 每次触发的失败按 4.1.1 自动重试<br>• 手动重试只在单条推送数据页的「服务商未受理」区，范围为自动重试结束不超过 24 小时、且触发条件仍成立的人次，例：37 人次超时中可重发 9 人次<br>• 不按失败列入总览待处理与列表「有失败可重试」；近 1 小时提交的全部未受理时列为待处理「按行为异常」（4.1.2） |
