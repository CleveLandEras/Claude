#### 4.3.5 条件说明

| 字段 | 规则 |
|---|---|
| 条件说明 | 新建标签必填；存量标签由维护人补，未补时显示「未填写条件说明」，不拦截使用。（v0.9.44）日更标签在说明里写进出时点，例「每日 06:00 算，数据截至前一日；当天首储的人次日离开」；存量标签补条件说明列为上线前验收项：各维护人补完，未补的列清单（7.3、第 9 章运营）；成本：写定 |
| 未登录型（v0.9.45） | 标签加属性「未登录型」（是／否，5.23 序号 34），条件说明里写明。名单为一段时间未登录的人为是（「N 天未登入」类、「回流前」类、新增·注册次日未再登录、新增·注册第 3 天未再登录），例「未登录型：是。名单为注册当天之后未再登录的人」；新建标签必选，存量标签由维护人随条件说明补，未补的按否并列清单；推送「近期已登录不发」按它默认勾（群组「在」行含时，复评后改），并按此人命中的未登录型标签定起点（4.1.1 三）。原按名称识别未登录型，标签字段里没有这个属性（资深同行评审甲 1），改 |
| 时间窗、数据来源 | 选填 |
| 维护人 | 必填 |
| 规范名称 | 选填；改名不改脚本，已引用的群组与规则不受影响。（v0.9.44）标签有规范名称时，群组下拉与组成处显示规范名称、原名灰字；（v0.9.45）机翻或语义不明的存量标签上线前须补规范名称，与条件说明一起列入上线前验收（7.3）；原全为选填，这些标签照原名进下拉，选错率降不下来（资深同行评审乙 10），改 |
| 群组说明（v0.9.44） | 群组加「说明」，选填，200 字内（5.23 序号 28）；推送、弹窗的群组下拉选项显示说明首句，群组组成展开处显示全文。为什么：同类群组名称相近（如潜在流失两档与单档），只看名称选不准；成本：写定；（v0.9.45）在用的存量群组（被上架规则、已排程或运行中推送引用）上线前须补说明，列入上线前验收（7.3）；原为选填，存量群组没有说明首句，同上改 |
| 显示 | 推送新建页与弹窗编辑页展开群组组成时，每个标签后显示条件说明。（v0.9.44）另显示每个标签「数据截至 10/12（每日 06:00 算）」与群组「批次 10/12 15:25」两项（4.3.1「标签计算状态」）；（v0.9.45 改）群组状态统一三级：正常／可用但名单较旧（黄，写最近成功时间与原因，例「可用但名单较旧：本批失败，沿用 10/12 14:40 名单」「可用但名单较旧：名单已过期（某标签最近成功 10/12 06:00）」）／已暂停（红，写原因与一个处理按钮，例「已暂停：人数骤降 16,564 → 0（10/16 19:35 批次）［确认采用新批次］」「已暂停：名单过期超过 24 小时，引用的推送已暂停［查看群组］」）；新群组首批算完前另显示「待计算」（不可选，不属异常）。具体判定（标签失败、过期时长、可疑批次阈值）留在 4.3.1、4.2.1「下发与显示的异常处理」6 与暂定参数表，界面只显示三级与原因（5.23 序号 31）。原按五种写（「本批失败，沿用 10/12 名单」「名单已过期」「今日名单未出」「待计算」「可疑批次」），运营要记五种状态、三档过期与两套阈值，只需知道能不能用、为什么、要做什么（资深同行评审过 2），改 |
