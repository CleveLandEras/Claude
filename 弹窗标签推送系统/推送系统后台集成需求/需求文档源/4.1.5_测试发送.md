#### 4.1.5 测试发送

> 确认前把表单当前内容发给测试账号，按账号逐行看结果；适用于游戏外推送（推播、短信、Facebook、LINE）与游戏内推送的快显。
>
> 关键规则：最多 10 个账号，只能从测试账号白名单选；不计入每人每天上限与任何数据；不受勿扰限制；按行为推送不等触发条件；每次测试发送记入操作纪录（v0.9.28）。（v0.9.47）测试账号在本后台维护（上限 50）；每次测试存为测试记录；确认块常驻测试状态，没测不拦；六种页面的测试入口都在底栏同一位置。

原型页 #3、#4、#6、#7、#10、#16；验收用例 T01、T33、T64、T65、T416（v0.9.28）；字段：[5.9](#s5-9)。

**核心逻辑**

| 项 | 规则 |
|---|---|
| 测试名单 | 下拉选测试名单，建议默认值为现有标签群组「运营测试组」（4 人）；也可选其他登记为测试名单的标签群组；（v0.9.28）测试名单的成员须都在测试账号白名单内，不在的成员不发，结果写「不在测试账号白名单」 |
| 会员编号（v0.9.28 改） | 只能从测试账号白名单选：输入会员编号或账号名称时按白名单联想，选中后加入；白名单外的编号标红「不在测试账号白名单，不能加入」，不计入 10 个；不能输入任意会员编号 |
| 测试账号白名单（v0.9.28；v0.9.47 改为在本后台维护） | • 登记的测试账号（会员编号），与固定排除「机器人与测试账号」中的测试账号为同一份登记，真实玩家不在其中；（v0.9.47）界面上称「测试账号」<br>• （v0.9.47 改，原「增删由研发按运营申请在系统配置操作（第 9 章研发 8）」）在测试面板「管理测试账号」增删，见下方「管理测试账号」；上线时由研发把系统配置里现有名单一次性迁入，之后不再在系统配置改（第 9 章研发 95）；每次增删记操作纪录：操作人、会员编号、原因<br>• 测试发送处显示，例「测试账号 12 个 · 管理 ›」 |
| 数量上限 | 测试名单人数＋会员编号合计最多 10 个账号；超出时不能再加，并写明「最多 10 个账号：已选 10 个（测试组 4 个＋编号 6 个）」 |
| 发什么 | 直接发表单当前内容（未保存的也发）；按行为推送不等触发条件 |
| 不计入 | 不计入每人每天上限，不计入任何数据，不受勿扰限制 |
| 操作纪录（v0.9.28 改） | 每次测试发送记一条，操作为「测试发送」：操作人、时间、推送方式与对象（推送 ID 与名称；未保存的写「未保存的草稿」）、测试账号（会员编号）、内容摘要（标题与内文前 30 字；短信另写则数） |
| 结果 | • 按账号与设备逐行列出：已送达，或未送达及原因（例：「测试03　iOS　未开启通知」「测试03　未送达：没有手机号」「测试02　未送达：未绑定 Facebook」）<br>• （v0.9.40 改）iOS 推播按通知服务扩展的到达上报写「已送达」；测试设备为未接入版本（旧版本 App）的，服务商受理即写「已发出（未接入到达上报）」，不写「已送达」，也不等 60 秒后写「无回执」；Android、短信、Facebook 按回执写「已送达」；（v0.9.40）LINE 测试走逐人推送，没有逐人到达，服务商受理即写「已发出（LINE 无逐人到达）」，不写「已送达」，也不写「无回执」<br>• 快显为「已显示」或「未显示：账号不在线」<br>• 顶部写发送时间与对象，例：「10/12 11:12 发出 · 运营测试组＋1 个编号」 |
| 时机 | 新建表单与编辑页都能发；测试在确认之前 |
| 入口位置（v0.9.47） | 推播、短信、Facebook、LINE、快显、弹窗六种页面都在底栏同一位置：「存为草稿」右侧、确认按钮左侧；游戏外四种与快显为「发送测试」，弹窗为「测试预览」（4.2.1）；点后打开同一个测试面板：选账号、发送、逐行结果、「测试记录」页签。推播页第 5 块（确认与测试）不再放按钮，只显示测试状态与上次结果（原型页 #3、#4、#6、#7、#9、#10） |
| 管理测试账号（v0.9.47） | • 测试面板「管理测试账号」：有「测试账号管理」权限的运营账号可增删（建议默认授予运营负责人，4.1.11），其他角色只看<br>• 上限 50 个；满 50 时「新增」置灰，写「已达 50 个，先移除不用的」<br>• 每个账号一行写它在六种推送上能不能收：推播 Android／iOS（有有效设备令牌且开启通知）、短信（有效手机号且未退订）、LINE（已加好友且未封锁）、Facebook（已绑定；是否在 24 小时窗口内）、弹窗与快显（最近在线时间）；收不到的写原因，例「测试03 · 推播 iOS：未开启通知」<br>• 新增：输入会员编号，显示账号名称、近 30 天登录与储值；确认框写「加入后该账号算机器人与测试账号固定排除，不再收到正式推送与弹窗」；近 30 天有储值的标黄「疑似真实玩家，请确认」，不拦；原因必填，最多 100 字<br>• 移除：确认框写「移除后该账号恢复为正式推送与弹窗的对象」；已有测试记录保留<br>• 测试名单（标签群组，如「运营测试组」）的成员仍须都在测试账号内（上方「测试名单」） |
| 测试记录（v0.9.47） | • 每次发送测试、测试预览存一条：时间、操作人、推送方式、推送 ID 或规则 ID 与当时版本号（未保存的写「未保存的草稿」）、内容摘要、每个账号的结果（已送达、已发出、已显示、已弹出、未送达及原因）<br>• 在单条推送（编辑页测试面板「测试记录」页签、单条推送数据页）、弹窗规则（编辑页测试面板）与活动总览（「测试」列，4.1.20）可查；随推送、规则长期保留<br>• 不计入正式数据：不进发送、到达、曝光、每人每天上限、数据看板与玩家查询收到记录 |
| 测试状态（v0.9.47） | • 确认与测试块标题下常驻一行（不占「提示」级三条名额）：没测过写「本条尚未发送测试」；测过写「上次测试 10/22 18:05 · 3／3 已收到」；有失败写「上次测试 10/22 18:05 · 2／3 已收到（测试03 推播 iOS 未开启通知）」；上次测试后改过推送内容块的写「上次测试后改过内容，建议重测」<br>• 「已测试」＝上次测试后推送内容块没改过，且至少 1 个账号收到（已送达、已发出、已显示或已弹出）<br>• 没测不拦，不设审批；高风险确认框里同样列一行测试状态（4.1.3.2「高风险确认」）<br>• 列表与活动总览的「测试」状态同口径：已测试／未测试／有失败／测试后改过内容；未测试标黄 |

**交互流程**

1. 在确认与测试块选测试名单，或输入会员编号。
2. 点「发送测试」，按钮转为发送中状态。
3. 结果随回执逐行更新；60 秒后仍没有回执的写「无回执」（iOS 未接入版本与 LINE 没有逐人到达，受理即写「已发出」，不进这一步，v0.9.40）。

**异常与边界**

| 场景 | 处理 |
|---|---|
| 会员编号不存在或不在白名单（v0.9.28 改） | 该编号标红「不在测试账号白名单，不能加入」，不计入 10 个 |
| 重复编号 | 自动去重 |
| 测试账号不可触达 | 照常尝试，结果写原因（未开启通知、没有手机号、未绑定 Facebook、未加 LINE 好友、账号不在线） |
| 内容校验未通过 | 内容块必填项未填时不能发测试；其余块未通过不影响测试 |
| 短信测试 | 按则计费，测试结果旁写本次则数 |
| 文案变量 | 用测试账号的实际值；取不到时用替代文字 |
| 测试账号已注销、停权（v0.9.47） | 「管理测试账号」该行标红「已注销」或「停权」，选不了；不自动移除，由有权限的人移除 |
| 两人同时增删同一测试账号（v0.9.47） | 只成功一次，后操作的看到「已由运营01 于 15:20 加入」 |
| 发送测试后又改了内容（v0.9.47） | 测试记录按发送时的内容存；测试状态改为「上次测试后改过内容，建议重测」 |
| 测试账号被移除时正在测试（v0.9.47） | 已发出的结果照常回填；之后不能再选该账号 |
