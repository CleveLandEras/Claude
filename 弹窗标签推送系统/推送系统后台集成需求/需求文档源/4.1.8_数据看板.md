#### 4.1.8 数据看板

> 两层推送数据的统计方法与缺数写法，以及数据看板页：概览（关键数字与上一周期比较、按日趋势、按推送方式、五类人群对比、表现最好与最差），按人群、日期查看并导出，另列拦下与未送达原因、推送明细。
>
> 关键规则：游戏外推送从发送算起，点击率＝点击÷发送，到达率＝到达÷可确认发送；游戏内推送从曝光算起，点击率＝点击÷曝光；每个数的来源、预期延迟与统计窗口见「指标来源表」；拿不到的数按「拿不到的数据怎么写」写原因，不写 0、不估算；与对比期比较时数量写增减百分比，比率写增减百分点。（v0.9.40 改）（10/18 资深同行评审后）游戏外比率只按推送方式给，概览关键数字、按日趋势、日报与周报正文不出五种推送方式的合计比率；对比期含某推送方式切换到本后台之前的日期时不比较。

**统计方法**

| 层 | 指标 | 怎么算 |
|---|---|---|
| 游戏外推送 | 发送 | 服务商受理的条数，含受理后退回的；服务商未受理的（超时、临时错误、当场拒绝）与结果不明的不计入；测试发送不计入；（v0.9.40）「已提交」含在途，不等于发送（4.1.1「术语」） |
| 游戏外推送 | 到达 | 确认到达的条数；（v0.9.40）来源按推送方式见下方「指标来源表」：推播 Android 客户端回执、推播 iOS 通知服务扩展上报（已接入版本）、短信运营商回执、Facebook 送达回调、LINE 窄播按请求取的已送达人数 |
| 游戏外推送 | 到达率 | （v0.9.40 统一）到达 ÷ 可确认发送；可确认发送＝发给有到达回传对象的条数：推播 Android 全部、推播 iOS 已接入版本、短信、Facebook、LINE 窄播发送；各页到达率旁统一写「分母只含可确认到达的发送，另列未接入、不回传 N 条」（原各页分别写「不含 iOS」「不含推播 iOS、LINE」「仅 Android」，三种分母，已统一）；（10/18）LINE 窄播发送在已送达人数出数前（待汇总）不计入分母，同处另列「待汇总 N 条」，出数后计入，今日与含当天的期间同此（同 iOS 未接入的处理）；推播 iOS 到达率旁另写「已接入占比」（见下方） |
| 游戏外推送 | 已接入占比（推播 iOS，10/18） | 发给已接入通知服务扩展版本的条数 ÷ 推播 iOS 发送条数；写在推播 iOS 到达率旁（按推送方式表、单条推送数据），说明 iOS 到达率只代表已接入的版本；升级比例变化会让 iOS 到达率趋势漂移，看趋势时一并看此项 |
| 游戏外推送 | 到达人数（10/18） | 所选范围内至少有 1 条确认到达的玩家数，按玩家去重，跨推送方式也去重；与档期汇总「确认到达（去重）」同口径；从逐人发送明细算，查询范围超过逐人明细保留期 30 天时写「—」，注明「超过逐人明细保留期」 |
| 游戏外推送 | 曝光 | 不显示；游戏外推送只看发送、到达、点击，各页曝光列只填游戏内推送，游戏外推送写「不适用」或不设该列 |
| 游戏外推送 | 点击 | （v0.9.40 统一）主口径「点击（条）」：点开推送或点了推送里链接的条数，每条发送最多计 1，同一条消息点多次计 1（逐人发送明细只记首次点击时间，推播回传按 deliveryId＋event 去重）；按行为、重复的定时同一玩家收到两条各点一次计 2。另列「点击人数」，按玩家去重，跨推送不相加；（10/18）点击人数从逐人发送明细算，查询范围超过逐人明细保留期 30 天时写「—」，注明「超过逐人明细保留期」。原「点击（人）」不再用 |
| 游戏外推送 | 点击率 | 点击条数 ÷ 发送条数；不用点击 ÷ 到达：推播 iOS 未接入版本与 LINE 逐人推送没有单条到达，用到达作分母各推送方式不可比（v0.9.40 改写原因） |
| 游戏外推送 | 跨推送方式的比率（10/18 资深同行评审后；10/18 最后对齐推到所有表） | 概览关键数字、按日趋势、日报与周报正文不给五种推送方式的合计到达率、合计点击率，只给数量（发送、到达、点击、到达人数）；比率按推送方式给（概览「按推送方式」表，各带较对比期）。各表跨推送方式的行同样只给数量：合计行（按推送方式、按发送小时、按跳转类型）、档期汇总的档期一行与「未设档期」一行、合并查看的合计行，游戏外到达率、点击率格写「—」，表下写一句「比率只在同一推送方式内比较」；五类人群对比、按人群（含任选群组并排）、周报五类人群小表的人群行，游戏外只给发送、点击（条），按人群另按推送方式分列点击率；推送方式筛选选定单一推送方式时，这些行照常显示该推送方式的到达率、点击率。本条是唯一定义，各表引用本条。原因：五种推送方式的到达来源与点击口径不同（见「指标来源表」），合计比率随各推送方式的发送占比漂移，与对比期比会把占比变化读成效果变化 |
| 游戏外推送 | 发送后登录 | （v0.9.30 由只有短信扩到推播、短信、Facebook、LINE）本条推送被服务商受理的玩家中，受理后 N 小时内登录游戏（App 或网页）的人数，按玩家去重；N 由运营在页面设定（建议默认值 24 小时，1–120 小时，不超过统计窗口 5 天）；另显示占比＝登录人数 ÷ 发送人数，分子分母都按玩家去重；（v0.9.40）起点统一写「受理后 N 小时」；同一玩家 N 小时内收到多条推送时，一次登录各条各计；（10/18 评审后改，原跨推送直接相加、合计处注明会重复）跨推送汇总的格（按推送方式各行与合计行、按人群、按日期、档期、合并查看）不把各条人数相加，写按玩家去重的人数：收到其中任一条、并在该条受理后 N 小时内登录的玩家计 1，占比的分母同样为去重后的发送人数；从逐人发送明细算，查询范围超过逐人明细保留期 30 天时写「—」；统计时长未满写「统计中 · 剩 N 小时」；统计时长满后固化 24 小时、72 小时两个数进汇总长期保留（见下方「保留」）。短信效果按这一项看：玩家收到短信后多直接打开 App 或网页，不点短信链接，点击会偏低。推播、Facebook、LINE 的发送后登录只作后台数据，效果仍按点击，不看登录 |
| 游戏外推送 · 储值类 | 发送后付费（v0.9.30） | 点击跳转类型为礼包或商城的推送（储值类，按跳转类型自动判定，不另设字段）：被服务商受理的玩家中，受理后 24 小时内有储值记录的人数（按玩家去重）与储值金额合计（转账不算）；不论是否经推送进入；只在单条推送数据显示（4.1.9），只作后台数据，不作效果判定与指标，不进目标、验收与对照 |
| 游戏内推送 | 曝光 | 弹出或显示 1 次计 1，按客户端显示后的上报计，已返回或已下发、未上报的不计；被频率上限拦下的不弹出、不显示，不计曝光 |
| 游戏内推送 | 点击 | 点了弹窗或快显的次数，每次曝光最多计 1（v0.9.40 补，同 4.1.1） |
| 游戏内推送 | 点击率 | 点击 ÷ 曝光；没有发送、到达两步 |
| 游戏内推送 | 受众、可触达 | 快显：受众为排除后的发送对象（立即、定时）或触发人次（按行为）；可触达为发送时在线的，快显漏斗各步见 4.1.9「漏斗」（v0.9.40）。弹窗在看板上从曝光算起；单条弹窗规则数据另有目标人数、进入该弹窗位置、符合条件三步（4.1.16） |
| 游戏内推送 | 曝光人数 | 有曝光的玩家数，按玩家去重；从逐次显示明细算，查询范围超过保留期 30 天时写「—」并注明「超过逐次明细保留期」；游戏内点击人数同此（10/18） |
| 两层 | 较对比期（v0.9.40 改，原「较上一周期」） | 对比期三选一：上一周期＝所选日期之前、天数相同的一段（例：近 7 天 10/06–10/12 对 09/29–10/05）；上周同一天（10/18 改名，原「上周同期」）＝所选日期各往前推 7 天，选单日时即上周同一星期几，选多日时为上周同一段；不对比。（10/18 资深同行评审后）默认：选单日时默认上周同一天，选多日（近 7 天、近 30 天、自定义多日）时默认上一周期；比较方式默认同龄，「只比窗口已满的部分」收在对比下拉的「高级」里（见下方「窗口未满与同龄比较」）。数量（发送、到达、点击、到达人数、曝光、曝光人数）写增减百分比，比率（到达率、点击率）写增减百分点；游戏外按同龄比较；对比期没有数据时写「—」<br>• 切换前不比较（10/18 资深同行评审后）：对比期含某推送方式切换到本后台之前的日期时（切换时刻取切换开关由原后台改为本后台的时刻，5.19 序号 8–11，与玩家查询「由谁发送」同源），该推送方式行的「较对比期」写「切换前由营销侧发送，不比较」（推播写「切换前由原处发送，不比较」）；含该推送方式的合计数（概览关键数字、合计行、五类人群对比、档期）同样不比较，写「含切换前日期，不比较」；切换前的数据不导入看板（见下方「异常与边界」） |
| 两层 | 差异显著性（10/18 资深同行评审后） | 两组并排比较比率时（游戏外、游戏内推送数据的任选标签群组并排，单条弹窗规则数据的实验组与对照组），每组写样本量（即比率的分母：游戏外点击率为发送条数、到达率为可确认发送条数，游戏内点击率为曝光次数、点击人数占比为曝光人数），差值按两比例检验（95% 置信）判断，不显著时差值旁写「差异不显著」；游戏外只在同一推送方式内比（逐推送方式各检验一次，不检验跨推送方式的合计比率，见上方「跨推送方式的比率」），某推送方式一组未发送时写「不比较」；任一组样本少于 1,000 时置灰写「样本不足」，不判断（10/18 最后对齐按原型改，原写 500；门槛同「表现最好与最差」的 1,000）；多于两组时各组与第一组比。例（原型页 #12）：潜在流失·实验组对对照组，推播 4.9% 对 4.7%（发送 3,000 对 3,340），+0.2 个百分点，差异不显著；短信 2.1% 对 1.9%（2,880 对 3,100），差异不显著；Facebook 610 对 600 条，样本不足；LINE 对照组未发送，不比较 |

**异常与边界**

| 场景 | 处理 |
|---|---|
| 所选范围没有任何发送 | 关键数字写「未发送」，按推送方式表各格写「未发送」，推送明细显示「所选日期内没有推送」 |
| 对比期没有数据 | 「较对比期」写「—」，不写 0% 或 100% |
| 表现最好与最差某推送方式不足 2 条（10/15 夜补充） | 只有 1 条时只写较均值，不分最好最差；没有满足条件的写「所选日期内没有发送满 24 小时且不少于 1,000 的推送」（游戏内写「曝光不少于 1,000」） |
| 自定义日期超过 1 年 | 提示缩短范围 |
| 导出量大 | 导出为后台任务，完成后在页面右上提示下载；导出文件保留 7 天 |
| 只读角色 | 数据照常显示；只导出汇总数据，名单与逐人明细不能导出（v0.9.30）；不显示「重试失败部分」「复制并改发送对象」 |
| 切换前的历史数据 | 营销侧发出的短信、Facebook、LINE 与礼包后台发出的推播不导入看板（见 4.2）；（10/18 资深同行评审后）对比期含切换前日期时不比较（「统计方法」较对比期），按日趋势标切换竖线，告警基线不足 7 天先不判断（「告警」）；导入切换前日汇总作对比基线本期不做，要数据平台导数，研发评审再定 |
