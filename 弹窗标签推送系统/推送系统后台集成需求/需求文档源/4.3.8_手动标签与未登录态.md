#### 4.3.8 手动标签与未登录态（10/16 夜补充）

| 规则 | 内容 |
|---|---|
| 现状 | 游戏标签每周一 00:00 重算，会冲掉运营批量打的手动标签；营运为避免回流后近一周无标签空窗而手动打标（Jira 二轮 RICH-16683）。配了排除对象后，未登录玩家看不到「全部玩家」Banner（RICH-17970） |
| 手动标签有效期 | 标签值分自动计算、手动两种来源；手动打标须填有效期（1–90 天，建议默认值 14 天）；有效期内重算不覆盖，同一玩家同一标签以手动值为准；到期后回到自动计算值；标签详情显示「手动 N 人 · 最早到期 MM/DD」（5.23 序号 16–17） |
| 批量手动打标 | 沿用现有批量导入（单次上限 3,000 个会员编号，不存在的过滤并逐个列出）；改动记入变更记录（4.3.7），写异动原因 |
| 名单另存为手动标签（v0.9.44） | • 推送发送对象「名单」区可「另存为手动标签」（4.1.1「名单」）：填标签名称与有效期（1–90 天，同本节「手动标签有效期」），按名单中有效的会员编号新建一个手动标签<br>• 走现有批量导入：单次 3,000 上限，超出的由系统自动分批导入，全部完成后标签才可选；导入结果与无效编号同批量导入逐个列出；记变更记录，异动原因默认「由推送 ID N 的名单另存」<br>• 存后可在标签群组设定里与其他标签、群组组合（例「名单标签 且 回流」），给弹窗、快显与其他推送使用；新建的手动标签没有自动计算值，到期即为空<br>• 本条推送仍「只用于本条」，不受另存影响（3.5）<br>• 为什么：一次性补偿名单常要再给弹窗或下一条推送用，原只能重新上传；复用借现有手动标签，不另建名单库<br>• 对标：Braze CSV 导入后可作筛选条件与其他条件组合，CleverTap、OneSignal 上传名单可成为可复用分群（4.3.9）<br>• 成本：小改动 |
| 未登录态 | 没有会员编号的请求：对象为「全部玩家」的照常命中，排除群组与固定排除不生效（无身份，无从命中）；对象为标签群组的不命中。弹窗、快显、游戏外推送都按会员下发，不受影响；本条约束与弹窗共用人群与排除的站内位（如大厅 Banner） |
| 成本 | 写定（由标签系统实现） |
