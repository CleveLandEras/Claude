#### 4.2.2 推荐礼包设定的推播迁移

> 礼包后台的「限时加码礼包未购买提醒」改由推播页的一条按行为推播发送；运营在迁入管理页（原型页 #17）切换、切回、改范围与验收，「推荐礼包设定」页只显示迁入状态与「去迁入管理」链接（原型页 #18）。（v0.9.50 改，原写「运营在「推荐礼包设定」页用切换开关切换」，因试点要验证迁入管理的切回与验收单，改）
>
> 关键规则：切到「由推送统一后台发送」须选定一条触发行为为「限时加码礼包快到期」、状态为草稿或已暂停的推播；切回「由礼包后台发送」时，同一触发行为的运行中推播全部变为已暂停。

原型页 #4、#17、#18（v0.9.50 加 #17）；验收用例 T02、T46、T439（v0.9.30）；字段：[5.13](#s5-13)、[5.19](#s5-19)。

| 项 | 内容 |
|---|---|
| 现有逻辑 | 礼包后台 › 推荐礼包管理 › 「推荐礼包设定」页设「限时礼包未购买推播时间：还剩 2 小时」与「标题：最後提醒⚠️幸運加碼禮包」；礼包后台直接发推播，数据在推播报表 |
| 存在问题 | 推播只能在这里配；能否按标签群组选对象待查，不能时在本后台按标签发；不受每人每天上限；数据没有到达 |
| 修改点 | • （v0.9.50 改）切换开关「限时加码礼包未购买提醒由哪里发」（由礼包后台发送／由推送统一后台发送）放在迁入管理页该项（原型页 #17），切换、切回、改范围、验收都在那里做；本页只显示「已迁入推送统一后台 · 推播 ID 31」与「去迁入管理 ›」链接，推播时间与标题只读（原型页 #18）。原写「页面加切换开关」，因试点要验证迁入管理的切回与验收单，改<br>• 开关为「由推送统一后台发送」时页顶显示迁移提示条「推播已迁到推送统一后台：推播「限时加码礼包未购买提醒」（ID 31）　前往推播页 ›」，推播时间与标题两项改为只读，礼包后台停止发送这条推播<br>• 其余设定（出现时间、冷却、准入、加码）不变，仍在本页设 |
| 兼容性 | 原设置逐项对应到选定的推播（见下方「原设置与推播的对应」），迁移不丢设置；迁移前的推播数据留在原推播报表，不导入数据看板；选定推播的设置摘要写「由礼包后台迁入」 |
| 变更影响范围 | 礼包后台（迁入状态与「去迁入管理」链接（v0.9.50 改，原「切换开关」）、只读、停止与恢复发送、发出限时加码礼包出现事件、提供礼包购买状态查询）；推播页；迁入管理页（v0.9.50）；操作纪录 |

**切换流程**

（v0.9.50）下列操作都在迁入管理页该项做，下文「本页」均指迁入管理页该项；推荐礼包设定页只显示状态与链接。原写在推荐礼包设定页做，因试点要验证迁入管理的切回与验收单，改。

| 操作 | 条件 | 同一事务里发生什么 |
|---|---|---|
| 切到「由推送统一后台发送」 | • 须选定一条推播：触发行为为「限时加码礼包快到期」，状态为草稿或已暂停<br>• 下拉只列出符合的推播<br>• 没有符合的推播时开关不能切，提示「先在推播页建一条触发行为为「限时加码礼包快到期」的推播并存为草稿」<br>• 选定的是草稿时须通过确认启用的校验 | • 礼包后台推播时间与标题改为只读、停止发送<br>• 选定的推播变为运行中（草稿生成版本 1；已暂停的恢复），`migratedFrom` 设为 GIFT_BACKEND<br>• 开关记下关联推播 ID 与切换时间（例：10/02 10:12 选定 ID 31） |
| 切回「由礼包后台发送」（回退） | 随时可切 | • 触发行为为「限时加码礼包快到期」、状态为运行中的推播全部变为已暂停：关联推播，以及开关为「由推送统一后台发送」期间另建的同一触发行为推播（已暂停、已结束的不变）<br>• 每条各记一条操作纪录「暂停」，操作人为切换人，原因「推荐礼包设定切回「由礼包后台发送」」<br>• 礼包后台两项恢复可编辑，并恢复发送<br>• 开关清空关联推播 |
| 再次切换 | 与第一次相同 | 可选原来那条（已暂停）或另一条符合条件的推播 |
| 改选推播 | 开关为「由推送统一后台发送」，且关联推播已结束 | • 在本页直接选另一条符合条件的推播（草稿或已暂停，触发行为为「限时加码礼包快到期」）<br>• 同一事务里该推播变为运行中（草稿生成版本 1；已暂停的恢复），`migratedFrom` 设为 GIFT_BACKEND，开关的关联推播改为它<br>• 礼包后台保持只读、不发送 |

**原设置与推播的对应**

| 礼包后台原设置 | 选定的推播（例 ID 31） |
|---|---|
| 未购买推播时间：还剩 2 小时 | 触发行为「限时加码礼包快到期」；触发条件：礼包剩余 2 小时时发送；只发给尚未购买该礼包的玩家 |
| 标题：最後提醒⚠️幸運加碼禮包 | 标题：最後提醒⚠️幸運加碼禮包 |
| 排除名单：黑名单、VIP 名单 | 排除群组：VIP 名单；另有固定排除黑名单、机器人与测试账号（4.1.1）。礼包后台的排除名单只管礼包资格，推播的排除在推播页设 |
| 推播内文（礼包后台无此项） | 内文由运营在推播页填写 |

**异常与边界**

| 场景 | 处理 |
|---|---|
| 切换那一刻正在处理的礼包快到期 | 以快到期时刻（expireAt − N）判断：切换前到点的由礼包后台发，切换后到点的由选定推播发（切换前已出现、未到期的礼包在切换时补排任务，见第 9 章研发 20）；同一次礼包快到期只发 1 条 |
| 开关为「由推送统一后台发送」期间，关联推播在推播页被暂停 | 礼包后台不恢复发送；本页提示「推播 ID 31 已暂停，这条提醒当前不发送；可在推播页恢复，或切回「由礼包后台发送」」；同时列入总览待处理「迁移提醒当前不发送」（4.1.2，v0.9.30） |
| 开关为「由推送统一后台发送」期间，关联推播已结束 | 礼包后台不恢复发送；本页提示「关联推播已结束」，可直接改选另一条符合条件的推播（见上方「改选推播」），也可切回「由礼包后台发送」；同时列入总览待处理「迁移提醒当前不发送」（4.1.2，v0.9.30） |
| 切换开关的操作纪录（v0.9.30） | 每次切换只记入推送统一后台的操作纪录（4.1.11）；礼包后台左菜单现有的「操作纪录」不另记 |
| 开关为「由推送统一后台发送」时推播页另有同一触发行为的推播 | 只提示重复发送，不阻止（见 4.1.4）；切回「由礼包后台发送」时与关联推播一并暂停 |
| 开关为「由礼包后台发送」时在推播页启用或恢复触发行为为「限时加码礼包快到期」的推播 | 不能进入运行中：<br>• 确认按钮换成「保存，去切换」（存为草稿并打开本页），提示「这条提醒目前由礼包后台发送；在迁入管理页切换后，本推送才开始运行」<br>• 「恢复」不可点，到时自动恢复不执行<br>• 服务端 confirm、resume 接口同样拒绝 |
| 礼包后台事件投递失败 | 礼包后台重发事件，推送服务按事件唯一标识去重 |

**接口需求**

| 接口（建议） | 输入 | 输出 |
|---|---|---|
| 限时加码礼包出现事件（礼包后台 → 推送服务；推送服务据 expireAt 按各推送的 N 排提醒，见第 9 章研发 20） | `eventId, memberId, giftId, expireAt` | — |
| 礼包购买状态查询（推送服务 → 礼包后台；到点、顺延到点、再次提醒、手动重试前调用） | `memberId, giftId` | `purchased, expired` |
| `GET /api/migration/gift-push` | — | `effectiveSide, linkedPushId, switchedAt, candidates[{pushId, pushName, status}]`；礼包后台据此显示迁入状态、只读与提示（v0.9.50 改，原「显示开关」，开关移到迁入管理页） |
| `POST /api/migration/gift-push/switch` | `targetSide`（LEGACY／UNIFIED）、`pushId`（切到 UNIFIED 时必填） | 切换结果；推播不符合条件或校验未通过时返回原因，不切换 |
