#### 4.3.2 运算顺序

| 规则 | 内容 |
|---|---|
| 纳入 | （v0.9.44 改）纳入部分由 1–5 个条件组组成（上限暂定，暂定参数表）；每组 1 行以上，每行选标签或群组；组内只用一种连接（全「且」或全「或」），组与组之间只用一种连接（全「且」或全「或」），没有优先级要记。原为「首行与组合方式为『且』『或』的行为纳入条件；『且』优先于『或』」，因运营逐行照心里的意思写「A；或 B；且 C」会得到 A ∪ (B ∩ C)，与本意 (A ∪ B) ∩ C 相反，改 |
| 排除 | 组合方式为「排除」的行合成排除集，最后统一从纳入结果中扣除，与行的位置无关。（v0.9.44）排除行放在排除组（一个），组内任一满足即排除，规则不变 |
| 条件行取反（v0.9.45） | 每行可切「在／不在」，建议默认值「在」；「不在」为行级取反（不在该标签或群组内的人），组内照常且、或，组间、排除组规则不变。例：「（新增 且 未首储）或 回流」在只有「已首储」标签时写成组 1「新增 且 不在 已首储」、组 2「回流」，组间「或」。原只能用排除组取反，排除最后对整体扣，写成排除已首储会把已首储的回流玩家也扣掉，正确写法要先建辅助群组再引用、页面没写（资深同行评审乙 5），改；对标 Braze、CleverTap、数数 TE 条件行都能选「不满足」（4.3.9「条件行取反」）；成本：小改动（标签系统编辑区加开关，组装 SQL 加 NOT；字段 5.23 序号 36） |
| 全部玩家（v0.9.44） | 标签下拉固定有系统标签「全部玩家」（全部注册会员，不剔除任何账号），可放在条件组里，用于「全部玩家 排除 五类」这类群组（例：纳入组「全部玩家」，排除组「新增 或 回流 或 近 7 天发生过破产 或 潜在付费 或 潜在流失（两档）」）；成本：小改动<br>• （v0.9.45）定义写定：全部注册会员，不随活跃度变；本文与原型示例里的「全部玩家 74,480 人」是 8/1–9/16 登录过的玩家（示例口径，数字不改），不是按本定义取的数；要近期活跃的玩家用现有标签「近 90 天有登入」，数据看板「五类人群概况」的「不属于五类」即以它为分母（4.1.8）。原各处人数用近期登录玩家、定义却是全部注册会员，两种口径并存（资深同行评审乙 2），写定 |
| 显示 | 编辑区下方实时显示计算式，例：「（新增 且 已首储）或 回流，再排除 机器人与测试账号」；（v0.9.44）例：「（新增 或 回流）且（未首储），再排除 机器人与测试账号」；（v0.9.45）取反的行写「不在 已首储」，例「（新增 且 不在 已首储）或 回流，再排除 机器人与测试账号」；每个条件组旁显示自身人数（4.3.4「逐组人数」；v0.9.45 改为准确值，原为估算人数） |
| 示例 | （v0.9.44 改）(A ∪ B) ∩ C＝组 1「A 或 B」、组 2「C」，组间「且」；A ∪ (B ∩ C)＝组 1「A」、组 2「B 且 C」，组间「或」；(A ∪ C) − B＝组 1「A 或 C」，排除组「B」。原为「『A；排除 B；或 C』＝(A ∪ C) − B；『A；或 B；且 C』＝A ∪ (B ∩ C)，要 (A ∪ B) ∩ C 时先建群组『A 或 B』再引用」，先建中间群组的做法删去，因 A、B 本身是群组时，中间群组带群组条件，按只嵌套 1 层（4.3.1）不能再被引用，走不通，改为直接用两个条件组 |
| 对标（v0.9.44） | Braze 每个条件都属于一个条件组，组内、组间各用且或连接，排除组恒为「且非」最后扣；CleverTap 规则组、Firebase 条件组、PlayFab「组内且、组间或」、数数 TE 两层且或，都用组结构表达括号，没有一家靠隐含优先级。我们每层只一种连接，比 Braze 组内可混用更严，有意为之：一眼读懂、不用记优先级（4.3.9） |
| 现状核对 | 评审前运营（第 9 章运营 16）在现有标签群组设定实测「或」「排除」与混合顺序并截图；不支持或顺序不同时按本节改，改前列出现有混用群组并核对人数变化<br>• （v0.9.44）现有群组自动转换：上线时按现行实际算法（运营 16 实测结果）逐个转成条件组写法。现行为「且优先于或」的，每段连续「且」串成一组，组间「或」；全为「且」或全为「或」的转成一个组；排除行进排除组；现行为其他顺序（如从左到右）的按实测顺序逐个转写；转出超过 5 组的列入确认清单<br>• 转换后用同一批次重算：人数相同的记变更记录「系统转换，人数不变」；人数有差的列清单交维护人确认，确认前沿用旧算法名单；凡人数变化的，按变更通知（4.3.6）通知引用方负责人，看板按人群标「人群口径改动」竖线（4.3.7）<br>• 核对范围从「混用或、排除的群组」扩到「混用且、或、排除的全部群组」<br>• 原写「改前列出现有混用群组并核对人数变化」，未写转换后人数变了谁知道，因上线时人数悄悄变化、引用方不知情，改；成本：写定 |
| 成本（v0.9.44） | 条件组：小改动（标签系统前端与组装 SQL）；条件组上限、组装方式由标签系统确认（第 9 章） |
