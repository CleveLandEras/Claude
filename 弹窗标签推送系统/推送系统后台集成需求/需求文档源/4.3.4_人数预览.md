#### 4.3.4 人数预览

| 规则 | 内容 |
|---|---|
| 人数含义 | 标签、群组人数为原始符合人数，不剔除任何账号；固定排除在推送的「排除后」一层扣除（4.1.1「四」），弹窗预计人数不扣、弹出时才扣。（v0.9.44）这一层的名称为「群组人数」（4.1.1「人数名称」①） |
| 人数名称（v0.9.44） | 各处人数旁写名称与批次时间：群组页与各处群组下拉为「群组人数（批次 10/12 15:25）」；推送侧为「受众」（排除后）、「可触达」（按推送方式）、「预计发出」；弹窗侧为「弹窗预计人数（未扣固定排除，弹出时扣）」；快显为预计显示次数（4.1.1「人数名称」）。为什么：同名不同义，运营把弹窗预计人数与推送可触达当成同一层比较；成本：写定 |
| 预览 | （v0.9.45 改）改任一条件后自动计算，2 秒内出准确值；只有改标签 SQL 的试算要跑 BigQuery，显示「试算中」（4.3.6）。原为「2 秒内出估算、15 秒内出准确值」，因标签系统每批名单已物化，交、并、差一次算准，两段带来两套计算、处处「估算」字样，运营还要分辨哪个数可信（资深同行评审过 1），改；显示「符合条件 N 人（批次时间）」与「当前生效 N 人」，下方参考行「其中固定排除约 X 人」 |
| 逐组人数（v0.9.44 改；v0.9.45 改） | 每个条件组显示自身人数；交集组内各行另显示各自人数，例「回流 16,564 · 潜在付费 4,860 · 组内且 1,320」；下方依次显示纳入合计、排除扣除、最终人数；（v0.9.45 改）逐组、逐行与最终人数一律为准确值，原为「逐组只给估算值，准确值只算整个群组」，改。原为「逐段人数：纳入条件每段显示累计人数，排除集显示扣除人数」，因交集要同时看两个群组各自人数、原来要跨页记数，且「逐段累计」在混用且、或时含义与计算式相反，改。对标：Braze 每个条件组给估算人数，精确统计只对整个分群（4.3.9）；（v0.9.45）我们逐组也给准确值，因活跃玩家约 7.4 万、名单已物化；成本：小改动 |
| 待计算 | 未完成首次计算的标签与群组显示「待计算」，可保存；推送与弹窗下拉同样置灰。（v0.9.44）新群组首批算完前显示「待计算，预计 15:50 可选」（下一批完成时刻），推送与弹窗下拉置灰并显示同一句；群组里只要有一个标签从未算出，群组整体「待计算」；「待计算」「尚未算出」「0 人」三种说法统一为「待计算」，4.1.3.2「新群组 0 人不能发送」同此（4.3.1「标签计算状态」）；成本：写定 |
