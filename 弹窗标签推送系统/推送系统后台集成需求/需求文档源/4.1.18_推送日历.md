#### 4.1.18 推送日历（10/16 夜补充）

> 只读日历：按周、月看全部游戏外推送、弹窗规则生效期间与快显的排期，同一群组同一天排得过多时标出。
>
> 关键规则：只读，不在日历上新建或拖动改时间；数据取各列表现有字段，不另存；撞车只提示、不拦截。

原型页 #10b（新增）；验收用例 T247、T248；字段：[5.24](#s5-24)。成本：小改动。

**核心逻辑**

| 项 | 规则 |
|---|---|
| 入口 | 侧栏「模板」下方「推送日历」 |
| 视图 | 周（默认，本周一至周日）、月切换；可前后翻页、回到今天 |
| 列出什么 | • 立即、定时推送：发送时刻一格；已发送的按实际开始时间<br>• （10/16 夜补充）时间偏移（项目锚点）的按行为推送：按项目时间算出的触发时刻画成一格（例「中秋排名赛结束前 2 小时」10/20 21:59），随项目时间变更移动<br>• 重复的定时：每一次各一格，写「第 N 次 / 共 M 次」<br>• 按行为推送与快显：生效期间画成横条，未设结束的画到视图末尾并写「长期」<br>• 弹窗规则：设了生效期间的画成横条；未设生效期间的上架规则在顶部「长期上架 N 条」一行汇总，可展开<br>• 草稿不列；已停止、已结束的保留已发出的格并标状态；已暂停的灰显 |
| 每格写 | 推送方式色块、名称与 ID、时间、发送对象（群组名、「全部玩家」或「名单」）、负责人（4.1.19）；点进对应列表、编辑页或单条推送数据 |
| 筛选 | 推送方式（多选，默认全部）、人群（标签群组；选后只列发送对象或「只限群组」含该群组的，全部玩家一并列出）、负责人、创建人、营销档期 |
| 节假日与大活动 | 日期头分两行（10/16 夜补充：原只读营销档期）：<br>• 第一行：台湾法定节假日，与项目目录（4.1.20）中活动类项目（可用、已排期、草稿，按上架开始、结束画成条；草稿标「草稿」）；项目时间是唯一时间源，延期后日历跟着变<br>• 第二行：「营销档期」页签（4.1.17）里设了起止日期的营销档期（（v0.9.47）跨活动的营销主题），名称后标「营销档期」，与项目区分<br>节假日表为系统配置，每年初由运营导入，可增改 |
| 撞车提示 | 同一天发给同一群组的游戏外推送不少于 3 条（不论推送方式）时，该日标黄「回流 4 条」这类提示，悬停列出各条；按群组名比较，「全部玩家」与任一群组都算重叠；3 条可改（第 9 章运营 22）。（10/16 夜补充）计数口径：按排期计，含时间偏移（项目锚点）算出的触发格；已发出、已跳过（勿扰放弃、频率上限拦下）与未发出的都计入，看的是排得是否过密；已停止且未发出的不计；草稿不计 |
| 弹窗撞车（10/16 夜补充） | 同一天同一位置、对象含同一群组的生效弹窗规则不少于 2 条时，日期格另起一行「大厅 · 回流 生效规则 3 条」，悬停列规则与优先级，点开为该规则的重叠检查（5.12 序号 13）；快显按行为的只画横条，不计撞车 |
| 空档 | 某天没有任何游戏外推送的，日期格标灰「无游戏外推送」 |
| 权限 | 运营、客服、只读都可看 |

**异常与边界**

| 场景 | 处理 |
|---|---|
| 一天超过 6 格 | 显示前 5 格与「另有 N 条」，点开列全部 |
| 时区 | 一律台湾时间 |
| 数据时效 | 与列表同源，打开或翻页时读取，不缓存 |

**接口需求**

| 接口（建议） | 输入 | 输出 |
|---|---|---|
| `GET /api/calendar` | `from, to, channels, groupIds, ownerId, createdBy, campaignId` | `items[{type, refId, name, channel, start, end, occurrenceNo, audienceLabel, ownerName, status}]`、`holidays[{date, name}]`、`conflicts[{date, groupId, count, refIds}]` |
