#### 4.1.1 通用规则

> 各推送方式共用的术语、发送对象与可触达判断、预计人数算法、每一人次的发送结果判定与表单校验。
>
> 关键规则：立即、定时的发送对象在开始发送那一刻锁定（重复的定时每次各锁定一次）；按行为推送每次触发时判断；游戏外推送只有服务商受理的条数（含受理后退回）计入发送与每人每天上限。

原型页 全景、#3；验收用例 T08、T10、T16、T19、T37–T40、T59、T60、T84、T85、T93–T96、T338–T349、T359、T361（10/16 夜补充）；字段：[5.1](#s5-1)、[5.4](#s5-4) 序号 45–50、[5.18](#s5-18)、[5.19](#s5-19)。

**二、术语**（与原型术语表一致）

| 术语 | 定义 |
|---|---|
| 推送方式 | 六种：游戏外推送的推播、短信、Facebook、LINE；游戏内推送的弹窗、快显。表格与筛选里的「推送方式」都指这一层 |
| 推送 | 一条推送，即某种推送方式下的一项发送任务，有推送 ID；弹窗以规则为单位，有规则 ID |
| 发送方式 | 三种：立即、定时、按行为。与「推送方式」不同：推送方式指推播、短信、Facebook、LINE、弹窗、快显六种 |
| 游戏外推送、游戏内推送 | 两层的名称，各含上面的推送方式 |
| 发送失败 | 只指一次性推送的一种状态（定义见 4.1.3.1）；没有被服务商接下的条数一律叫「服务商未受理」 |
| 失败条数、部分失败 | 都指服务商未受理的条数，不是状态：「失败条数」＝服务商未受理条数（可重试＋当场拒绝）；「部分失败 N 条」是已完成推送的标注，状态仍为已完成；「重试失败部分」＝重发服务商未受理·可重试的部分 |
| 会员标签 | 在「会员标签设定」里按一项条件圈出的玩家，约 100 个，分十个大类；推送与弹窗不直接选标签，选由标签组合成的标签群组（原型页 #19） |
| 标签群组 | 在「会员标签设定」的「标签群组设定」页用几个会员标签按且、或、排除组合出的玩家群，如新增、回流、潜在付费、潜在流失；名单每 25 分钟刷新（原型页 #19） |
| 「名单」（发送对象） | 立即、定时推送的一种发送对象：运营粘贴或上传的会员编号，默认只用于本条推送，（v0.9.44）可另存为手动标签（规则见下方「三」）。带引号的「名单」专指这一项；发送时算出的人称「发送对象」，如「发送对象在开始发送那一刻锁定」；「群组名单」「导出名单」等处不带引号的名单指一组玩家的清单 |
| 排除群组 | 从发送对象中去掉的标签群组：固定排除黑名单、机器人与测试账号，不可删；VIP 名单默认排除，运营可删；其余由运营加（见下方「三」固定排除） |
| VIP 名单（10/16 夜补充） | 排除群组里的一个标签群组（例 108 人）：推送默认排除、运营可删，弹窗固定排除；不同于运营按当前卡别分的四层价值分层（低 V／中 V／高 V／至尊卡），四层是由卡别标签组成的标签群组，可作发送对象（见下方「固定排除」「VIP 名单与价值分层」） |
| 触发的玩家 | 按行为推送的发送对象，即发生所选行为的玩家；每次触发时判断该玩家是否在只限群组内、是否在排除群组内 |
| 受众 | 符合发送对象条件的玩家：立即、定时按开始发送那一刻锁定的发送对象去重后计（快显立即按确认发送时）；按行为按触发人次计。（v0.9.44）受众＝排除后：群组人数（选「名单」时为匹配人数，选全部玩家时为全部玩家人数）减排除群组与固定排除；被前序推送排除、已由合并组发送、重复的定时本期不发的人不算受众（下方「人数名称」②）。原未写是否已扣排除，受众异常示例取了可触达、单条推送数据取了原始人数，改 |
| 可触达 | 受众中本推送发得到的玩家，判断条件见下方「三」 |
| 服务商 | 接收发送请求的一方：推播为推送服务；短信为短信服务商；Facebook、LINE 为各自平台 |
| 发送 | 游戏外推送被服务商受理的条数（即「已受理」），含受理后退回的，不含服务商未受理与结果不明的；（v0.9.40）「已提交」另指提交给服务商的条数，含在途、未返回的，不等于发送 |

**八、发送任务的可靠性**（10/16 夜补充）（异常层走查；原型页 #1、#2、#3、#13；验收用例 T338–T349；字段：[5.1](#s5-1) 序号 28–30、[5.2](#s5-2) 序号 40–42、[5.15](#s5-15) 序号 31–32、[5.18](#s5-18) 序号 10、11、71–75）

- 适用：游戏外推送四种的一次性推送（立即、定时；重复的定时按次）与按行为推送；快显下发失败见 4.1.6「异常与边界」。

- 标「暂定」的阈值按此开发：业务阈值由运营确认（第 9 章运营 29、30），实现方式由研发确认（第 9 章研发 14、56–62）。
