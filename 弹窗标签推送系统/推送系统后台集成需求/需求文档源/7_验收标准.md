## 7 验收标准

<a id="s7-1"></a>
### 7.1 通用

| 项 | 标准 |
|---|---|
| 用例 | [验收用例.html](验收用例.html)（原在原型附录）785 条验收用例（T01–T785）全部通过；迁入管理按已知 6 项写，写死项清单定稿后增补；（10/16 夜补充）写死项清单定稿前，迁入部分（T120–T126、T279）不构成上线放行条件 |
| 功能逻辑 | 符合第 4 章；状态流转与各状态表一致，表外的流转不发生 |
| 默认值 | 上线时各字段默认值与第 5 章「建议默认值」一致 |
| 跨端 | 快显显示、弹窗截断与上报在 iOS、Android、Web、H5 表现一致；（10/16 夜补充）T27、T325、T353 在四端各执行一次 |
| 界面 | 无排版、文字错误；用词与原型术语表一致（不一致处以本文为准，见 [10.3](#s10-3)）；缺数格子只用 4.1.8「拿不到的数据怎么写」的写法：待回执、无回执、该渠道不回传、未接入、待汇总、统计中、低于统计门槛、未收到上报、不适用，以及到达率下的「分母只含可确认到达的发送，另列未接入、不回传 N 条」（v0.9.40，原「仅 Android」）、「未发送」「—」「整行写原因」，不写 0；总览另有「今日未发送」「尚未切换」「已切回营销侧」（4.1.2） |
| 边界 | 字数上限、0 人、3 分钟后与 30 天内、重复最长 90 天、测试账号 10 个、「名单」50,000 个、上限 1–99、勿扰跨午夜都按规则处理 |
| 异常 | 失败按 4.1.1 分类处理：<br>• 服务商临时错误，以及连接阶段超时、请求未送达服务商（确定未提交）的，记「服务商未受理 · 可重试」，首次未受理后 30 分钟内自动重试 3 次，之后 24 小时内可手动重试；重试沿用同一发送键，不重复发送<br>• 请求已发出后等待响应超时（已提交、无结果）：能按我方 ID 去重或查询的（LINE 用重试键，自首次提交起 24 小时内有效，已满 24 小时的不再重发，记「结果不明」；短信按签约服务商，本文已按能去重）照常按「可重试」重试；推播、Facebook 记「结果不明」，不自动重试，推播可在重试窗口内手动重试一次，Facebook 不重试<br>• 服务商当场拒绝不重试<br>• 限流、通道熔断、额度耗尽挂起的人次留在待提交，不消耗重试次数<br>• 切换与回退都在同一事务完成，同一条推送只在一处发（见 [4.1.1](#s4-1-1) 五、[八](#s4-1-1-8) 2、4） |
| 权限 | 只读角色看不到写操作；直接调用写接口被服务端拒绝 |
| 留痕 | 每个写操作在操作纪录有一条，编辑有改前改后 |
| 性能 | 达到 4.1.14 各项；验收口径与暂定阈值见 [7.3](#s7-3)（10/16 夜补充） |
| 稳定 | 日志无报错；客户端无新增崩溃 |
