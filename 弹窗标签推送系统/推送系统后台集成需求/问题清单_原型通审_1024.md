# 问题清单 · 需求评审版原型通审（2026-10-24）

## 结论

**可以拿去评审，但建议先改掉下面 3 个 P0**，否则评审时容易在「推播主结构以哪套为准」「示例数据是否可信」「单条规则数据页在说什么」上扯皮，开发也会跟错。

最严重的 3 个：
1. **推播信息架构双轨**：新页（日历 / 定时 / 条件触发）与旧页（今明两天列表）同包并存且未标废弃。
2. **同一天星期互相矛盾**（10/21：日历写周三，今明/短信写周二）。
3. **单条规则数据页（14）与当前设置矛盾**：设置写「弹出数量 1 · 仅破产礼包」，下方却按 8 条内容画图，改动日志还写「破产礼包第 3→第 2」。

其余以 P1 为主：上架空状态漏扫、操作纪录 ID/排序离谱、内容库嵌套两层表、定时列表「发送对象」列串了类型。未发现「场景」造词回归；玩家查询口语已收敛。

审阅范围：34 张 `需求评审版_图/*.jpg` 均过目；关键帧对照单页 HTML（未 dump 11MB 拼装版正文）。**本次只审不改。**

## P0 · 会误导评审 / 开发（必须先改）

### P0-1 推播主结构双轨，评审不知以哪套为准
- **页面**：02a / 02e / 02f vs 02c / 02d  
  文件：`02a_推播列表.jpg`、`02e_推播定时.jpg`、`02f_推播按行为.jpg` vs `02c_推播今明两天.jpg`、`02d_推播拦下原因.jpg`
- **现象**：新页签为「日历 | 定时 | 条件触发 | 操作纪录」；旧页仍为「推播 | 操作纪录」+ 今明两天时间轴/列表。
- **证据**：HTML `data-tabs`——02a=`*日历|定时|条件触发|操作纪录`，02c/02d=`*推播|操作纪录`；改动清单仍写「02c 今明两天时间轴结构未动」且未标废弃。
- **为何是问题**：运营任务「扫周排期 → 看上限/顺延 → 改停」依赖日历结构；同包两套主导航会让评审争论「列表还是日历才是方案」，开发也可能各实一半。
- **建议**：评审包只留一套为主（推荐日历三页签）；02c/02d 要么删出评审主线，要么明确标「已废弃示意 / 仅作名额说明参考」。

### P0-2 同一天「今天」的星期互相矛盾
- **页面**：02a、02c、16a  
  文件：`02a_推播列表.jpg`、`02c_推播今明两天.jpg`、`16a_短信列表.jpg`
- **现象**：同一样本日 10/21，有的标周三，有的标周二。
- **证据**：02a 文案「周三 / 10/21 / 今天」；02c「今天 10/21（二）」；16a「今天 10/21（二）」。
- **为何是问题**：跨页对排期时会怀疑整包示例是否可信；日历与短信名额条无法对齐理解。
- **建议**：统一一张「样本日历」（建议锁定 10/21=周三或二选一并全包替换），短信/推播/快显同一锚点日。

### P0-3 单条规则数据页：当前设置与图表、改动日志互斥
- **页面**：14  
  文件：`14_单条规则数据.jpg`（对照 `14_单条规则数据.html`）
- **现象**：顶栏「当前设置」写破产 · 优先级 1 · 对象 2,410 · **弹出数量 1 · 弹窗内容：破产礼包**；同页「按弹窗内容」却列出首储礼包 / 破产礼包 / 独享礼包 / 限时加码…共 8 项；改动日志写「弹窗排序：破产礼包 第 3 → 第 2」。
- **证据**：HTML 第 15 行当前设置 vs 第 149–161 行图表标签 vs 第 141 行改动日志。
- **为何是问题**：对照任务「建规则 → 命中一条 → 取用内容」时，数据页像在讲「本规则有 8 个内容」或「整位置汇总误贴到单规则」，开发会跟错指标口径。
- **建议**：单规则页图表只展示本规则当前内容（此处应只剩破产礼包）；历史多内容用时间筛选或单独「历史配置」说明；改动日志与当前弹出数量自洽。

### P0-4 操作纪录示例：规则 ID 与排序位数对不上现网规则
- **页面**：20 / 20b  
  文件：`20_操作纪录.jpg`、`20b_操作纪录展开.jpg`
- **现象**：纪录写「回流活动弹窗（**ID 13**）…回流任务 **第 7 → 第 1**」；规则列表回流为 **ID 83**，且该规则弹出数量仅 **4**。
- **证据**：`20_操作纪录.html` 一行 vs `10a_弹窗列表.html` ID 83、`10_规则编辑.html` 弹出数量 4。
- **为何是问题**：操作纪录是查责与回放入口；ID/排序离谱会让人以为规则编号体系或排序上限未定。
- **建议**：改成 ID 83（或统一的真实示例 ID）；排序改动落在 1–4 内（例如第 4 → 第 1）。

## P1 · 影响理解或体验，建议本轮改

### P1-1 「上架」空状态只改了大厅列表，同结构页仍空白
- **页面**：00、10b（对照已改的 10a）  
  文件：`00_后台首页.jpg`、`10b_弹窗模拟玩家.jpg` vs `10a_弹窗列表.jpg`
- **现象**：10a 上架行有浅灰「上架」；00、10b（实际为破产筛选）状态列对上架行为空单元格。
- **证据**：00/10b HTML `<td class="st"></td>`；10a 为 `<td class="st mute">上架</td>`。
- **为何是问题**：交付自查要求空状态不误导；空白像未完成，且与「本轮已补上架」结论不符。
- **建议**：凡弹窗规则表统一写浅灰「上架」，00/10b 与 10a 对齐。

### P1-2 10b 文件名与真实内容不符
- **页面**：10b  
  文件名：`10b_弹窗模拟玩家.jpg` / `.html`（title：`10b 筛到破产`）
- **现象**：图是「破产」位置下的规则列表，不是模拟玩家。
- **证据**：截图与 HTML title；评审包内无单独「模拟玩家」页。
- **为何是问题**：按文件名找能力会以为有模拟器；对照「命中预览」任务会找不到入口。
- **建议**：改名为「筛到破产」类；若需要模拟玩家，另做一帧或标明未做。

### P1-3 弹窗内容库展开仍是嵌套两层表
- **页面**：10c2 / 10c3  
  文件：`10c2_弹窗内容展开.jpg`、`10c3_从规则点热门资讯.jpg`
- **现象**：内容行下再嵌一张「弹窗位置 / 规则 / 规则内排序 / …」子表。
- **证据**：`10c2` 外层 `qtable` + 内层 `table.inner`；交付自查明确「没有嵌套两层表」。
- **为何是问题**：第一次分清「内容 vs 规则」的人，展开后又掉进第二套表头，理解成本高（规则页嵌套已被打回过）。
- **建议**：引用改为侧滑 / 独立「被引用规则」页 / 单行摘要跳转，避免表中表。

### P1-4 定时列表「发送对象」列混入推播类型
- **页面**：02e  
  文件：`02e_推播定时.jpg`
- **现象**：#53 维护预告在「发送对象」列写的是「服务通知」，同列其它行是人数（如 74,480）。
- **证据**：`02e_推播定时.html` 该行 `<td class="r">服务通知</td>`。
- **为何是问题**：扫「发给谁」时类型与人数混列，易当成对象=服务通知。
- **建议**：对象列留空/「全部」等；类型放到推播名旁标记或独立列（与「不计入」次要行配合）。

### P1-5 短信 / 快显列表结构仍停在「今明名额 + 分区列表」，与推播新 IA 不一致
- **页面**：16a、17a vs 02a/02e  
  文件：`16a_短信列表.jpg`、`17a_快显列表.jpg`
- **现象**：短信/快显顶栏仍是今明名额条 + 页内「定时 / 条件触发」分区；推播已升为日历三页签。
- **证据**：三页 `data-tabs` 与截图结构对比。
- **为何是问题**：运营跨渠道排期时要学两套扫读方式；评审会问「短信要不要也改日历」。
- **建议**：本轮至少在清单/口头对齐「推播先改、短信快显是否跟」；若跟，名额条与列表页签策略写清，避免默认同包即同方案。

### P1-6 跨渠道编号 #52 撞车（若编号被理解为全局唯一）
- **页面**：02f vs 17a  
  文件：`02f_推播按行为.jpg`、`17a_快显列表.jpg`
- **现象**：推播条件触发「周年庆 #52」；快显「中秋排名赛最后 1 小时 #52」。
- **证据**：两页 HTML 均出现 `#52`。
- **为何是问题**：操作纪录、玩家收到记录若只写 #52，会对不上渠道。
- **建议**：确认编号是否分渠道；若分渠道，列表与纪录加渠道前缀；若全局唯一，改掉一侧 ID。

## P2 · 小瑕疵 / 可选优化

### P2-1 位置数据改动日志略解释腔
- **页面**：13 · `13_游戏内数据.jpg`
- **现象**：日志「热门资讯：本规则内未暂停」。
- **建议**：改成可枚举操作结果（如「热门资讯 · 取消暂停」），去掉解释句。

### P2-2 日历色义未用满 CSS 里已有状态
- **页面**：02a · 对照 `_推送.css`
- **现象**：日历事件主要用普通 / `warn`；CSS 另有 `sent` / `now` / `defer` / `hit` 等。
- **建议**：可选——发送中/已发完/顺延用不同左边色，与底栏摘要一致；非必须。

### P2-3 内容编辑页「引用规则」频率与常见大厅配置差异大（可接受但宜标）
- **页面**：10e · `10e_弹窗内容编辑.jpg`
- **现象**：同一「首储礼包」在银卡为「每天首次登录 1 次」、在普卡为「每周 2 次」。
- **说明**：规则内次数本就可不同；若示例本意是两端都「每日首次」，建议改齐，减少评审追问。**可选。**

### P2-4 推播操作纪录在「全部页面」下混出弹窗行
- **页面**：20 · 筛选为「全部页面」
- **现象**：推播模块下的操作纪录出现「页面=弹窗」行。
- **说明**：筛选为全部时合理；若默认进页是「全部」，建议默认「当前模块」或注释默认范围，避免以为串模块。**可选。**

### P2-5 快显新建页脚「英文横幅待核对」偏提示句
- **页面**：17 · `17_快显.jpg`
- **现象**：底栏状态句提醒待核对。
- **建议**：与多语言 Tab 上的「待核对」徽章对齐即可，底栏可去掉重复提示。**可选。**
