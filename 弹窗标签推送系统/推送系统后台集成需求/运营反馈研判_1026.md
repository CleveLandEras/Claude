## 1. 总判

## 2. 推播逐条

### 2.1 「营销、服务通知、定时、条件触发这 4 个类型的分级关系是什么？」

| | |
|---|---|
| **运营在问什么** | 把四者当成同一套分类树，想知道谁管谁、谁平级。 |
| **方案实际是什么** | **两维交叉，不是四级。** ① 消息类别：营销 / 服务通知（新建第 1 段；顶栏「营销 2 条 · 服务通知不计入」）。② 发送时间：定时 / 条件触发（新建第 4 段；页签「日历｜定时｜条件触发」）。一条推播 = 选一个类别 × 选一种发送时间。营销受上限与勿扰；服务通知不受上限、不计条数。 |
| **判定** | **误解为主，表达不清加重。** |
| **依据** | `02_新建推播.html` 两段卡片；`02a/02e/02f` 顶栏；业务规则「内容」「发送时间」「上限与勿扰」。定时页筛选仍写「推播类型｜子类型」却无展开选项，像在暗示还有一套「类型树」。 |
| **回运营可说** | 「不是四级：营销/服务通知管算不算进每天 2 条；定时/条件触发管什么时候发。一条推播两个都要选。」 |

### 2.2 「怎么把所有类型推播放一起管？5 条（2 手动 + 3 自动）上限 2，如何设优先级只让希望的 2 条发出？」

拆成两个子问。

#### A. 放一起管理

| | |
|---|---|
| **运营在问什么** | 定时和条件触发（其口中的手动/自动）能否在同一视野里排期、抢名额。 |
| **方案实际是什么** | 上限池是**合的**：营销推播不论定时还是条件触发，都进「每人每天 2 条」。管理视图是**拆的**：日历只排定时；条件触发单独页签，日均不并进日历拦下估算（规则写明「条件触发的今日与日均……不计入 4,030」）。旧「今明两天」页（02c）曾把按行为和定时放一起，但仍与新 IA 双轨并存。 |
| **判定** | **表达不清 / 能力半截。** 合池有；「一张表管全部」没有。 |
| **依据** | 业务规则「同一天按发送时间先后占用名额」；`02a` 日历无条件触发条；`02f` 独立页。 |
| **回运营可说** | 「名额是共用的；日历目前只看定时，条件触发在隔壁页签，要用发送时刻去和定时抢那 2 条。」 |

#### B. 5 条里指定希望收到的 2 条

| | |
|---|---|
| **运营在问什么** | 跨定时/条件触发的**显式优先级**，点名保留哪几条。 |
| **方案实际是什么** | 只有「**按实际发送先后**占名额，到 2 条当天不再发」。没有跨条排序、没有「必达清单」。早期稿有「重要程度·普通/重要 + 预留名额」，**本版新建页与业务规则均已无「重要程度/预留」**（组装稿 0 命中）。条件触发与定时的竞态取决于触发时刻，运营无法在后台点名「这两条优先」。 |
| **判定** | **真缺口**（相对运营举例的能力）；若产品刻意只做先后占用，则是**未写清「做不到点名保留」**。 |
| **依据** | 业务规则「今天起 7 天」「上限与勿扰」；`02_新建推播.html` 无重要程度；改版记录曾有重要程度（约 10-20），与现稿不一致。 |
| **「手动/自动」对应** | 方案用语是**定时 / 条件触发**，全文无「手动推播」「自动推播」。运营口头映射大致成立：手动≈定时，自动≈条件触发。 |
| **回运营可说** | 「现在不能给 5 条排优先级点名留 2 条，只能靠谁先发占满 2 条；要点名保留得另做（例如恢复重要预留，或跨类型优先级）。」 |

## 3. 弹窗逐条

### 3.1 「【充值】【活动】没看到；感觉没按之前优化做」

| | |
|---|---|
| **运营在问什么** | 以前规则层的「活动类 / 储值（充值）类」还在不在；整体是否落实过往沟通。 |
| **方案实际是什么** | 规则写明：原「活动类」「储值类」**改为弹窗内容上的标记「储值」「活动」**。出现位置：内容编辑（`10e` 第 2 段）、规则内排序行徽章（`10`）、内容库「标记」列（`10c`）。规则列表（`10a`）按人群规则名排，**不再以活动/储值分规则类型**。用词是「储值」不是「充值」。此前对齐的**六种弹出时机**（活动开启、首次/非首次/第 N 次登录、进入/返回大厅）在现稿编辑页与业务规则中**整段消失**，次数侧只剩「每日 / 每周 / 每 3 天 / 每天首次登录…」等。 |
| **判定** | **充值/活动：误解 + 表达不清**（做了但改名挪层，列表看不见）。**「没按优化」：部分真缺口**——至少「第 N 次登录等弹出时机」相对已对齐沟通是回退；不是运营纯没看懂。 |
| **依据** | 业务规则「研发要做的改动」「规则内容」；`10e`/`10`/`10a`；改版记录 10-20 对六种时机与运营 273 条的对齐。 |
| **回运营可说** | 「以前的活动类/储值类改成每个弹窗内容上的『储值/活动』标记了，在内容编辑和规则排序里，不在规则列表顶上。若你说的充值=储值，就是这个。第 N 次登录那种弹出时机这版拿掉了，和之前聊的不一致，要不要加回请拍板。」 |

### 3.2 「频率应统一成一种；每周×次和每天×次同时存在时，每周何时触发？」

| | |
|---|---|
| **运营在问什么** | 是否一套统一频率；同一对象上「每周」和「每天」如何叠加。 |
| **方案实际是什么** | **每个弹窗内容在每条规则里只设一个「弹窗次数」**（互斥选项，不是两个开关同时开）。同一规则里不同内容可以一个「每日 1 次」、一个「每周 2 次」（如回流规则）。同一内容在不同规则里也可以不同（首储：银卡「每天首次登录 1 次」、普卡「每周 2 次」）。玩家只命中**一条**规则，故同一人同一内容不会同时吃两套周期。每周 2 次 = 在该规则命中且未暂停时，按自然周计数，满 2 次本周不再弹该内容；与同规则里其他内容的每日次数无关。界面**没有**写清「每项只选一种周期、跨规则不叠加」。 |
| **判定** | **误解为主**（把同规则多内容、或同内容跨规则，看成「一条上又开每周又开每天」）；**表达不清**加重；若运营坚持「全站只允许一种频率语法（如仅每天次数 + 第 x 次登录）」，则与现「多周期枚举」是**产品分歧**，需拍板而非改文案能了。 |
| **依据** | `10` 排序四行不同次数；`10e` 引用表三行不同次数；业务规则「弹出次数、冷却按规则内每个弹窗设」。 |
| **回运营可说** | 「不是同一条内容同时开每周又开每天：每一项在规则里只选一种。你看到的每天和每周是不同内容，或同一内容在不同人群规则里各设一次；一个人只走命中的那条规则。」 |

## 4. 建议 dk 怎么回 / 要不要改原型

**回运营（建议口径）**  
先澄清推播两维与弹窗「储值/活动」在哪；坦白「5 选 2」和「弹出时机」现状与预期不符，问要不要做，不辩解。

**改原型？选项（可多选）**

| 选项 | 改什么 | 推荐 |
|---|---|---|
| A. 只回写说明，暂不改稿 | 用上面四句口径对齐认知 | 若本周只求对齐语言 |
| B. 推播补「维度说明」+ 日历/规则写清「先后占用、不能点名」 | 新建旁或规则首条；定时筛选「类型」与营销/服务通知对齐 | **建议做**（成本低，消误解） |
| C. 补「点名保留」能力 | 恢复重要预留，或跨定时+条件触发优先级 | **有产品取舍**；运营第 2 问核心，建议 dk 定做不做 |
| D. 条件触发进日历或合池预估 | 日历标条件触发占用/风险 | 中成本；与 C 可分开 |
| E. 弹窗：列表或规则顶露出储值/活动；文案「储值」是否改「充值」 | 降「没看到」 | **建议做**（小） |
| F. 弹窗：加回弹出时机（至少第 N 次登录），并写清次数与时机关系 | 回应「没按优化」 | **建议 dk 拍板**——与现「只靠次数」模型冲突，回加即改规则 |
| G. 频率：规则旁一句「每项只选一种周期」；或收成运营要的单一语法 | 消每周/每天疑惑 | 一句说明 **建议做**；收语法看 F |

**推荐组合：** 先 B + E + 频率一句说明；C 与 F 请 dk 二选或都做/都不做——这两项决定运营是否还会觉得「没按需求」。旧页 02c/02d 双轨问题仍在，回运营前最好标废弃或删掉，以免拿旧「今明」理解新口径。

## 5. 事实 / 推断分界

**已核实：** 两维字段与顶栏文案；合池+发送先后；无重要程度；日历不含条件触发；储值/活动在内容层；无弹出时机字段；次数按内容×规则。

**推断：** 运营「手动/自动」= 定时/条件触发；「充值」= 现稿「储值」；重要程度与弹出时机是本轮 IA 重做时拿掉，改版记录未写清决策句（记录止于约 10-21，之后日历/弹窗大改未入同一文件）。
