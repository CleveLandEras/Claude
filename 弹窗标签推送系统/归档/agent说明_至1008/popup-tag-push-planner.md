## 三、下一步队列
5–8 项，按执行顺序排列。格式：
`- [ ] Q编号｜需设计 或 直接做｜环节（如「弹窗·诊断」）＋推进的是哪条完成标准｜要做什么（具体到分析什么、改哪份文件的哪里）｜为什么（补的是哪个缺口）｜完成标准（可核对，含「决策汇报第 X 节同步更新」）`
要求：
- 只排当前环节的工作，以及回头修正前面环节的工作（见第 2.5 步）。
- **三句检查（工作原则第三节）**：每一项在「为什么」里写明推进哪一份近交付、属于中目标哪一项、对业绩的影响。前两句写不出的不排。数据考证（账号性质、字段含义、口径细节）只在会改变交付内容时才排，做到够用为止。上一版队列里不满足这一条的，撤下。
- **排序先近后远**：推进近交付的项排在前面；只服务远目标的分析排在后面，且不得挤占近交付。
- **类型必须标**，写在 Q 编号后的第一个字段：
  - 「需设计」：数据分析、问题诊断、根因判断、方案设计与比较、预期影响估算。这类项由设计者先写设计卡，执行者再照卡执行。所以「要做什么」写清要回答的问题就够了，方法交给设计者。
  - 「直接做」：同步修改、处理明确的修正、整合、登记。
- 设计卡里有「⚠ 设计意见，待规划者确认」的，先处理：修改或撤下该队列项，或者在队列项里写明「设计意见已知悉，按卡执行」。
- 在当前环节里，优先补最弱的缺口，优先做能用数据回答的分析（分析结果写进 `分析/`，写明方法、口径、分母、局限）。
- 每项都要是执行者一轮能完整做完的工作单元（单轮最长 50 分钟），太大的拆开；但不要为了切小而把一个完整的分析拆碎。
- 依赖外部答复的不放进来，只在决策汇报里写明缺口。
- 凡是改动了支撑文件的队列项，完成标准都要包括同步更新决策汇报的对应部分。
- Q 编号接着已有的最大编号往下编。上一版中未完成且仍然合理的项保留原编号。
