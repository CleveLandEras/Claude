# P-06R2｜P-06 调用路径边界表述修正

设计者：2026-09-29  
关联审查：I-017 Reviewer，问题 D-I017-003  
适用范围：仅目标目录内的补充说明与验收；不访问、写入或执行来源目录。

## 要回答的问题

怎样在目标目录补充一段可复核的说明，处理 P-06 原验收记录中「实际命令均以目标目录为工作目录」这一宽泛自述与事故自报之间的冲突，同时不改写原验收记录、不把目标侧证据外推成来源目录安全结论，也不解除 I-014、I-017。

## 为什么重要

原句覆盖了 P-06 的全部命令和整个历史执行过程，但现有事故自报已经使这个覆盖范围不能直接成立。若保留原句，读者可能把它理解为来源目录从未被访问、写入或执行；若直接把原句改成相反结论，又是在没有完整历史证据的情况下补写事故经过。

本卡只建立一个可审查的目标侧边界：当前补充做了什么、看到了什么、没有能力证明什么。它不为原记录背书，也不替事故自报定性；I-014 和 I-017 继续保持原状态，必须由各自的后续审查或处置流程决定。

## 假设与其他可能的解释

- **主假设：表述范围过宽。** 原验收记录可能只想描述某一批目标侧操作，却写成了覆盖 P-06 全部命令的绝对句；事故自报至少说明该绝对范围目前不能作为已证事实。
- **其他解释 1：历史命令确有跨目录调用。** 目标目录现有文件不足以还原命令、工作目录、调用链和影响范围，不能排除。
- **其他解释 2：命令在目标目录启动，但通过脚本、软链接、参数或工具间接触及来源目录。** 「工作目录」本身不能证明访问边界，不能用它替代路径级证据。
- **其他解释 3：事故自报与原验收记录覆盖的是不同时间段或不同命令集。** 需有逐命令清单和时间范围才能区分；本卡不自行选择其中一种解释。
- **其他解释 4：目标侧文件是事后产物。** 文件存在、时间戳或当前 diff 只能证明目标侧状态，不能证明历史命令没有在来源目录发生。

## 方法

### 1. 目标侧范围

执行者只读本目标目录内已存在的 P-06 原验收记录、事故自报、相关审查材料及本卡指定的目标侧补充文件；新建文件也只能写入本目标目录。不得通过绝对路径、软链接、脚本参数、搜索路径或任何其他方式访问、写入或执行来源目录；不得为了取证而重放历史命令。

### 2. 证据登记

在目标侧补充说明中建立证据表，至少列出：

| 证据类别 | 可以记录的内容 | 不能推出的内容 |
|---|---|---|
| 目标目录文件 | 文件路径、读取时点、内容中明确写出的范围 | 历史命令实际在哪个目录启动 |
| 原验收记录 | 原句原样摘录及其声称的覆盖范围 | 原句为真，或来源目录从未被碰过 |
| 事故自报 | 自报的事件、时间范围和已知影响（按原文） | 自报之外的完整命令链、全部影响范围 |
| 目标侧本轮操作 | 本卡创建、目标侧只读核对及产出路径 | P-06 历史操作均采用同一路径 |
| 目标侧差异/哈希（如有） | 当前目标文件状态可复核 | 来源目录安全、无泄漏或无遗留影响 |

证据表不能把「未在目标侧看到」写成「来源目录不存在」。信息缺失时使用「无法由目标侧材料判断」，不使用「没有发生」。

### 3. 目标侧补充说明（拟写入内容）

补充说明应单独成段并标注「P-06R2 目标侧补充」，建议使用下列口径：

> P-06 原验收记录中的「实际命令均以目标目录为工作目录」是未经逐命令证据限定的宽泛表述；该表述与事故自报存在范围冲突，本补充不将其视为已证事实。当前仅能确认本次 P-06R2 的核对和产出限定在目标目录内；目标侧材料不足以证明 P-06 历史命令均未访问、写入或执行来源目录，也不足以确认事故自报之外的完整影响范围。原验收记录不修改，来源目录安全性不作声称，I-014 与 I-017 维持原状态，待各自流程继续审查。

如实际证据只能覆盖更窄范围，应把「本次 P-06R2 的核对和产出」进一步替换成可逐项核对的文件清单；不得恢复「实际命令均……」或同义的全量承诺。

### 4. Executor / Reviewer 分离

- **Executor（执行者）**：只读目标目录，整理证据表并写入目标侧补充说明；不得改原 P-06 验收记录、事故自报或队列状态日志台账；不得访问、写入、执行来源目录；不得把历史事实缺口用推测补齐。
- **Reviewer（审查者）**：在不依赖执行者口头说明的前提下，独立读取目标侧原件、补充说明和差异，核对每一条结论是否超出证据范围；不得要求执行者为来源目录安全作证明，也不得以本轮目标侧核对替代 I-014/I-017 审查。
- **角色边界**：执行者可以提出「待证据」或「BLOCKED」；审查者决定 PASS、RETURN 或 BLOCKED。执行者不得自行把审查未完成写成 PASS，审查者不得把缺失证据改判为事实成立。

## 判读规则

1. 原验收记录的宽泛句与事故自报存在覆盖范围冲突时，判为**表述边界需修正**；不判定哪一份历史叙述最终为真。
2. 目标侧文件只能证明目标侧文件及本轮目标侧操作；「目标侧未发现」一律不得改写为「来源目录安全」或「历史命令均在目标目录」。
3. 只有逐命令、逐时段且路径证据完整覆盖的目标侧材料，才可以描述相应的有限子集；即使如此，也不得外推到未覆盖的 P-06 命令。
4. 原验收记录必须保持原样；若补充说明需要引用，使用原文摘录加边界说明，不做原地替换。
5. I-014、I-017 只要没有各自流程明确的关闭证据，就保持未解除；本卡的 PASS 不等于事故关闭或安全确认。

## 结论边界

本卡能确认：目标目录新增了一个对 D-I017-003 的边界修正方案；方案要求原记录不变、目标侧证据不越界、角色分离，并给出可复核的 PASS/RETURN/BLOCKED 判定。

本卡不能确认：P-06 历史命令的真实工作目录、来源目录是否被访问或写入、事故影响的完整范围、来源目录的安全性、I-014/I-017 是否已关闭，也不能替代来源目录取证或事故响应流程。

## 已知陷阱

1. 把「工作目录」当成「访问边界」；脚本、软链接、参数和外部工具可能突破该假设。
2. 用当前文件时间、git diff、哈希或目标侧搜索反推历史命令路径。
3. 为了修正文案而改写原验收记录，导致审计对象变化、原始证据丢失。
4. 把事故自报的单个已知影响当成完整影响清单，或把未知写成零影响。
5. Executor 与 Reviewer 共用同一份未留痕的判断，形成自审；或由 Executor 直接标记 PASS。
6. 把本卡 PASS 误读成「来源安全」「事故已关闭」或「I-014/I-017 已解除」。
7. 把队列状态、推进计划或台账的未更新误读为本卡未完成；本任务明确不更新队列状态日志台账，状态只在本卡和审查结果中体现。

## 状态判定

| 状态 | 必须满足的条件 | 处理 |
|---|---|---|
| **PASS** | 补充说明明确指出原句过宽且与事故自报存在冲突；仅声称目标侧可证内容；明确不改原记录、不声称来源安全、不解除 I-014/I-017；证据表、Executor/Reviewer 分工和审查依据完整；未访问、写入或执行来源目录；未改队列状态日志台账 | 允许把本卡标为已审查通过；只表示「边界表述已修正」，不关闭事故或安全事项 |
| **RETURN** | 仍保留「实际命令均……」等全量自述；把目标侧检查外推为来源安全；改写原记录；缺少证据范围或角色分离；Executor 自报 PASS；或出现队列台账等越界修改 | 退回补充说明，指出超界句和缺失证据；保持 I-014/I-017 原状态 |
| **BLOCKED** | 目标侧原件或事故自报不可读；无法确认补充说明对应的目标文件；需要来源目录才能判断历史事实；Reviewer 无法独立复核；或出现疑似来源目录访问/执行痕迹但目标侧无法收敛范围 | 保持未定，不补写历史结论；将缺口交给具备相应权限的事故/审查流程；不得以 BLOCKED 推断安全或事故关闭 |
