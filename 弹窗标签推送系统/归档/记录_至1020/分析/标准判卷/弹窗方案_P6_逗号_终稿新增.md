# 弹窗方案 · 逗号检查（终稿新增句）

**总判定：通过。** 8 句、12 个逗号，都可用，没有不可用或判不了的。

判法：逗号两边是因果、条件、承接、补充、对比、同一件事的展开 → 可用；两边是互不相关的两件事 → 不可用。
范围：只判中文逗号「，」；顿号「、」和箭头「→」不在范围内。

| 页码 | 句子 | 每个逗号两边各是什么 | 判定 |
|---|---|---|---|
| p6 | （iOS 推播没有到达，LINE 到达只有按日总数） | 左：iOS 推播缺到达数据<br>右：LINE 到达只有按日总数 | 可用。两边是同一件事的展开：两个渠道的到达数据各缺在哪里，都属于「到达数据不全」 |
| p11 | 配置分散，不能统一按人群发 → 先按标签发短信，再建推送统一后台 | 逗号①　左：配置分散；右：不能统一按人群发<br>逗号②　左：先按标签发短信；右：再建推送统一后台 | 可用。①是因果：配置分散导致不能统一按人群发。②是承接：「先……再……」的先后步骤 |
| p11 | 数据分散，且部分查不到 → 推送统一后台查发送、到达、点击 | 左：数据分散<br>右：且部分查不到 | 可用。补充：「且」接上数据的第二个问题，两边都在讲数据现状 |
| p11 | （建成后 iOS 推播仍没有到达，LINE 到达只有按日总数） | 左：建成后 iOS 推播仍缺到达数据<br>右：LINE 到达只有按日总数 | 可用。同一件事的展开：后台建成后仍存在的两处到达缺口，与 p6 同构 |
| p13 | 推送统一后台建成后，Android 补上到达；iOS 仍没有到达，只有发送、点击 | 逗号①　左：推送统一后台建成后（时间、条件）；右：Android 补上到达<br>逗号②　左：iOS 仍没有到达；右：只有发送、点击 | 可用。①是条件：建成后才补上。②是对比和补充：iOS 没有什么、有什么。分号已把 Android 和 iOS 两件事隔开，用法正确 |
| p14 | 游戏外推送：运营自设文案、跳转，可定时或按行为发 | 左：运营能自设的内容（文案、跳转）<br>右：发送方式（定时或按行为） | 可用。同一件事的展开：两边都在讲冒号前「游戏外推送」能怎么配，主语承前省略 |
| p14 | 快显：运营自设文案、跳转，可按行为发，不能定时 | 逗号①　左：运营能自设的内容（文案、跳转）；右：可按行为发<br>逗号②　左：可按行为发；右：不能定时 | 可用。①是同一件事的展开：都在讲「快显」能怎么配。②是对比：能按行为发，但不能定时 |
| p11 | 快显固定在客户端，不能按人群显示 → 改由推送统一后台配置，按人群显示 | 逗号①　左：快显固定在客户端；右：不能按人群显示<br>逗号②　左：改由推送统一后台配置；右：按人群显示 | 可用。①是因果：写死在客户端，所以不能按人群显示。②是承接：先改成后台配置，再实现按人群显示 |

**附：相对最接近边界的一句**
p6 和 p11 括号句的两边主语不同（iOS 推播、LINE），但两边讲的是同一指标「到达」在两个渠道的缺口，不是互不相关的两件事，所以判可用，不必改成分号。
