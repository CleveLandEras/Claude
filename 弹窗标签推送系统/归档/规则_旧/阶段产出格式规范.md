# 阶段产出格式规范（过审条件）

> 10/14 起已由 `标准体系.md` 取代，仅作背景：八阶段、定时角色、check_format.py 均已停用；写法以写作标准为准。

Dk 10/8：「这个文档可读性有点差」「观感不好」「太平铺了，看得很费劲，没有结构性」「规范阶段性的输出格式，观感结构什么的必须要好才能通过」。
**本规范由主对话制定，条文待 Dk 认可**；Dk 定的只有「格式不好不能过审」。本规范适用于根目录全部 `阶段N_名称.html`。**第五节的机器检查和人工检查满足，才能过审；其中 A 第 9、10、12、13 项是主对话定的参考值（出处见各项），`check_format.py` 报 ✘ 时只作提醒，由人工检查按读者是否看得费劲来判。** 组件用法参考 `阶段1_需求分析.html`（Dk 尚未认可为范例）。

## 一、页面骨架（顺序固定）
1. `p.meta`：阶段 · 名称 · 对象 · 日期 · 状态，一行。
2. `h1`：整份的中心结论，一句话，可直接转述。
3. 首屏核心区：用 `div.core`（核心表）、`div.tree`（层级总览）或 `div.summary`（2–4 组 `dt`/`dd`）给出本阶段的核心内容；可加 `div.kpis` 关键数字。明细放进各节，可用 `details.more` 折叠。
4. 各节 `section.sec`：`div.sec-h` = `span.sec-no`（一、二、三…）+ `h2`。h2 写成「节名：本节结论」，节名与 `弹窗标签推送方案/阶段产出/阶段产出规划.html` 该阶段「结构」一列一致、顺序一致。需要时一行 `p.sec-sub` 交代口径。
5. 末节「关键假设」（第 7、8 阶段除外）。
6. `p.links`：依据与素材链接。

## 二、组件（样式全文取自 `规则与交接/阶段产出模板.css`，放进 `<style>`）
| 用途 | 组件 |
|---|---|
| 关键数字 | `div.kpis > div.kpi` |
| 层级总览 | `div.tree`：`p.goal`（根）+ `ul > li`（子项，可带锚点链接） |
| 首屏摘要 | `div.summary > dl > dt + dd` |
| 分组块（主体的层级单元） | `div.cap`：`div.cap-h`（名称、一句定义、来源 chips）→ 块内子项表 → `div.cap-v`（结论或作用） |
| 表格 | `div.tw > table`；分组行 `tr.grp`；编号列 `td.no`；出处写在单元格内 `span.src`，不单独占列 |
| 标签 | `span.tag`：`t-goal` 目标/记载/主管明确、`t-con` 约束、`t-sug` 建议、`t-inf` 推断、`t-add` 本文补充（不逐条贴分类标签，见写作标准「要删掉的内容」） |
| 短引用 | `span.chip`：场景编号、对应需求等 |
| 并列项 | `div.cards > div.card` |
| 清单分栏 | `div.cols > div.box`（`h4` + `ul`） |
| 表下说明 | `p.note` |
分组块、层级总览的样式未在模板 css 里的，从组件用法参考 `阶段1_需求分析.html`（Dk 尚未认可为范例） 的 `<style>` 复制。

## 三、写法
- **按层级组织**：先总后分，子项挂在所属父项下；不用几张平铺清单靠编号互相引用。
- **单元格写短**：表格单元格一般一句话（Dk 10/8「这个文档可读性有点差」；当时单元格塞满出处和限定语，是主对话的判断）；长说明放 `p.note`，或移到「关键假设」。
- **不写方法过程**：节开头不交代怎么做的；方法、推算、选取依据放 `分析/`，正文链接。
- **推断写明依据和边界**：在句中写明是推断及其依据，不逐条贴分类标签；暂时无法确认的、「理由弱、缺什么」集中写在「关键假设」。
- **措辞**：专业、简洁、直接；标题、定义、结论可直接转述（Dk 10/8「我都没法转述给别人到底能力目标是什么」）：短名称说不清时写成主语、动作、对象齐全的句子，不用名词罗列代替；通用名称（如「现状盘点」）照用；正文不出现内部编号（Q、R、K、A 编号）。
- **不设字数上限**；标准是结构清楚、扫读能抓到结论。

## 四、自查流程（已停用）
- 执行者每改一次阶段产出，运行 `python3 …/_scripts/check_format.py`，把 ✘ 项改完再标完成。
- 规划者排「整合」项时，完成标准写「check_format 全部通过，并满足本规范第五节人工检查」。
- 审查者做过审审核时，**先运行 check_format.py**；有 ✘ 判「过审审核：不通过」（第 9、10、12、13 项除外，这四项按人工检查判断），再做人工检查。

## 五、过审标准（全部满足才通过）（已停用）

**A. 机器检查（`check_format.py`，全部 ✔）**
1. 使用模板样式
2. 有 meta 行、唯一的 h1，h1 无占位
3. 首屏有核心内容区（核心表、层级总览或摘要）
4. 至少 3 节；每节有节编号和 h2；h2 为「节名：结论」
5. 各节名与规划表该阶段「结构」一一对应
6. 有「关键假设」节（第 7、8 阶段除外）
7. 无「待写」等占位
8. 正文无内部编号
9. 表格单元格（不含出处小字）不超过 140 字（主对话定的参考值，无 Dk 出处；✘ 只作提醒）
10. 无文字墙：正文段落不超过 200 字（主对话定的参考值，无 Dk 出处；✘ 只作提醒）
11. 本地链接都能打开
12. 首屏核心加全部节标题约 3 分钟读完（3 分钟出自写作标准；1000 个汉字是换算的参考值，✘ 只作提醒；写作标准「有效信息不删，优先于篇幅与时长限制」）
13. 全文较长时，各节明细用 `details.more` 折叠（「展开：……」）（写作标准「附录默认收起」；3000 字触发线是参考值，✘ 只作提醒）

**B. 人工检查（审查者逐条判，写进过审审核）**
1. 首屏读得出结论：只看 h1、关键数字、总览或摘要，能复述本阶段结论。
2. 只看节标题读得出论证，节标题可直接转述。
3. 层级清楚：先总后分，子项挂在父项下，没有靠编号互相引用的平铺清单。
4. 观感：使用格式规范的组件，留白、分组、标签一致；没有拥挤的表格和大段文字。
5. 信息完整：精简没有丢掉理由、出处、口径。
6. 措辞专业简洁，无口语化解释，无内部编号。
