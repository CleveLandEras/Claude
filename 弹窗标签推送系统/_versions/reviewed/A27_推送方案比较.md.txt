# A27 推送定向：现有通路、专人名单，还是等 07 统一后台

> **按原则 v3 的说明（2026-09-30 Q146）**：本文「07『为了钱』的理由不成立」「07 只剩两个理由」「首期建议缩成群组定向推播 + 数据」（清点第 3 项）是旧原则下拿业绩尺子衡量能力得出的，按 v3 作废，不作推荐；07 的优先级按能力线逻辑链重排（待做）。四格人数、覆盖上界、S / R、前提成本等数字与事实仍可引用。

## 结论（一句话，条件式）

**钱的一侧（高卡流失风险层 927 人）在四种外部答复下的首选都是专人名单式联系**：按月均储值排，占八成的只有 168 人（待再来 131、已离开 37），是名单量级。高卡已有专人，就把名单和排序交给他们；没有专人，是否设人属主管决定。**所以 07 统一推送后台「为了钱」的理由不成立（推断）。** 07 只剩两个理由：一是沉默老账号独有部分（26,844 人，人数侧），在现有通路不能按名单发时只能靠它；二是发送、到达、点击数据可查。07 现版本只含手机推播和游戏内推送条，推送条对不来的人碰不到，所以 07 对这两块人只有推播一条，上界约为各格的 68–79%。**任何一条路能召回多少人，本地都没有数据。**

证据强度：各格人数、S / R、App 类占比、07 的范围 → 已证实（本快照与需求原文）；覆盖上界、条件式推荐、07 为了钱的理由不成立 → 推断（条件式）；召回率、各通路定向能力 → 待确认。

## 方法

- **四格**（照卡）：D1 待再来 755、D1 离开 172、D8 独有待再来 14,828、D8 独有离开 12,016。人群定义复用 A16、A20，人数与 A14、A23 一致。
- **五条路**：P0 维持现状（对照）；P1 现有通路手工定向（运营按名单或人群用推播、短信、LINE、Facebook 发；前提是这些通路能按名单发，9-2 未知）；P2 专人名单式联系（只对 D1）；P3 07 现版本（手机推播 + 游戏内推送条）；P3′ 07 扩到短信、LINE（只登记为 P1 不可行时的开发方向，不估成本）。
- **覆盖**：游戏内推送条与快显只对在线的人，四格一律「不能」（机制：Dk 答复问题 9、盘点第五节）。推播填该格 App 类（android、ios、apk）人数，作**上界**：App 类指最后一次登录的平台，装了 App 不等于开了推播权限，离开者可能已卸载，推播也不发给 VIP。短信、LINE、Facebook 一律「未知（9-2）」，不用任何代理估算。
- **D1 名单量级**：引用 A25 表 4（R 口径）。927 人合起来 K80 = 168，待再来 131，离开 37。
- **判读规则 1–6**（照卡原文）：
  1. 钱侧（D1）：K80（R，755 与 172 合并）≤ 300 →「名单量级」，D1 首选 P2。A = 有专人 →「交给现有专人，名单与排序由我们给」；A = 无 →「是否设专人属主管决定」，同时写 P1 / P3 推播作无专人时的备选。K80 > 300 → 不判首选。
  2. 人数侧（D8 独有）：不适用 P2。B = 能按名单发 → 首选 P1；B = 不能 → 只能 P3 / P3′，写「需开发，推后」。两种情况都写「召回率未知，量级只能写暴露上界」。
  3. 07 的角色：若判定表四格里 07 在 D1 都不是首选 →「07 为了钱的理由不成立（推断）」，07 只保留「D8 独有（B = 不能时）」与「数据可查」两个理由。
  4. 名单量级门槛沿用 Q86 规则 4（300 / 1,000）。
  5. 覆盖只写上界或未知，不写「能召回 / 能触达 x 人」。
  6. 离开格 App 类占比 < 50% 时注明「过半数推播碰不到」。

## 07 的角色（判读规则 3）

- 四格里 D1 的首选都是 P2（名单量级，规则 1）→ **「07 为了钱的理由不成立（推断）」。**
- 07 保留两个理由：① D8 独有，在 B = 不能时只能靠 07，这是人数侧（26,844 人，占合并储值 S 1.69% / R 4.83%）；② 发送、到达、点击数据可查，这是 P1、P2 都没有的。
- **边界（如实写）**：在「A = 无专人、B = 不能」且主管决定不设专人时，07 的推播是 D1 唯一不靠人的触达，上界 687 人。这时 07 会重新带上一部分「为了钱」的理由。它不改变规则 3 的判定（D1 的首选仍是 P2，只是由主管决定），但要让主管知道：不设专人，D1 就要等 07。
- **首期范围的重写建议（写在这里，不改 07 原文）**：以「按标签群组定向的手机推播 + 发送、到达、点击数据」为首期核心。游戏内推送条对不来的人为 0，它的价值在在场的人（如新手通行证提示），可以放第二期。首期上线的前提是 D8 独有所需的标签群组已建好（Q89），否则等于只能对全部玩家发。

## 证据强度

- 已证实（本快照与原文）：四格人数、S / R、App 类占比；07 现版本范围（「适用范围：手机推播与游戏内推送条两种形态」）；推送条与快显只对在线的人（机制）。
- 推断（条件式）：覆盖上界；判定表；07 为了钱的理由不成立。
- 待确认：各通路能否按名单发（9-2）、发送与到达数据（9-3）、高卡有无专人（运营第 3 句）、自查 ⑥、召回率。

## 局限

1. **召回率本地为 0 数据**：表 1 只是「能不能碰到」的上界，不是「能找回多少」。
2. **App 类 ≠ 开了推播**：上界可能明显高于实际可达。
3. **待再来不等于流失**：8–14 天那一档里有每周或隔周来一次的正常玩家（A20 其他解释 3），推送对他们是「多来」，不是「找回」。
4. **D8 独有不是「只能靠推送」**（提醒 40）：自查 ⑥ 未答。
5. **D1 与 D8 独有的当量不能相加**成「推送总价值」（提醒 23）。
6. 名单量级只用 R 口径判（照卡）；S 口径 K80 为 275（A25），同样 ≤ 300，判读不变。

## 这会成为哪个决策点

- **主管层级：高卡设不设专人**（A = 无时）。这决定 D1 走 P2 还是退到推播。
- **主管层级：07 首期范围**。是按原需求（全部推送统一 + 推送条），还是按本文件建议（群组定向推播 + 数据），以及排期先后（B = 能时可后做）。
- **运营**：9-2（现有通路能否按名单发）与第 3 句（高卡有没有专人），两句答完判定表就只剩一格。
