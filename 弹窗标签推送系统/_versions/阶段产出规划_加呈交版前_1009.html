阶段产出对象结构完成标准状态
1需求分析
阶段1_需求分析.html		弹窗、标签、推送三项能力的需求（主管、制作人、运营）
  1. 需求来源：主管弹窗、标签、推送三组目标，以及范围约束、同事建议，附原文与出处
  2. 能力拆解：需求归为几项能力；每项能力下列出运营要完成的场景（按理想状态写全，标主管明确或本文补充），以及该能力让运营能做到什么
  3. 验收标准与需求边界：能力建成的判定标准；哪些不属于能力需求；成本取舍不在本阶段做
  4. 相关方：各方在决策、使用、开发、数据支持中的职责
  5. 关键假设：本阶段的推断及依据
场景均可溯源至需求原文；能力项互斥且覆盖全部场景进行中
2
与 3 并行		人群分析
阶段2_人群分析.html		五类目标人群，以及五类之外的人群
  1. 人群口径：五类人群的圈选条件
  2. 人群画像：每类人群的规模、储值贡献、行为特征和需求
  3. 人群重叠：同时属于多类的用户规模与分布
  4. 未覆盖人群：五类以外的用户（如持续活跃用户、高卡用户）及处理建议
  5. 推送受众：离线用户规模及各通路可触达范围
  6. 关键假设：本阶段的推断及依据
各类人群口径与数据完整；覆盖全量活跃用户未开始
3
与 2 并行		现状盘点
阶段3_现状盘点.html		现有弹窗、标签、推送、数据和运营流程
  1. 弹窗：现有规则配置与内容池（活动、礼包）
  2. 标签：现有标签体系与组合逻辑
  3. 推送：各通路的覆盖、定向能力与数据回收
  4. 数据：已有数据、可取数据与缺失数据
  5. 运营流程：弹窗配置、标签创建、推送下发的现行流程与痛点
  6. 人群触达现状：各类人群在进入大厅、破产时点的实际弹窗曝光
  7. 场景可行性：需求分析中各场景：可实现、不可实现或推断可实现
  8. 关键假设：本阶段的推断及依据
每项均有出处或推断依据未开始
4问题诊断
阶段4_问题诊断.html		需求与现状之间的缺口
  1. 缺口：不可实现的场景，及影响的用户规模
  2. 根因：缺口归因、依据及已排除的替代解释
  3. 优先级：根因处理顺序及依据
  4. 关键假设：本阶段的推断及依据
缺口均有归因；优先级有依据；不涉及解决方案未开始
5方案选型
阶段5_方案选型.html		能力建设的备选方案
  1. 候选方案：2–3 个备选方案（如按人群分层配置、按内容配置加排除去重、待总控功能上线后实施）
  2. 方案对比：根因覆盖、现有后台可行性、改动成本、风险；成本作为对比项，不据此预先排除理想方案
  3. 行业参照：同类产品的通行做法
  4. 推荐方案：推荐及依据
  5. 关键假设：本阶段的推断及依据
各根因在每个方案下均有对比结论；推荐有依据未开始
6方案设计
阶段6_方案设计.html		选定方案：标签、弹窗、推送、数据的整体设计和人群策略
  1. 总体架构：标签、弹窗、推送、数据四个模块如何衔接
  2. 标签体系：人群分层、口径管理、交集需求
  3. 弹窗体系：位置分层、互斥规则、总量控制
  4. 人群策略：各类人群的内容策略及依据
  5. 推送体系：统一入口、通路选择、定向、频控
  6. 指标体系：能力是否建成、是否在用的衡量指标，以及效果查看须提供的数据项
  7. 实施分层：短期（现有后台配置）、中期（小改动开发）、长期（较大开发），每项标成本与依赖，供与上级讨论取舍
  8. 短期快速提升：现有后台即可做、低成本、路径短的操作：做什么、对谁、做完后运营能做到什么、怎么确认做到
  9. 约束与风险：现有功能限制、资源、合规、变更风险
  10. 关键假设：本阶段的推断及依据
各模块均有设计依据，并标注现有后台可行性未开始
7方案验证
阶段7_方案验证.html		方案设计：用需求场景和目标人群逐一检验
  1. 场景验证：需求分析中各场景在方案下的实现路径
  2. 人群验证：各类人群的触达结果与弹窗数量
  3. 根因验证：问题诊断中各根因的解决情况
  4. 边界：方案未覆盖的情形
  5. 假设汇总：各阶段关键假设的依据、影响范围与验证方式
场景与根因均有验证结论；不可实现项明确列出未开始
8结论汇总
阶段8_结论汇总.html		各阶段结论和待决事项
  1. 结论：各阶段核心结论
  2. 完整方案与成本分层：全部需求及短期、中期、长期分层
  3. 短期快速提升：可立即执行的低成本操作清单
  4. 待决事项：取舍建议，每项的背景、选项、建议
首屏呈现结论与待决事项；确认后启动落地规划未开始

过审硬条件：符合《阶段产出格式规范》（机器检查全部通过，且人工检查首屏、标题、层级、观感、信息完整、措辞）。需求按理想状态写全，成本取舍留给与上级讨论；短期快速提升的低成本操作单列。写法：按「结构」分节，每节对应一个问题，节标题即结论；内容按层级组织（先总后分，子项挂在所属父项下），不用几张平铺清单靠编号互相引用；以结构清晰为第一标准，不设篇幅上限；表述简洁但信息完整，标题和定义可直接转述。推进：需求分析通过后，人群分析与现状盘点并行；两者都通过后进入问题诊断，之后逐阶段推进。每阶段审查通过即进入下一阶段，不停下等确认，同时提醒 Dk（需求分析、方案选型两处重点提醒）；Dk 主动确认或反馈，反馈优先处理。信息缺失时基于合理假设推进，影响结论的列出备选方案；待核实问题单列，不阻塞推进。本表变更需经 Dk 确认。
