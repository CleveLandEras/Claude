## 需求背景

推送由各功能各自实现，配置分散在各功能后台，没有统一入口。已知两种形态：手机推播（限时加码礼包未购买提醒，配置在推荐礼包管理后台）与游戏内推送条（新手通行证升级提示）。各推送的发送量、到达率均无记录。

## 需求目标

- 全部推送在统一后台新建、查看与启停
- 推送可按标签群组定向
- 每条推送的发送量、到达率、点击率可查

**适用范围**：手机推播与游戏内推送条两种形态，含现有各功能推送。

**排除项**：侧边栏常驻入口、红点、大厅活动中心二级入口。

## 功能说明

### 全新需求：推送后台

**推送列表**：列出全部推送，每行显示推送名称、形态、对象、发送方式、状态、发送量、到达率、点击率，可按形态、状态筛选。

**新建推送**：填写形态、对象、发送方式与内容后保存。定时推送在设定时间发送，立即推送在确认后发送。

**现有功能推送纳入**：限时加码礼包未购买提醒、新手通行证升级提示等现有推送在列表中显示，发送方式为「事件触发」。触发逻辑仍由原功能决定，统一后台提供查看数据与启停。

**每人每日推送上限**：全局设置。玩家当日已收到的推送数达到上限后，后续推送不再发送给该玩家，次日 0 点（Asia/Taipei）重置。事件触发类推送同样计入。

### 数据口径

| 指标 | 定义 |
|---|---|
| 发送量 | 推送系统成功发出的条数 |
| 到达量 | 手机推播：推送服务回执为已送达的条数；游戏内推送条：客户端完成展示的条数 |
| 到达率 | 到达量 ÷ 发送量 |
| 点击量 | 玩家点击推送的条数 |
| 点击率 | 点击量 ÷ 到达量 |

## 后台需求

### 推送

| 序号 | 字段名称 | 程序命名建议 | 数据类型 | 必填 | 规则说明 | 备注 |
|---|---|---|---|---|---|---|
| 1 | 推送名称 | name | string | 是 | 后台内部识别用，不对玩家显示 | |
| 2 | 形态 | channel | enum | 是 | 手机推播、游戏内推送条 | |
| 3 | 对象 | target_type | enum | 是 | 全部玩家、群组 | |
| 4 | 群组 ID | group_id | string | 对象为群组时必填 | 引用标签群组 | |
| 5 | 发送方式 | send_type | enum | 是 | 立即、定时、事件触发 | 事件触发仅用于现有功能推送，不可新建 |
| 6 | 发送时间 | send_at | datetime | 定时时必填 | Asia/Taipei | |
| 7 | 标题 | title | string | 手机推播时必填 | | |
| 8 | 内容 | body | string | 是 | | |
| 9 | 点击跳转 | link_target | string | 否 | 游戏内页面标识；为空时点击仅打开游戏 | |
| 10 | 状态 | status | enum | 是 | 草稿、待发送、已发送、启用、停用 | 启用、停用用于事件触发类 |

### 全局设置

| 序号 | 字段名称 | 程序命名建议 | 数据类型 | 必填 | 规则说明 | 备注 |
|---|---|---|---|---|---|---|
| 1 | 每人每日推送上限 | daily_push_cap | int | 是 | ≥ 0；0 表示不限制 | 默认 0 |

### 数据（只读，按推送展示）

| 序号 | 字段名称 | 程序命名建议 | 数据类型 | 规则说明 |
|---|---|---|---|---|
| 1 | 发送量 | sent_count | int | 见数据口径 |
| 2 | 到达量 | delivered_count | int | 见数据口径 |
| 3 | 到达率 | delivery_rate | decimal | 保留两位小数的百分比 |
| 4 | 点击量 | click_count | int | 见数据口径 |
| 5 | 点击率 | click_rate | decimal | 保留两位小数的百分比 |

## 资源需求

无。

## 验收标准

| 序号 | 功能 | 验收标准 |
|---|---|---|
| 1 | 新建推送 | 以群组为对象的定时手机推播，在设定时间仅发送给群组内玩家；游戏内推送条按内容与跳转正确展示 |
| 2 | 现有推送纳入 | 限时加码礼包未购买提醒在列表中可见；停用后不再发送，启用后恢复 |
| 3 | 每人每日上限 | 设为 2 时，测试账号当日第 3 条推送不发送；次日 0 点后恢复 |
| 4 | 数据 | 列表中每条推送的发送量、到达量、点击量与测试发送记录一致，比率按口径计算 |
